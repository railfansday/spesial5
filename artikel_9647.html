Why your WordPress sitemap shows raw XML in Chrome 158 (and why it's fine)

Tanggal: 2026-11-27

TL;DR: Chrome 158 removed XSLT on 17 November 2026. Sitemaps that used an XSL stylesheet now show a warning above raw XML. Search engines never used that stylesheet, so your SEO is fine. Check the Sitemaps report in Search Console, and if you want the table back, fix it in your own browser.

If you opened your WordPress sitemap in Chrome recently, you probably saw a wall of tags where a tidy table used to be. Nothing is broken. Here is what happened and what to do about it.

Chrome 158 reached the stable channel on 17 November 2026 and stopped running XSLT, as planned on Chrome's deprecation page. XSLT is the language that turned sitemap XML into a readable HTML table. Sites on the origin trial and companies using the enterprise policy keep it until Chrome 176, in August 2027. Everyone else has lost it.

A sitemap that links to an XSL stylesheet now opens with this line at the top:

This document cannot be formatted as intended. It uses XSLT, which the browser does not support. You might be able to install a browser extension that allows you to view it.

Below it, Chrome shows the XML as a plain tree. Every , and is still there. Only the layout is gone.

Google, Bing and other crawlers fetch the XML and read the entries. They never ran your XSL file. The stylesheet was only there for humans who opened the sitemap in a browser.

The plugin teams say the same thing. Yoast support wrote that "Search engines never used the styled view" in this WordPress.org thread. Rank Math support told users the warning does not change how search engines crawl the sitemap (thread).

Don't trust any browser view for this. Ask Google.

"Success" means Google loaded and processed the file with no errors, according to the Sitemaps report help. If you see "Success", the raw XML in Chrome is a display change and nothing more. If you see "Couldn't fetch" or "Has errors", that is a real problem, but Chrome 158 did not cause it.

If you are not sure which file is yours, my guide on how to view a WordPress sitemap covers where each plugin publishes it and how to read a sitemap index.

WordPress core. The stylesheets were removed in trunk with the commit "Sitemaps: Remove XSL stylesheets", which closes ticket #65593. The change is expected in WordPress 7.2, which Search Engine Journal reports is scheduled for 8 December 2026. After that, Chrome should show its plain XML tree with no warning. The same commit deprecates the wp_sitemaps_stylesheet_* filters, so don't build anything new on them.

Yoast SEO. Version 28.9 no longer applies XSLT, as Yoast support confirmed in the thread linked above.

Rank Math. No announcement yet. Support says updates on the Chrome display will appear in the Rank Math changelog, and that you can leave your sitemap settings as they are.

SEOPress. The plugin author says you don't need to do anything, and that they will adjust the browser display if needed (thread).

The raw XML only bothers people. So fix it for people, not for crawlers.

In your own browser. The "install a browser extension" link in Chrome's warning opens a Chrome Web Store search. The official result is XSLT Polyfill. It runs the stylesheet again on XML pages, so your old table comes back. I wrote up what the XSLT Polyfill extension can and can't do. Another option is XMLNest. Disclosure: I build XMLNest. It shows a sitemap as a table you can filter and sort. With either extension, only your browser changes. Your visitors still see raw XML.

Without installing anything. Paste the sitemap into a reader such as this Sitemap Checker (also mine). It lists the URLs and flags problems like bad addresses or invalid dates.

Your sitemap did not break. Chrome stopped drawing a table that only humans ever looked at. Check that Search Console says "Success", keep your SEO plugin up to date, and use an extension or a reader tool when you want to browse the file yourself.
