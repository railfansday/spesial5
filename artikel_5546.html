The next chapter for Red Hat: AI agents rewrite the cloud-native playbook

Tanggal: 2026-11-11

Red Hat LLC has spent years making Kubernetes manageable for enterprises that would rather run applications than tend clusters. As AI agents move into production, the company is extending that experience to a new generation of workloads. AI agents don’t just consume infrastructure. They execute commands, call external tools, access enterprise systems and take actions that can affect the business. The next phase of AI agent infrastructure requires enforceable security boundaries alongside efficient resource management.

Red Hat arrives at KubeCon + CloudNativeCon North America in Salt Lake City this week with a growing portfolio of technologies addressing those requirements. OpenShift provides the Kubernetes foundation; its work with Nvidia Corp. on OpenShell addresses agent execution and security; and the llm-d project has reached version 1.0 with capabilities for serving the context-heavy workloads agents create. Together, these developments position Red Hat to help enterprises manage agentic AI through open, Kubernetes-based infrastructure.

Unlike conventional applications, autonomous agents can generate commands, invoke tools and delegate work across multiple systems. That flexibility creates opportunities for automation while increasing the importance of consistent access controls and oversight.

This feature is part of SiliconANGLE Media’s exploration of how cloud-native infrastructure is evolving to support enterprise AI, with Red Hat and the broader Kubernetes ecosystem addressing the security, operational efficiency and scalability requirements of autonomous agents. The rapid adoption of OpenClaw has brought renewed attention to agent security. An agent that can read files, run shell commands and make network calls needs clearly defined permissions and isolation to operate safely within enterprise environments.

Red Hat’s response centers on its collaboration with Nvidia around OpenShell, a runtime that places agents inside isolated execution environments and applies policy to their access. Nvidia developed OpenShell; Red Hat is working with Nvidia and the wider community to integrate the technology into Red Hat AI and its open hybrid cloud platform. Red Hat’s announcement describes the work as part of a broader effort to bring security-focused agentic AI capabilities to enterprise infrastructure.

OpenShell uses sandboxing, process-aware policy and controls over network access and credentials. Red Hat has also described how OpenShell can work with OpenShift’s sandboxed containers, adding application-level restrictions inside a virtual-machine boundary. These complementary layers govern agent behavior and isolate the environments in which agents operate, as Red Hat explains in its technical overview of layered sandboxing.

The distinction matters because sandboxing does not make an agent trustworthy. It limits the damage an agent can cause when its instructions, generated code or external inputs lead it somewhere they should not.

In a recent interview with theCUBE, Pete Cheslock, principal AI community architect at Red Hat, described how OpenShell builds on Kubernetes infrastructure: “The agent sandbox is one of them, so that you can deploy these agents in a secure way using Kubernetes native APIs.” His comments get to the central issue: enterprises cannot delegate authority to agents without defining and enforcing its limits.

Red Hat Chief Technology Officer Chris Wright also emphasized the importance of agent isolation in a May interview with theCUBE. Agents that can take real actions in a business need sandboxing and least-privilege protections, he explained.

“You’ve got to give it the right sandboxing. You’ve got to put protections around the agent, give it least privileges so it doesn’t think about read versus read-write — very big difference,” Wright said in SiliconANGLE’s coverage of Red Hat Summit.

Beyond sandboxing, enterprises must manage agent identities, data permissions, tool access and authorization. That distinction is reinforced by Paul Nashawaty, practice lead and principal analyst for application development, modernization and cloud native at theCUBE Research, whose September analysis of AI agent governance examines the difference between observing what agents do and proving what they were authorized to do. The research identifies runtime enforcement, delegated authority and verifiable audit evidence as requirements that become more important as autonomous systems move into production.

“This creates an opportunity for platforms that can unify application development, infrastructure orchestration, security and observability rather than adding another layer of disconnected tooling,” Nashawaty said.

Beyond security, agents create new requirements for inference infrastructure. An agent may call a model, retrieve information, invoke a tool and return to the model with additional context. Each interaction consumes compute, memory and network capacity, while the system must preserve enough context to continue efficiently.

Red Hat’s llm-d project addresses part of that problem. Founded by Red Hat, IBM Corp., Google Cloud, CoreWeave Inc. and Nvidia, and now governed by the Cloud Native Computing Foundation, llm-d uses Kubernetes-native components to distribute inference across accelerators and manage traffic between them.

The project reached version 1.0 on Oct. 20, adding session-aware routing, turn-priority scheduling, multi-tenant quality-of-service controls and high-availability operations. Those features aim to keep multi-turn requests close to cached context, prioritize latency-sensitive work and reduce disruption during maintenance. The Red Hat release announcement and Google Cloud’s technical overview describe the release.

The architecture provides operators with additional options for coordinating inference workloads and managing accelerator resources within Kubernetes.

Red Hat Senior Vice President and AI Chief Technology Officer Brian Stevens described one of llm-d’s central architectural decisions in SiliconANGLE’s report on Kubernetes inference: “We can independently scale the processing of the input from the production of the tokens.”

Other infrastructure providers are addressing complementary requirements. ScaleOps Labs Ltd. focuses on GPU utilization and resource optimization across Kubernetes workloads. Vultr Holdings LLC offers GPU infrastructure and Kubernetes-based model deployment, while Broadcom Inc. positions VMware Cloud Foundation as a private-cloud platform for Kubernetes and AI workloads. Together, these offerings reflect expanding enterprise choices for resource optimization, accelerator capacity and private-cloud operations.

The operational gap appears in theCUBE Research’s “Day 0 Build, Test Survey Research Report.” Based on a survey of 375 IT, development, operations and platform engineering professionals, the research found that cloud-native adoption is widespread but maturity remains uneven. Inconsistent automated testing, fragmented developer tools and gaps in rollback capabilities continue to complicate production deployment.

“Ninety-two percent of organizations are integrating AI into at least one stage of the software development lifecycle, while 79% expect full-scale AI agent adoption within the next three years,” Nashawaty said, adding that approximately 30% still face operational readiness challenges.

The broader industry is also moving toward production-scale infrastructure. The CNCF’s 2026 annual cloud-native survey found that 82% of container users run Kubernetes in production and that 66% of organizations hosting generative AI workloads use Kubernetes for some or all inference. Those figures reinforce Kubernetes’ expanding role as enterprises adopt AI workloads.

The open-source ecosystem is expanding alongside agentic AI adoption. On Nov. 5, Google announced the donation of Agent Substrate, gVisor and OpenRL to the CNCF following their acceptance into its Sandbox program in October. The projects address agent execution, isolation and reinforcement-learning workflows. Agent Substrate separates agent sessions and identities from active compute, allowing idle environments to pause and resume; gVisor provides an additional isolation boundary for untrusted code; and OpenRL supports reinforcement-learning post-training on Kubernetes. Google’s announcement describes the projects and their transition into CNCF governance.

These contributions complement broader efforts across the Kubernetes community. Red Hat is a co-founder of llm-d and is integrating Nvidia’s OpenShell into its enterprise AI platform, while Google is contributing technologies related to runtime and training requirements. The common emphasis on open infrastructure creates opportunities for interoperability as enterprise AI systems mature.

Broadcom added another development on Nov. 9, announcing that its VM API project had been accepted into the CNCF Sandbox. The project aims to let organizations manage virtual machines through Kubernetes application programming interfaces across different infrastructure providers. This extends the Kubernetes conversation to managing virtual machines alongside containerized workloads.

Project Lightwell adds another dimension to Red Hat’s enterprise strategy. Announced with IBM in May, the $5 billion initiative aims to use AI-assisted vulnerability identification and validated fixes to strengthen open-source software supply chains. The initiative extends security efforts to the software dependencies supporting production workloads.

Sam Weston, industry analyst for enterprise applications, development and modernization at theCUBE Research, points to the infrastructure mix enterprises already operate.

“With our data showing 61.8% of enterprises run hybrid deployments and an additional 10% operate across multi-cloud environments, Red Hat’s hybrid-first platform strategy aligns closely with where enterprise infrastructure lives today,” Weston said.

Red Hat’s established OpenShift footprint provides a foundation for connecting these developments. As enterprises deploy more autonomous workloads, the company is positioned to combine Kubernetes orchestration, agent isolation and distributed inference within its broader hybrid cloud strategy.

The opportunity extends beyond any individual project. OpenShift, llm-d and OpenShell illustrate how Red Hat is contributing to an open infrastructure model that accommodates both conventional applications and emerging AI agents.

For enterprises, the objective is to make AI workloads secure, efficient and manageable without losing control over how autonomous systems operate. Red Hat’s work across the Kubernetes ecosystem reflects how that foundation is taking shape.
