C’s designated initializers give us named arguments

In my previous post I talked about C++’s “relatively nerfed” form of designated initializers. This time I want to show you a neat thing you can do with C’s full-power designated initializers. I first saw this pattern in Ben Klemens’ book 21st Century C (2014), pages 226–228. (Godbolt.)

This idiom gives us named, defaultable arguments with natural function-call syntax. It relies on two features of C’s designated initializers that C++20 didn’t adopt:

They can appear in any order: (struct IdealVolumeArgs){ .atm=1, .moles=2 } means the same thing as (struct IdealVolumeArgs){ .moles=2, .atm=1 }.

The same designator can appear multiple times, and only the last one “sticks”: (struct IdealVolumeArgs){ .atm=1, .moles=2, .atm=3 } means the same thing as (struct IdealVolumeArgs){ .atm=3, .moles=2 }.

That second bullet means we’re relying on something that would be bad style if it weren’t intentional. Clang emits a -Winitializer-overrides diagnostic by default. GCC (more sensibly IMHO) emits -Woverride-init only with -Wextra.

Once a function uses this idiom, adding a new named parameter to the function definition is no longer an API break! For example, we might decide to let the caller provide their own value for the ideal gas constant R. We simply add a new field to the Args struct. All the old call-sites will still compile just fine, and have the same behavior. (It’s not an API break, but it is an ABI break: the callers needn’t be re-written, but they do need to be re-compiled against the new header.)
