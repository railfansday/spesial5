Website screenshots without cookie banners: a tested Playwright approach

Tanggal: 2026-11-27

Posted on Nov 27 • Originally published at siftwright.com

There are three common fixes floating around: hide the banner with CSS, click the "accept" button, or block the consent script. Each works on some sites and quietly fails on others. We wanted to know where, so on 27 November 2026 we ran them against real sites with Playwright and Chromium and looked at every screenshot. This post covers what broke, why, and the script that ended up handling every banner in our sample.

We picked 20 well-known sites across news and retail in the UK, Germany, France, Italy, Spain, the Netherlands and the US. From our IP, six of them (including Reddit, eBay UK, Forbes and Adidas) returned a bot block page instead of content, which is a separate problem that no banner trick will solve. Six more showed no consent banner from the US. That left eight sites with a banner to remove: The Guardian, Der Spiegel, Le Monde, IKEA UK, Stack Overflow, Corriere della Sera, Le Figaro and El País.

For each site we took a 1280x800 screenshot with no cleanup, then with each method, and checked the images by eye. We also recorded document.documentElement.scrollHeight, because a full-page screenshot is only as tall as the document says it is.

The most common advice is to inject a stylesheet that hides the containers of well-known CMPs:

This removed the banner on four of the eight sites: The Guardian, Der Spiegel, IKEA and Stack Overflow. It did nothing on Le Monde, Corriere della Sera or Le Figaro, which all run their own consent walls with their own class names. (El País served us a bot check on that run, so we could not judge it.)

It also has a second, less visible failure. On The Guardian and Der Spiegel the banner disappeared, but the page still could not scroll: kept overflow: hidden, and the full-page screenshot came out exactly 800 pixels tall. On Corriere, was locked in the same way. The first fix we tried made it worse. We added html, body { overflow: auto !important } to the stylesheet, which turned into its own scroll box, and Stack Overflow's full-page height dropped from 2,810 pixels to 800. On The Guardian our rule did not even win: Sourcepoint adds a sp-message-open class to , and its own !important lock is more specific than ours. What worked was to set overflow: visible as an inline !important style, which beats any stylesheet rule, and only on elements that were actually locked.

CSS hiding is cheap and does not change the site's state, but on its own it covered half of our sample.

Clicking the button is closer to what a person does, and it removes the scroll lock along with the banner because the site's own code runs. The difficulties are finding the button and choosing which one to press.

Finding it. Playwright's role locators (getByRole('button', { name })) search inside open shadow roots automatically, and page.frames() includes cross-origin iframes, so looping over frames finds buttons inside Sourcepoint's iframe without extra work. Matching on the button's accessible name is more robust than matching CMP-specific selectors, but you need the words in each language: "Accept all", "Alle akzeptieren", "Tout accepter", "Accetta e continua".

Run it with node capture.mjs https://www.ikea.com/gb/en/ ikea.png. You need npm install playwright and a browser (npx playwright install chromium).

The fixed 3-second wait after loading is deliberate. Consent scripts often appear a second or two after domcontentloaded, and a screenshot taken earlier will miss the banner, then the banner will appear in the next frame. A waitForSelector on a known CMP container is faster when you only capture a few sites you know.

All eight final full-page screenshots showed the page content with no consent UI. Full-page heights ranged from 2,810 pixels (Stack Overflow) to about 49,000 (Corriere).

That is what hideLargeOverlays() is for. It hides any position: fixed element that covers at least 30% of the viewport and actually contains something. It removed The Guardian's fundraiser and The Independent's popup, and left headers and Der Spiegel's slim subscription strip alone. The "contains something" check came from a real false positive. IKEA keeps 14 empty, closed modal wrappers fixed over the whole viewport, and the first version of the function dutifully "hid" all of them. They were invisible, so the screenshot did not change, but the log was noise and a less careful rule could hide something that matters.
