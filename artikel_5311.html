Ethereum (ETH) Gas Estimates Are Broken: Explaining the Fix and the Issue

Ethereum transactions can appear successful, but there might be a problem hiding behind the scenes.

A Geth developer has proposed a fix to the client's gas estimation, according to draft pull request #36084 on GitHub. The patch addresses an issue in the current estimator, which could result in incorrect gas limits due to failed internal calls (calls from one smart contract to another) being ignored.

Although the transaction could still be completed, there is no evidence that the action the user wanted has actually happened.

The issue lies in a mechanism where a smart contract calls another smart contract, catches an error, and then proceeds to a refund, records the failure, or skips an item entirely. Technically, the transaction was successful, but the outcome is different for the user.

This could potentially result in wallets suggesting a gas limit that is enough to finish the transaction, but not enough to complete the work inside it. The developer also noted that EIP-8037 could make this behavior more common, since gas returned from failed internal execution can help fund the fallback.

According to the pull request, the change includes a stricter definition of success for gas estimates. This version of Geth would improve the way it deals with internal failures, counting failed internal calls and contract creations instead of checking only whether the transaction completes.

Even if the transaction completes, the estimate would get rejected if it produces more internal failures than a reference execution with a higher gas limit.

Nonetheless, the developer stressed that an internal call that always fails should not push the estimate higher indefinitely. The reference execution enables the estimator to keep existing failures without allowing additional ones caused by insufficient gas. The proposal also introduces a separate Amsterdam reference, preventing unnecessary increases made purely to access the state gas reservoir.

The developer states that they've replayed 432 mainnet transactions with the new set of rules from the Amsterdam update and that the suggested change fixed 64 out of 67 cases.

The gas limit increased by 4%. 254 additional estimates were unaffected due to the lack of the problem, with 3 cases being undetected.

For regular investors, the proposed change should improve the reliability of wallet estimates and reduce transactions that complete without delivering the intended result, despite introducing higher gas limits in some cases. Luckily, there is no proven link between higher gas limits and higher fees.
