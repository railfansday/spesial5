The Frankenstein Table

Tanggal: 2026-11-06

It was naivety, but when I first came across Flexbox, and then CSS Grid, I had this feeling all those positioning properties (align-self, justify-content…) would be available to use on block and inline elements; things like tables, lists, fixed elements, everything. The workings might be different under the hood, depending on the reference boxes, but the syntax and expected outcomes would be same: push to one edge, keep at the center, spread around evenly, etc.

Although that didn’t happen, what if I made something of that sort?

For example, I could take out the soul of an HTML table and stitch it back together with CSS Grid. In other words, it reads like a table, but acts like a grid, allowing me to use grid properties. Believe it or not, some form of this was used in the past to make tables responsive.

Before I kill off a table in this article though: there are a lot of advantages to straight-up tables. They provide a clean semantic layout that browsers perfectly understand and translate for assistive technology when needed. There’s even a element.

On the CSS side of things, there are indeed circumstances where CSS Grid is necessary for its intrinsic responsiveness, source order independence, and positioning. That’s why it’s an indispensable tool for layouts. Use that and let HTML tables to do the work of actually displaying tabular data!

But it’s understandable why it looks more than a little gross and against the grain of what we should be able to. We’re encouraged to maintain a separation of concerns between content and presentation and this does exactly that without affecting the tables semantics, such as its role. But maybe it should? The pseudo-semantic angle is what really sold me here. I run an informational niche site that’s full of reference tables (status codes, payment schedules), and scanning raw markup with / pairs is so much easier to read than a pile of nested divs. That said, Mike Mai’s point about VoiceOver gives me pause — I’ll probably keep this trick for decorative layouts and leave the actual data tables semantically intact.

This is a fun experiment, and I especially liked the distinction you drew between a real table and a pseudo-semantic one. Once display: grid is applied, the browser no longer treats the th and td relationship the way it does in a normal table, so the visual connection stays for sighted readers while the structural meaning is lost. That trade-off is what makes Mike Mai’s point land for me: it is convenient for the author, but assistive technology does not get the same benefit. I would keep this pattern for a purely presentational card only where the same information is also available in a straightforward, accessible form, rather than using it for actual data.
