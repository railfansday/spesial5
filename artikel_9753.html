InfoQ Homepage News Cloudflare Introduces Private Origins for Application Services

Nov 15, 2026 2 min read

Cloudflare recently made Application Services for Private Origins generally available, allowing public traffic to reach applications hosted on private networks without exposing their IP addresses or opening inbound firewall ports. Private-to-private connectivity is not yet supported.

Announced in closed beta in June, the service is now generally available with a simplified configuration: private IP addresses are automatically detected in proxied DNS records, and private routing can be configured through the DNS API. Enrique Somoza, product development manager at Cloudflare, writes:

We launched this capability (...) to address a problem we kept hearing from customers: Their internal APIs, AI agent backends, MCP servers, and operational tools weren’t built to face the Internet, but those services still need to accept requests from partners, customers, or agents over the Internet.

Existing Cloudflare connectivity can be used to apply WAF, bot management, rate limiting, caching, and Workers to private origins, just as with public-facing applications. The service also supports private TCP/UDP origins through Spectrum and private connectivity for Workers. Somoza adds:

Those requirements often left private applications without the same protections and controls they used for public applications, including WAF, bot management, rate limiting, caching, traffic acceleration, rewrites, and Workers.

Using Private Origins requires a Private Origins entitlement, Cloudflare One connectivity, and Unified Routing (not required when using Cloudflare Tunnel). Cloudflare WAN and Mesh connections also require return routes for Cloudflare's IPv4 (100.64.0.0/12) and IPv6 (2606:4700:cf1:5000::/64) source ranges, as well as a proxied DNS record pointing to the private IP with private network routing enabled. Existing WAF, caching, and bot management policies apply automatically. Simon Painter, cloud network consultant, notes:

No extra connector software. WAF, bot management, rate limiting, caching and Workers all sit in front of stuff that was never meant to be on the open internet. The interesting bit isn't the marketing wrapper — it's the DNS implication. For years the rule was: "if it answers a public DNS name, it's reachable from the public internet." That stops being true here.

Cloudflare is not the only cloud provider offering ways to connect public-facing services to private application backends. AWS, for example, offers CloudFront VPC Origins, while Microsoft provides similar capabilities through Azure Front Door Premium and Private Link. Giacomo Masseroni writes:

Finally. been punching holes in security groups just to let the edge in.

With general availability, Cloudflare has updated the Private Origins developer documentation. The announcement does not clarify whether the feature carries an additional charge or is included in existing Enterprise contracts.

Cloudflare plans to extend the service to support private-to-private traffic, allowing users, services, and AI agents on one private network to access applications on another. A closed beta is targeted for early 2027.
