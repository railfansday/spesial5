osFoundry का Agent team क्या करता है, और कब एक ही agent काफ़ी है?

Tanggal: 2026-11-06

मंगलवार सुबह के 7:40 बजे हैं और प्रिया के पास एक सवाल है जिसका जवाब उसकी डायरेक्टर को लंच तक चाहिए: क्या चार दिन का वर्क वीक सच में आउटपुट बनाए रखता है? वह इसे किसी chatbot में पेस्ट करके पूरे भरोसे से लिखा एक पैराग्राफ़ पा सकती है। लेकिन जो model आंकड़े ढूंढेगा, वही यह भी तय करेगा कि आंकड़े सही हैं या नहीं, और वह शायद ही कभी खुद से असहमत होता है। प्रिया चाहती है कि एक व्यक्ति trials ढूंढे, दूसरा आंकड़े निकाले, और कोई तीसरा हर उस चीज़ को वापस भेज दे जिसका कोई source न हो।

osFoundry एक desktop app है जिससे आप AI का काम अपनी ही मशीन पर चला सकते हैं, और इसमें agents को काम सौंपने के दो मिलते-जुलते तरीके हैं। Agent (sidebar में Single agent के नाम से दिखता है) एक नाम वाला agent है जिसका एक ही काम होता है: आप उसे instructions देते हैं, उसे AG-0001L जैसी अपनी ID मिलती है, और उसका हर run रिकॉर्ड होता है ताकि आप बाद में उसे देख सकें। Agent team में specialist members की एक टीम के आगे एक leader होता है। Leader काम की योजना बनाता है, हर step किसी member को देता है, और आप तक पहुंचने से पहले एक reviewer हर step जांचता है। दोनों sidebar में Agents के नीचे एक-दूसरे के बगल में हैं और एक ही स्क्रीन खोलते हैं। फ़र्क़ बस टीम के साइज़ का है। अगर आप कभी ऐसे group chat में रहे हैं जिसमें कोई project manager हो, तो Agent team जाना-पहचाना लगेगा। फ़र्क़ यह है कि हर message, हर handoff और हर फ़ैसला सेव रहता है, और आप scroll करके पीछे देख सकते हैं।

यह एक पूरा हो चुका team session है। सवाल और जवाब एक demo run का उदाहरण डेटा हैं।

प्रिया Agent team खोलती है और New session दबाती है। New team session dialog में वह "Start from a team" चुना रहने देती है और Team लिस्ट से Deep Research Team चुनती है। Dialog इसके पांच members लोड करता है (deep-research-agent, research-analyst, data-researcher, search-specialist, academic-researcher)। "Who leads" के नीचे Orchestrator दिखता है, जो "plans the work up front, then delegates the steps to the agents below"। वह किसी भी member पर "make leader" दबाकर उसे leader बना सकती है।

वह Create दबाती है, leader की chat में अपना सवाल टाइप करती है और भेज देती है। Leader इसे पांच हिस्सों में बांटता है: trials ढूंढना, studies, आंकड़े, उलटे सबूत, और फिर एक जवाब। तीन members एक साथ काम शुरू करते हैं। Data Researcher आंकड़े निकालने से पहले Search Specialist की लिस्ट का इंतज़ार करता है। जब Data Researcher 40% का आंकड़ा रिपोर्ट करता है, तो reviewer उसे "Sent back" मार्क कर देता है, क्योंकि उसमें न source है, न तारीख़, न मापने का पैमाना। वह step दोबारा चलता है, source ढूंढता है, और approve हो जाता है।

आख़िर में उसके पास बीच वाले pane में एक जवाब होता है, और उसके हर आंकड़े की जांच उस agent के अलावा किसी और ने की है जिसने उसे ढूंढा था। साथ में एक ईमानदार "Not covered" लाइन भी मिलती है, जिसे वह डायरेक्टर के लिए अपने नोट में पेस्ट कर सकती है।

टॉम हफ़्ते में कई बार meeting notes से action items बनाता है, और हर बार पहले नियमों वाला वही पैराग्राफ़ chat में पेस्ट करता है। इस काम के लिए टीम की ज़रूरत नहीं है। ज़रूरत है एक ऐसे agent की जो नियम याद रखे।

वह Single agent खोलता है, New session दबाता है और Create in chat tab पर ही रहता है। "New agent" बॉक्स में वह एक लाइन में लिखता है कि उसे क्या चाहिए और Start दबाता है। जो chat खुलती है वह एक setup agent है। वह कुछ सवाल पूछता है, फिर एक नाम, एक @handle और पूरे instructions सुझाता है। Composer के ऊपर एक card आता है जिसमें नाम, handle, Show instructions लिंक और Create agent बटन होता है।

वह instructions खोलकर देखता है कि उसका सबसे ज़रूरी नियम उनमें है या नहीं: owner या deadline का कभी अंदाज़ा न लगाना। फिर वह Create agent दबाता है। वही chat अब वह agent बन जाती है। जब वह अपने notes पेस्ट करता है, तो जो owners और तारीख़ें नहीं हैं वे missing मार्क होती हैं, उनका अंदाज़ा कभी नहीं लगाया जाता। Session अपनी Agent ID rail में रखता है, और अगली बार उसे बस agent चुनना होता है।

दारी एक छोटी product team की releases संभालती है। उसके team session में एक leader और Release Drafter, Change Auditor, Docs Reviewer, QA Summarizer और Approval Prep नाम के members हैं। हर एक release package का एक हिस्सा संभालता है।

Run से पहले वह Goal tab खोलती है और Set a goal दबाती है। Panel बताता है कि goal को success criteria में बांटा जाता है, जो शुरू में fail रहते हैं और जैसे-जैसे agents उन्हें पूरा करते हैं, हरे हो जाते हैं। Session तब तक चलता रहता है जब तक सब pass न हो जाएं या round limit न आ जाए। वह तीन criteria लिखती है, जिनमें आख़िरी यह है कि approval packet पूरा हो। Members के काम करते समय वह Handoffs देखती है ताकि leader से हर member तक और वापस की chain फ़ॉलो कर सके। वह Proposals भी देखती है कि किसी member ने कोई config बदलाव तो नहीं सुझाया, और वहां कुछ भी उसके बिना लागू नहीं होता। वह किसी भी समय leader की chat में जवाब देकर उसे दिशा दे सकती है, और panel header में Pause दबाकर review करते समय run रोक सकती है।

आख़िर में उसके पास release package और यह रिकॉर्ड होता है कि हर हिस्सा किसने draft, audit और approve किया। जो भी पूछे कि notes में कोई लाइन कैसे आई, उसे वह यह दिखा सकती है।

Agent और Agent team वह जगह है जहां काम शुरू होता है। Sessions वह जगह है जहां आप उसे देखते हैं। वह board हर chat, agent, team और terminal session को एक card के रूप में दिखाता है, जो Running, Needs you, Paused, Idle, Done और Failed में इस हिसाब से बंटे होते हैं कि session असल में क्या कर रहा है।

जब एक ही team job बार-बार चलानी हो, तो Loop एक roster को trigger, limits और हर round के रिकॉर्ड के साथ लपेट देता है कि कौन से criteria pass हुए। Graphs उस काम के लिए हैं जिसका रास्ता इस पर निर्भर करता है कि बीच में क्या होता है। Leader वाली बातचीत एक Maestro chat है, इसलिए टीम का जवाब आपके बाक़ी Maestro काम में आगे बढ़ सकता है। Session का Enable sync लिंक उसे project के message channel से जोड़ता है, जहां लोग और agents एक ही जगह बात कर सकते हैं। ज़्यादा जानकारी के लिए Agents feature page और agent sessions overview देखें।

टीम की जगह single agent कब इस्तेमाल करूं? Single agent तब इस्तेमाल करें जब काम एक साफ़ task हो और नियम तय हों, जैसे notes को reformat करना या एक ही अंदाज़ में जवाब draft करना। टीम तब इस्तेमाल करें जब काम के हिस्सों को अलग-अलग tools चाहिए, या जब आप चाहते हैं कि आपके देखने से पहले कोई अलग reviewer काम जांचे।

क्या session शुरू होने के बाद टीम बदल सकते हैं? नहीं। New team session dialog में लिखा है कि टीम "is fixed for this session's life"। Create दबाने से पहले dialog के अंदर आप agents जोड़ या हटा सकते हैं और चुन सकते हैं कि leader कौन होगा। अलग roster के लिए नया session शुरू करें।

क्या इसमें से कुछ cloud पर चलता है? New session form में Local और Isolated runs के विकल्प हैं। उसमें लिखा है कि दोनों आपकी मशीन पर आपकी अपनी keys से चलते हैं और कुछ भी cloud पर नहीं जाता। Chat history default रूप से local रहती है।

क्या agents अपने instructions खुद बदल सकते हैं? वे बदलाव सुझा सकते हैं, जो Proposals में दिखते हैं। Proposal का मतलब accept हो चुकी configuration नहीं है। Agents अपने prompts छू सकते हैं या नहीं, यह एक अलग setting है।
