Ripple-65B Is an Open Coder With 1M Context. Its DGX Spark Script Stops at 128K

Tanggal: 2026-11-05

Posted on Nov 5 • Edited on Nov 5 • AI-assisted

On November 4, Ricursive Intelligence released Ripple-65B Preview, a 65-billion-parameter dense model it says it pretrained from scratch on 12 trillion tokens. The weights are on Hugging Face under Apache 2.0.

The headline is 80.5 on Terminal-Bench 2.1, ahead of Reflection's Beam (501B, 80.1), Meta's Muse Spark Open (816B, 76.4) and Thinking Machines' Inkling (975B, 63.8). Ripple's score is Ricursive's own, set against each rival lab's self-reported figure, and VentureBeat points out these are separate vendor evaluations, not a controlled head-to-head test.

The launch page also says the model's size lets it run efficiently on local devices such as NVIDIA's DGX Spark, a desktop box with a GB10 chip and 128 GB of unified memory. Ricursive's own inference scripts show the window depends on the route. Its two-B200 server recipe defaults to 1,048,576 tokens. Its DGX Spark script sets 131,072.

The card says "up to 1M" context in its intro, while its training table lists a 2M sequence length for the long-context stages.

The architecture is new, and it ships as code. The repo's config sets model_type to ricursive and maps the model class to modeling_ricursive.py in the repo (Hub API). Loading that with Transformers takes trust_remote_code=True, which runs the repo's Python on your machine (Hugging Face docs). This is the publisher's own repo, but read the file before you load it.

Ricursive's pitch: one 65B dense model against MoE models roughly 8 to 15 times its total size, on its own scorecard.

The card's table mixes published numbers with Ricursive's in-house runs, and the harnesses differ: Terminus 2 for SWE-bench Pro v2.0 Hard, DeepSWE 1.1 and one of the two Terminal-Bench columns, Inspect AI for SciCode, and OpenCode wherever no harness is named (card). Ripple's Terminal-Bench lead holds under both columns it reports: 80.5 against Beam's 80.1 self-reported, and 80.5 against Beam's 70.8 under Terminus 2.

It does not lead everywhere. On the same table, Beam scores 81.6 to Ripple's 76.5 on SWE-bench Verified, and 66.1 to 61.42 on SWE-bench Pro v1.0. Muse Spark Open leads DeepSWE 1.1 at 60.0 to 44.3 and MCP Atlas at 89.2 to 71.67. On SciCode, Ripple's 39.4 is the lowest of the five models.

The numbers also move between Ricursive's own documents. VentureBeat found the launch graphic giving Inkling 39.6 on SWE-bench Pro v2.0 Hard, where the card lists 2.0.

"Smaller" needs a footnote too. Beam has 501B total parameters but 23B active per token. Ripple is dense, so every token it generates goes through all 65B, on a Spark that Ricursive's launch page itself describes as low on memory bandwidth next to datacenter accelerators.

Same weights, three routes. The context window you get depends on which one you take.

The OpenRouter row comes from its endpoint listing: BF16, $0.20 per million input tokens, $0.60 per million output, $0.05 for cached input, with tools and tool_choice supported. VentureBeat's article reported a 16,384-token limit there; the listing now shows the full window, so check it before you size a prompt. Together AI lists the model as coming soon.

MacBooks? VentureBeat says Ricursive's social announcement names them, but the release doesn't pin down a laptop memory configuration, speed or usable context. The Hub already lists nine community quantizations, including MLX and GGUF builds, all from uploaders other than Ricursive. Ricursive's own cards don't mention them.

Several of the agentic scores on Ripple's card came from the OpenCode harness, and OpenCode can talk to OpenRouter through its provider config. That makes a fair test cheap: give one ticket to the agent you trust and the same ticket to OpenCode on Ripple, then compare the diffs.

The card calls this a Preview release, and the NVFP4 build is marked Experimental. Neither the release nor VentureBeat's coverage cites an independent Terminal-Bench run of the 65B model. Together's listing still says coming soon. Fireworks, which the launch page said would go live later on release day, had no confirmed rate in VentureBeat's report. And the community MLX and GGUF builds still have to prove themselves on real agent tasks.

If you own a Spark, measure tokens per second on spark.py with a prompt close to 128K before you plan local agent work around it.
