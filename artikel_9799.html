We scanned 3,728 AI-built apps in Germany, Austria and Switzerland. Here is what we could measure.

Tanggal: 2026-11-21

Posted on Nov 21 • Originally published at decivo.de

We run a recurring outside-in scan of web apps built with tools like Lovable, Base44 and Bolt that show a connection to Germany, Austria or Switzerland. The latest run closed on 8 November 2026 and covered 3,728 apps. This post summarises what the scan could actually measure, and just as important, what it could not.

Full report with charts and the open dataset (CC BY 4.0): https://www.decivo.de/en/ki-app-report-2026

A disclosure first: we build and repair software for a living, including apps like these. So treat this as a vendor survey. The dataset is public precisely so that others can check it.

Every share comes with its count and its base. Rules that need a real browser only count across the 3,280 apps where the browser check ran.

Accessibility is the most common real problem. Three in four apps had at least one serious violation once the page had finished rendering: buttons without a name, inputs without a label, insufficient contrast. AI builders produce interfaces that look right. Whether a screen reader can use them is not visible in the preview.

Consent banners that do not control anything. In 13% of the apps a tracker fired on the very first load. In the EU that usually means the analytics script sits in the page head and the banner was added later without wiring the two together.

Soft 404s and empty HTML. More than half of the apps answer any made-up path with "200 OK", and a quarter ship almost no text in the initial HTML. Search engines and many AI crawlers that do not run JavaScript see an empty page.

Known-vulnerable libraries are rarer than the headlines suggest, from the outside. 6% shipped a front-end library version with a public advisory. That is a lower bound for security problems, not an estimate: see the next section.
