Open Redirects: Find and Fix Them Before Phishers Do

Tanggal: 2026-11-15

An open redirect is the bug security teams love to mark "low" and phishers love to use. Your login page takes a next parameter, sends the user wherever it says, and suddenly a link that starts with your real, trusted domain lands a victim on a credential-harvesting page. The fix is not a smarter regex. It is a small allowlist function, written once and used by every redirect in the app.

I build PixelValut, a set of free browser-side security tools. I wrote this with help from AI tools and checked every command, output and claim myself. Below are real responses from a tiny test server I ran on Nov 15, 2026, the bypass payloads that defeat naive checks, and the validation pattern I ship instead.

Direct answer: An open redirect is an endpoint that forwards users to any URL supplied in a parameter, letting attackers borrow your domain's trust for phishing or OAuth token theft. Fix it by accepting only same-origin relative paths or an explicit allowlist of exact hostnames, parsed with a real URL parser, and falling back to a safe default.

Every open redirect I have fixed came down to one missing function. Parse the destination, allow same-origin paths and exact hostnames, default to a safe page, and use that helper everywhere your app sends a user onward. Then test the classic bypasses in CI so the bug does not come back with the next login refactor.
