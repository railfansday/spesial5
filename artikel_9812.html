Why is changing one line in a Word document so difficult for an AI agent?

Tanggal: 2026-11-16

Posted on Nov 16 • Edited on Nov 16 • Originally published at attentionform.com

“Change the deadline to 18 November. Keep the formatting. Leave everything else alone.”

If you work with proposals, reports or contracts, that is an ordinary request. You should be able to give it to your AI assistant and get a Word document back that your colleagues can continue editing.

But knowing what to change is only half the job. The assistant also has to preserve the document around it: the bold phrase in the same sentence, the numbering, the table on the next page, the comments left by a reviewer. And you need a way to check the result and recover an earlier version.

We built ASTra for that workflow. It lets an AI agent, a script or a person create and edit .docx files through one engine: read a short outline, change exactly what was asked, check the result against the Office schema, and keep a history you can undo.

A board report built by ASTra from one Markdown file, then formatted by an agent. Styled tables, three native Word charts, callouts and a footnote. The company and figures are fictional. Rendered by Microsoft Word from the .docx file.

In short. ASTra works on Word (.docx) files and runs on your own machine.

A .docx is a ZIP package of XML files, images and relationships between them. One visible sentence can be split into several runs of text with different formatting. Comments, tracked changes, charts, headers and footers add more parts.

An agent that reads all the XML spends its context on markup. An agent that rebuilds the document from extracted text can lose details you expected to keep. ASTra gives the agent an outline and operations on document elements. The agent chooses the change; ASTra handles the document mechanics.

The engine does the work. The three front ends are thin: they call the same code, so a document behaves the same way whichever door you use.

The same operations also cover tables, lists, charts, images, equations, callouts, footnotes and endnotes, cover pages, watermarks, page borders, hyperlinks and bookmarks, and document properties. Every edit, whichever front end sends it, goes through the same loop.

Edits are all or nothing. We sent a batch of four operations whose third one named a paragraph that does not exist. The batch was refused, and the outline read back afterwards was identical to the one before it:

Impossible values are refused at the call. Ask for a paragraph colour of banana and the call is refused before the batch runs. The message names the field and lists the forms it accepts: six hex digits, auto, or one of ten colour names such as red or grey. Colours, highlights and sizes that no writer can use used to pass this check and fail after the whole batch had run, with a raw XML message.

Bad files are refused at save time. Everything that gets past the call is checked again when you save, against the Office schema. If an edit makes the file worse, the save is refused and the agent gets the first errors with their locations:

The file on disk is untouched. By default ASTra lets you keep working on a file that already has errors (for example one re-saved by another program) and blocks only the edit that makes it worse. Strict mode refuses any error at all. How well does this catch problems? See the measurement below, including where it falls short.

Every save can be undone. Through the MCP server, each successful save is recorded as a history entry, and if the entry cannot be written the save is refused. On the command line you switch recording on once with astra history --init. A revert is a new history entry, so nothing is rewritten and you can undo the undo:

(Output shortened.) A revert puts back every part of the package exactly as it was saved, not just the visible text.

An agent that can see the page catches a table that spills over or a heading left alone at the bottom. visual_inspect (and astra visual) draws a page as an image, and export --format pdf writes a PDF. On Windows, ASTra uses Microsoft Word when Word is installed and falls back to LibreOffice if Word fails. On Linux and macOS it uses LibreOffice. A program you name is never replaced by another one.

By default a render draws no comments. --show-markup (showMarkup in the MCP tools) draws tracked changes and comments, so a reviewer can see the redlines in the image. The output then shows reviewer names and deleted text, so check it before you share it.

Two things to know. Word and LibreOffice lay a page out differently, so page breaks can move between them. And the Word checks were done on one Word build on one machine, so treat a page image as a check, not as proof of how Word shows the page. Before a render, ASTra also neutralises network references in the document (a linked image, a template, a field that fetches a file) on the copy it renders, so drawing a page does not contact the network by default. If you want those references loaded, you can allow it: --allow-network-references on the command line (or the environment variable ASTRA_ALLOW_NETWORK_REFERENCES), allowNetworkReferences: true in the MCP tools. Only do that for a document you trust: loading a network location can leak information, for example a Windows login hash through a UNC path.

The astra tool is the engine without an AI in the middle. It suits shell scripts, CI jobs and anyone who wants to see exactly what changes. Every command accepts --json. Exit code 0 means success, 1 an operational failure and 2 a usage error, so a script can branch on the result.

Can an AI agent edit a Word document without losing formatting or tracked changes? ASTra is designed to preserve formatting and tracked changes during targeted edits, because it edits the document's elements and not its text. Review the result on your own files. ASTra changes the paragraph you point at. In our corpus, an edit changed the content of no other paragraph in 1,047 of 1,047 cases. The XML of the whole file is rewritten on the first save, so the bytes are not identical. That is a count on generated documents, so try it on a copy of your own files.

Do I need Microsoft Word installed? No. ASTra reads and writes .docx files itself. You only need a renderer (LibreOffice, or Word on Windows) if you want page images or a PDF.

Will Word open the file ASTra saves? Every save is checked against the Office Open XML schema with Microsoft's Open XML SDK validator. By default a file that already had errors can still be saved, and a save that adds new errors is refused; strict mode refuses any error. A valid file is not a correct document, and passing the schema check does not guarantee that Word opens it without a message, so open important files and look.

Does the document leave my machine? In normal use ASTra works on local files and makes no network calls of its own. The AI assistant you connect it to sends what it reads to its own model provider, and a document that links to an external resource can make a renderer fetch it.

Which assistants work with it? Any client that supports MCP servers over stdio, including Claude Code, Claude Desktop, Cursor and Windsurf. The Connect page has the setup for each.
