identity-deep-dive: A Weekly Briefing and a Sourced Spec Map for OAuth, WIMSE, and OpenID

Tanggal: 2026-11-14

If you work on identity, the specs move under you. An OAuth WG draft goes to the IESG, a WIMSE draft gets a new revision, the OpenID4VCI repo switches a document's JSON properties to snake_case. Each of those is a signal that "now is the time to read this", but the signals are spread across IETF Datatracker, the mail archive, and about ninety GitHub repositories (66 under openid, 21 under oauth-wg, and 6 under ietf-wg-wimse in the 2026-11-14 run).

I kept missing them, so I built identity-deep-dive. It collects those sources every six hours, explains what changed, and keeps a map of where each spec stands and who documents support for it. The result is a static site at 0-draft.github.io/identity-deep-dive, in English and Japanese.

The material Claude reads is written by third parties, so the workflow treats it as untrusted. The model runs in a job with read-only repository access and read-only tools. A second job with write access has no model in it: it validates the output and only then commits it. Every explanation and pick also carries a Japanese version.

As of 2026-11-14, the spec map covers 62 OAuth, OpenID, workload identity and credential specs in 11 layers, from grants and flows to security events. Each card says where the spec stands and how it relates to the others: what it builds on, profiles, extends or replaces. Of the 62, 25 are RFCs, 11 are OpenID Final specifications, one comes from another body, and the rest are IETF drafts at various stages.

The part I care about most is the "documented support" list. A vendor or project is listed only when its own documentation, or a standards body's page naming it, says it supports the spec. Each of the 211 claims stores the official URL and an exact phrase from that page. A weekly job with no model in it fetches every page and checks that the phrase is still there. If it is gone, the site says "not re-verified since" with the date instead of quietly showing stale support. Experimental, alpha and beta support is counted separately as preview.

For example, DPoP currently lists eight: Okta, Auth0, Keycloak, Duende IdentityServer, node-oidc-provider, Spring Authorization Server, Spring Security and Authelia's oauth2-provider.

Most specs on the map also have an explainer: when you reach for it, the problem it solves, how it works, what it requires and what to watch out for, with section references. For 17 RFCs there is a side-by-side page with the official English text next to an unofficial Japanese translation.

The ranking feeds deep dives. Once a week a job takes the top candidate in each track that has no deep dive yet, has Claude draft one from the source text (context, spec notes, an interop checklist and a hands-on log), and opens it as a draft pull request. Nothing lands until a person has checked it against the primary sources.

Reading that closely pays off. The WIMSE HTTP signature deep dive records that draft-ietf-wimse-http-signature-08 (Sections 3 and 3.6) tells recipients to validate the workload identity token "as specified in Section 5.1.4" of the workload credentials draft. Neither -02 nor -03 of that draft has a Section 5.1.4. In -03, WIT validation is Section 5.1.3. As of 2026-11-14 there are nine deep dives, including OAuth 2.1, SD-JWT VC, Client ID Metadata Documents and OpenID4VCI. If WIMSE itself is new to you, I wrote a WIMSE deep dive earlier.

If you follow OAuth, workload identity, or OpenID specs, the site gives you "what moved this week" without opening Datatracker, and the map tells you where a spec stands and who documents support for it, with a link you can check yourself. If a source, a spec or an implementation you care about is missing, issues and PRs are welcome. A new support claim needs an official URL and the exact phrase from that page.
