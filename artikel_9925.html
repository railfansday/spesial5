I am working on a PDF-merging program. This is to merge several pages from different PDF-files into one big page (not just concatenating the pages after each other). This is to align several maps produced from AutoCAD into one big map while removing overlapping sections.

While it's a small project I have learned some new things already about MuPDF and I'm using Raylib for the simple UI.

Working with PDFs like that is both a hassle and fun in a way for me. I’ve got a little script I knocked together at some point that takes 5.5x8.5in half-page PDFs as input and imposes them in the right order on 8.5x11in paper so that I can print on regular paper and make a single slice through the stack. It was a little tricky figuring out the right sequence, but not bad overall. We use it for making flight test cards and it’s saved me and my colleagues a surprising amount of hassle.

Working to perfect mddog, a terminal tool that lets you preview Markdown in the terminal as if you're on GitHub or Obsidian: headings at the correct sizes, images rendered, etc.

I look at Markdown files a lot for work and prefer to just stay inside the terminal without switching out of it so this has been a game changer.

It basically works by building out the Markdown into its real format using macOS built-in engines like CoreText and CoreGraphics, then send the outputs to the terminal as image strips. I'm enjoying learning about the terminal, Rust, and the kitty graphics protocol throughout this process.

If you give it a try, let me know how you like it!

Coincidentally, I was working on a similar scenario recently: I wanted to convert all Markdown files in a repo to HTML, preserving links between Markdown files (as well as to other resources), for later viewing in a terminal browser (like w3m). I had gotten tired of piping cmark-gfm into w3m, and I've now got a 500 KB self-contained proof-of-concept (I actually just hacked it into my luasmith static site generator).

The most similar tools I found prior to starting were grip (which depends on a GitHub endpoint) and Ghore (which is built on Node, which I've been successfully avoiding lately).

mddog looks nice and is much fancier, but I needed to support older terminal emulators... and NetBSD :)
