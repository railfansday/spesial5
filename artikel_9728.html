Unlike a lightweight Python script, Nod spins up a multi-container stack under the hood:

It also ships with 4 built-in guardrails: an encrypted credential Vault isolated from raw prompt context, human-in-the-loop Telegram approvals before sending money or emails, a default $5/task cap, and a $200/month default budget ceiling.

Nod has a keep-awake flag while a job is actively running, but it cannot override a closed laptop lid or OS sleep mode. For reliable morning inbox triage, scheduled web checks, and remote Telegram triggers while traveling, Nod belongs on an always-on Linux box.

Reality check on 4 GB servers: Do not try to squeeze Nod onto a 2 GB or 4 GB VPS if you are building from source. Running docker compose build alongside PostgreSQL and headless Chromium tabs routinely spikes memory and triggers OOM crashes. On an 8 GB KVM VPS, peak load hovers cleanly around ~4.6 GB, leaving comfortable headroom.

Before v0.8.0, one expensive frontier model handled everything, including repetitive background cron jobs. Now, you can assign a dedicated Scheduled Model using a low-cost open-weight API while reserving frontier models only for high-stakes interactive prompts.

Routing those 18M scheduled tokens through an open-weight API like DeepSeek v4.1 Flash ($0.30 input / $1.20 output per million) slashes the monthly API bill from $72.00 down to $9.45.

If your VPS already hosts n8n, Coolify, Traefik, or Nginx on ports 80 and 443, do not enable Nod's bundled Caddy HTTPS profile, or it will crash trying to bind the same ports.

Low-cost KVM providers like RackNerd give you clean root Linux performance, not a managed PaaS control panel. Set up automated off-server backups for your .env file, Vault keys, and PostgreSQL volumes.

Even n8n notes that safety approvals are model-driven. Smaller open-weight models are noticeably weaker at spotting prompt injections buried inside untrusted emails or scraped web pages.

Nod is evolving fast (v0.7 ➔ v0.8 ➔ v0.9+). Before running git pull && docker compose up --build, always read the latest release notes for .env or schema changes, and back up your volumes first.
