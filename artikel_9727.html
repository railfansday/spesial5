The SEO launch checklist for a new website, with a prompt that runs it for you

Tanggal: 2026-11-13

New sites rarely fail in search because of strategy. They fail because the staging noindex shipped to production, the canonicals point at the preview domain, or the sitemap lists URLs that redirect. And the checklist everyone followed had nothing you could actually run.

Below, a popular launch checklist becomes commands: checks on the build before launch, then on the live domain after. The examples use an Astro dist/ folder and https://www.example.com; swap in your own. At the end is a prompt that has a coding agent run the lot.

All three should print nothing. The last pattern assumes rel comes before href, the usual order in layouts.

Then open dist/robots.txt. A Disallow: / left over from staging blocks the whole site. Add a Sitemap: line with the full URL.

alt="" is correct for decorative images, so the last check only flags missing attributes. One H1 is a good convention, but Google has said several won't hurt, so treat those hits as review items.

npx linkinator ./dist --recurse serves the folder and follows every link. Each 404 is a broken link or a page that didn't build.

For orphans (pages nothing links to), crawl the local preview with Screaming Frog (free up to 500 URLs) with sitemap crawling on. It flags sitemap URLs it never reached through links and shows click depth. The original's "within 3 clicks" is a rule of thumb, not a Google rule.

Paste it into the Schema Markup Validator, which checks any schema.org type, and the code tab of Google's Rich Results Test, which only reports types Google turns into rich results.

Valid markup doesn't guarantee a rich result. Since August 2023, Google shows FAQ rich results only for well-known government and health sites, so FAQPage on a dentist's site changes nothing in search.

Run npx @lhci/cli autorun. Without a url list, Lighthouse CI audits only five auto-discovered pages, so list one per template.

Lighthouse emulates a phone by default. That's your "mobile usability" check now, since Search Console's Mobile Usability report and the Mobile-Friendly Test were retired in December 2023. Then tap through the menu, forms and phone links on a real phone.

You want 200 and at most one redirect each. Then check headers:

An X-Robots-Tag: noindex header works like the meta tag, and grepping dist/ will never find it. Cloudflare Pages adds it to every preview deployment by default, so confirm production doesn't send it. Run the loop over any old site's URLs too.

If robots.txt blocks a URL, Google never sees its noindex, so protect staging with a password, not Disallow.

No output is a pass. The loop doesn't follow redirects on purpose: a sitemap should list only canonical URLs, so a 301 is a fail. Google ignores priority and changefreq, so skip them.

URL Inspection only works on a verified property Google can reach, so "test key URLs in GSC" is a post-launch job for most staging setups. Add a Domain property through DNS, submit the sitemap, and run "Test live URL" on one page per template. Under "View tested page", check the rendered HTML has your main content and nav links.

The PageSpeed Insights API defaults to desktop, so set the strategy:

A new site has no Core Web Vitals field data until enough Chrome users visit, so at launch you're reading lab numbers. The metrics are LCP, INP (which replaced FID in March 2024) and CLS.

Open the live site through Tag Assistant or GTM preview, then GA4's Admin > Data display > DebugView. Submit a test form and tap the phone link. Each event should appear once, with the right name. Mark it as a key event (GA4's current name for conversions).

For two weeks after launch, watch the Pages report and Crawl stats in Search Console for 404s and 5xx errors.

Before trusting a PASS, run two of the commands yourself and compare. Any row whose evidence paraphrases instead of showing real output gets rerun.

Short on time? Run the noindex grep on dist/, then the redirect loop and X-Robots-Tag check the moment the site is live. Those catch the mistakes that keep a whole site out of Google. Everything else fixes one page at a time.
