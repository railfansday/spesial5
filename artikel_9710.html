One agent task can involve multiple models, and each call can send customer records, contracts, or source code to a different vendor. That’s definitely something agent developers should take into account from the start.

Lucky for you, this article will show you how the data flows, compare main deployment options, and offer you a checklist to help you prepare for your next security review.

To put it bluntly, adoption is outpacing control. Here’s what’s happening, in a nutshell:

86.9% of companies delayed AI deployments because security and governance weren’t ready, not because of budget or internal support.

69% said security concerns are slowing agent adoption down, and 83% named data leakage as the barrier.

Shadow AI incidents (staff using unapproved AI tools) more than doubled, from 20% to 43%, and they cost more than the year before.

About three quarters of organizations have an AI governance body, but only 12% call it mature. The State of AI 2026: Security Insights CISOs Need to Know +5

The EU AI Act deadline for high-risk systems has been extended, but the rules still apply. To be specific, under the Digital Omnibus on AI, stand-alone high-risk systems listed in Annex III (hiring tools, credit scoring, education) must now comply by December 2, 2027 instead of August 2, 2026.

In its contract review agent walkthrough, Superlinked describes a review process that involves ten model calls. These include triage, vision, Optical Character Recognition (OCR), embeddings, reranking, entity extraction, text-to-SQL, risk reasoning, orchestration, and a safety guardrail. In a typical stack, these calls may involve several different vendor accounts.

If the checklist above has got you thinking, “We need to self-host the sensitive steps, but we don’t want to build or maintain a model-serving platform,” well then, SIE (Superlinked Inference Engine) is the right fit for you.

SIE is an open-source inference server that runs encoders, rerankers, entity extractors, and generation models on your own infrastructure. You can run it on anything, from a laptop to a production Kubernetes cluster. It supports 100+ open models through four primitives: Encode, Score, Extract, and Generate.

If you want to test models before setting up a cluster, SIE Serverless offers a hosted version with SOC 2 Type 2 and US or EU data residency. However, keep in mind it’s still a hosted processor, so test it with non-sensitive data and move sensitive workloads to your own cloud. If you want help running it in your own cloud, take a look at Native Inference.
