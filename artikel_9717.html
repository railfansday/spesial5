Wi-Fi Connected But No Internet: The Layer 2 vs Layer 3 Triage Protocol

Tanggal: 2026-11-17

Quick answer: “Connected, no internet” means the 802.11 Layer 2 association succeeded, but Layer 3 connectivity failed. The usual cause is a missing or invalid default gateway, failed DHCP lease, WAN authentication loss, blocked DNS, or an upstream routing fault. Test the gateway, a public IP, and DNS in that exact order.

Operating systems generally report Wi-Fi as connected after the wireless adapter completes association with the access point. At that point, the client and router have established Layer 2 communication, often including WPA2 or WPA3 key exchange.

That status does not prove any of the following:

A device can show full Wi-Fi bars, receive an address such as 192.168.1.100, and still have no internet because the router lost its PPPoE session, lacks a WAN VLAN tag, or cannot forward traffic beyond the LAN.

Do not begin by changing DNS servers or resetting the router. Test each layer in sequence.

Use a wired Ethernet connection when possible. Wi-Fi adds RF interference, roaming behavior, band steering, and driver variables that can obscure the underlying fault.

Before running commands, collect these facts:

DHCP is a client-server protocol that assigns reusable network addresses and delivers configuration parameters, including the information needed for IP operation. The Dynamic Host Configuration Protocol (RFC 2131) defines the lease-based allocation process used by most home and business networks. [29]

Open Command Prompt as a standard user. Replace 192.168.1.1 with the actual default gateway shown by ipconfig.

Replace en0 with the active Wi-Fi interface if necessary. Use networksetup -listallhardwareports to identify it.

PPPoE is common on DSL and some fiber installations. The router must authenticate with the ISP using a username and password before it can establish a session and receive routing information.

A factory reset, firmware update, ISP password change, or expired account can remove or invalidate those credentials. The result is a router that still serves DHCP and Wi-Fi on the LAN but has no upstream route.

Fix the WAN configuration before changing client settings. Confirm the connection type, PPPoE username, PPPoE password, and any ISP-required service name. Do not assume the ISP login equals the Wi-Fi password or router administrator password.

Some ISPs require a VLAN tag on the WAN interface. IEEE 802.1Q inserts a four-byte tag into the Ethernet frame, allowing one physical link to carry separately identified logical networks.

If the router loses the required VLAN ID after a reset, the WAN port may show a physical link while DHCP discovery or PPPoE discovery receives no response.

If the ISP specifies a VLAN ID, restore it exactly. A VLAN tag is not optional when the provider requires it. Do not add a VLAN tag unless the ISP confirms that one is required.

ARP maps an IPv4 address to a MAC address on the local network. If two devices claim the same IP address, ARP replies can alternate between different MAC addresses. The client may reach the gateway intermittently or not at all.

This is common when a static IP is assigned inside the DHCP pool, a forgotten device reuses an address, or a virtual machine bridge shares an IP with the host.

If the MAC address associated with the gateway changes between pings, investigate duplicate IP assignment. Assign infrastructure devices addresses outside the DHCP range or create DHCP reservations.

Hotel, airport, campus, and some ISP networks intercept DNS queries before full internet access is granted. The network may return a captive-portal IP address for every domain, causing a browser to open a login page while normal applications fail.

This is not always a router fault. The client may be associated to Wi-Fi, receive an address, and have a default gateway, but the upstream network blocks DNS or HTTP traffic until authentication completes.

If both queries return an unexpected internal address or the same IP address for unrelated domains, a captive portal or DNS interceptor is likely active. Open a plain HTTP page, complete the portal login, then retest.

The legacy “30-30-30” reset method is not a universal procedure for modern flash-based routers. Modern devices often use NAND or NOR flash storage, staged bootloaders, and separate configuration partitions.

Holding Reset too briefly may only reboot the router. Holding it too long can interrupt a firmware-related process or place certain models into recovery mode. The correct reset duration is model-specific.

If the router enters a boot loop, use the vendor’s official recovery utility or TFTP procedure only after confirming the exact model and firmware instructions. The directory of default router IP addresses can help identify the correct administration address before recovery.

A common mistake is treating DNS failure as proof that the internet is down. DNS and routing are separate services.

If ping 1.1.1.1 succeeds but nslookup routeripguide.com fails, do not reset the router. Inspect DNS settings first.

For a practical recovery sequence after a reset, follow the seven-fix walkthrough for Wi-Fi connected with no internet.

This guidance is general and may not match every ISP or router model. Follow the instructions supplied by your internet provider and the documentation for your exact router before resetting or changing WAN settings.
