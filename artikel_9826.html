osFoundry 的 Agent team 能做什麼？什麼時候一個 agent 就夠了？

Tanggal: 2026-11-06

星期二早上 7:40，Priya 手上有個問題，主管要她午餐前給答案：一週工作四天，產出真的不會掉嗎？她大可以把問題貼進聊天機器人，拿回一段口氣篤定的文字。但找數字的模型，同時也是判斷這些數字站不站得住腳的模型，而它很少會反駁自己。她要的是一個人去找試行案例、另一個人把數據拉出來，再由第三個人把沒有來源的東西全部退回去。

osFoundry 是一款在自己電腦上跑 AI 工作的桌面應用程式，把工作交給 agent 的方式有兩種，兩者關係很近。Agent（側邊欄顯示為 Single agent）是一個有名字、只負責一件事的 agent：你給它指示，它會拿到自己的 ID，例如 AG-0001L，每一次執行都有紀錄，之後可以回頭追。Agent team 則是讓一位 leader 帶著一組專職成員。Leader 規劃工作、把每個步驟分給成員，再由 reviewer 檢查每一步，通過後才會交到你手上。兩者都在側邊欄的 Agents 底下，緊鄰彼此，開啟的也是同一個畫面。差別只在成員多寡。如果你待過有專案經理的群組聊天，Agent team 用起來會很熟悉。不同的是，每則訊息、每次交接、每個判定都會留下來，可以捲回去看。

Priya 打開 Agent team，按下 New session。在 New team session 對話框裡，她維持「Start from a team」，並從 Team 清單選了 Deep Research Team。對話框載入了五位成員（deep-research-agent、research-analyst、data-researcher、search-specialist、academic-researcher）。「Who leads」底下顯示 Orchestrator，說明是「plans the work up front, then delegates the steps to the agents below」。她也可以在任何一位成員上按「make leader」，改由那位成員帶頭。

她按下 Create，在 leader 的聊天裡輸入問題送出。Leader 把問題拆成五個部分：找試行案例、找研究、找數字、找反面證據，最後整合成一個答案。三位成員同時開工。Data Researcher 會先等 Search Specialist 的清單出來，才開始拉數據。當 Data Researcher 回報一個 40% 的數字時，reviewer 把它標成「Sent back」，理由是沒有來源、日期也沒有衡量指標。這一步重新執行、找到來源，然後通過。

最後她在中間窗格拿到一個答案，裡面每個數字都經過「找到它的 agent 以外」的人檢查。她還拿到一行誠實的「Not covered」，可以直接貼進給主管的筆記。

Tom 一週會好幾次把會議紀錄整理成待辦事項，每次都得先把同一段規則貼進聊天裡。這種工作不需要團隊，需要的是一個記得規則的 agent。

他打開 Single agent，按 New session，停留在 Create in chat 分頁。在「New agent」欄位寫一行說明需求，按下 Start。打開的聊天是一個設定用的 agent。它問了幾個問題，接著提出名稱、@handle 和完整的指示。輸入框上方會出現一張卡片，上面有名稱、handle、Show instructions 連結和 Create agent 按鈕。

他打開指示，確認他最在意的那條規則有寫進去：絕對不要猜負責人或截止日。然後按下 Create agent。同一個聊天現在就變成那個 agent。他貼上會議紀錄後，缺少的負責人和日期都會標示為缺漏，絕不會用猜的。這個工作階段會在側欄保留它的 Agent ID，下次他只要選這個 agent 就好。

Dari 負責一個小型產品團隊的發版。她的團隊工作階段有一位 leader，成員是 Release Drafter、Change Auditor、Docs Reviewer、QA Summarizer 和 Approval Prep，各自負責發版包的一部分。

執行之前，她打開 Goal 分頁，按下 Set a goal。面板說明，目標會拆成幾條成功條件，一開始都是失敗，隨著 agent 達成逐一轉綠。工作階段會持續執行，直到全部通過或達到回合上限。她寫了三條條件，最後一條是核准資料包要齊全。成員工作時，她在 Handoffs 追蹤從 leader 到各成員再回來的整條鏈。她也會看 Proposals 裡有沒有成員提出的設定變更，那裡的東西沒有她點頭都不會套用。她隨時可以在 leader 的聊天裡回覆來調整方向，審閱時也可以按面板標題列的 Pause 暫停執行。

最後她拿到發版包，以及每個部分由誰起草、誰稽核、誰核准的紀錄。有人問 release notes 裡某一行是怎麼來的，她都能拿出來給對方看。

Agent 和 Agent team 是工作的起點，Sessions 則是你觀察工作的地方。這個看板把每個聊天、agent、團隊和終端機工作階段都顯示成一張卡片，依照工作階段實際的狀態分到 Running、Needs you、Paused、Idle、Done 和 Failed。

同一份團隊工作需要反覆執行時，Loop 會替成員名單加上觸發條件、上限，以及每一回合哪些條件通過的紀錄。Graphs 則適合路徑會依中途結果而改變的工作。與 leader 的對話是一個 Maestro 聊天，所以團隊的答案可以接著用在你其他的 Maestro 工作裡。工作階段的 Enable sync 連結會把它接上專案的訊息頻道，讓人和 agent 在同一個地方溝通。更多內容請看 Agents 功能頁面 和 agent 工作階段概覽。

什麼時候該用單一 agent，而不是團隊？ 工作是一件明確、規則固定的任務時，用單一 agent，例如整理筆記格式，或用同一種語氣草擬回覆。工作包含需要不同工具的幾個部分，或你希望在看到結果前先由另一位 reviewer 把關時，就用團隊。

工作階段開始後可以換團隊嗎？ 不行。New team session 對話框寫明團隊「is fixed for this session's life」。在按下 Create 之前，你仍可以在對話框裡新增或移除 agent、選擇由誰帶頭。要換成其他成員名單，就開一個新的工作階段。

這些東西有任何部分在雲端執行嗎？ New session 表單提供 Local 和 Isolated 兩種執行方式。表單上註明兩者都用你自己的金鑰在你的電腦上執行，不會有任何東西送到雲端。聊天紀錄預設存在本機。

Agent 可以改寫自己的指示嗎？ 它們可以提出修改建議，建議會出現在 Proposals。提案不等於已接受的設定。Agent 能不能動到自己的 prompt，是另一個獨立的設定。
