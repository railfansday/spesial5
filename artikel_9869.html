Microsoft's NTLM security changes trip up third-party logins

Tanggal: 2026-11-26

It's not our fault if you've implemented it wrong

Microsoft's November security updates can break authentication in some third-party applications and devices following changes to NTLM message signing.

Affected systems include authentication proxy servers, single sign-on (SSO) products, and application packaging tools, the company's support notice says.

The failures stem from products that claim to supply required information during NTLM authentication but return incomplete or empty data, Microsoft said: "An affected device might set the NTLMSSP_NEGOTIATE_TARGET_INFO flag in its CHALLENGE_MESSAGE but provide an empty or incomplete TargetInfo field."

Administrators can use the notice's network trace and event log examples to identify affected products. For confirmed cases, the temporary workaround is to set the ClientAllowUnsignedNtlm Registry value to 1 on affected clients. This stops the client offering signing, backing out the new default rather than fixing the incompatible product. The recommended long-term options are a vendor update or Kerberos authentication, where supported.

The value sits under HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0 and defaults to 0, enabling clients to offer signing on non-anonymous connections.

The NTLM changes arrived in the November 10 update as phase 1 in a 2-phase process. In phase 1, "Windows client devices begin offering NTLM signing on all connections by default. Servers accept both signed and unsigned clients. Auditing events identify clients not using signing."

Phase 2, scheduled for May 2027, will make Windows servers require NTLM signing by default. "Clients that do not offer signing will be rejected by secure servers," Microsoft stated.

Ominously, Microsoft warned that it "might remove the registry keys at a future date," so the company is not kidding about the temporary workaround thing.

The additional protections were added to address CVE-2026-118737, a vulnerability in which "improper verification of cryptographic signature in Windows Remote Procedure Call Runtime allows an unauthorized attacker to execute code over a network."

NTLM is on Microsoft's hit list, having joined the Deprecated Features list in 2024. It dates back to the era of Windows NT, and Microsoft has made clear that it wants customers to move to Kerberos, which became the default in 2000. Even so, NTLM lingers on.

Deprecation doesn't remove Microsoft's obligation to secure NTLM while it remains in supported Windows releases. For administrators, though, the immediate task is identifying incompatible products before temporary exceptions give way to stricter enforcement. ®
