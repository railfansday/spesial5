Bitcoin privacy weakness links wallet addresses to network nodes in 30 out of 30 tests

Tanggal: 2026-11-28

On Nov. 25, researcher Abubakar Sadiq Ismail reported linking addresses to the correct nodes in all 30 attempts in regtest, Bitcoin Core’s local testing environment.

Ismail said the same behavior can expose a watch-only wallet, which monitors addresses and transactions without storing the keys needed to spend the funds.

A service can keep its spending keys off the machine it uses to monitor deposits, and a match identifies the node whose wallet recognizes the address.

In his write-up on wallet rebroadcast for Delving Bitcoin, Ismail described a long-known behavior in Bitcoin Core. After a wallet learns about an unconfirmed transaction, it can announce that transaction again to peers.

That repeated announcement can reveal that the node’s wallet recognizes activity involving a particular address or output. The blockchain records confirmed transactions, while the extra clue about who tracks an address comes from the node’s network activity.

Ismail’s reported matches show that wallet behavior can reveal an address-to-node link in a controlled network.

A node is a computer running software that exchanges information with peers on the Bitcoin network. Its wallet tracks addresses and transactions, and software that loads addresses into a Bitcoin Core wallet can inherit the exposure, even when its role is limited to monitoring.

One node may track two addresses that belong to different users of the same service, and a single operator can also run several nodes. An observer who sees a match learns how a wallet is used, while ownership across those addresses remains uncertain.

An operator can use private broadcast to shield the initial announcement of a transaction. If it stays unconfirmed, Bitcoin Core’s wallet may later announce it more broadly.

A user who chooses a private path for the first announcement can still lose some of that protection in the later broadcast.

Ismail pointed to -walletbroadcast=0 as a way to disable wallet-initiated announcements, which also stops the wallet from automatically announcing the user’s own new transactions. Users who turn off wallet broadcasting need a separate way to relay the payments they intend to send.

A pending Bitcoin Core proposal would preserve part of rebroadcast’s original purpose. A pending transaction can drop out of a node’s mempool, its local pool of unconfirmed transactions, and still need another chance to reach the network.

Bitcoin Core pull request #36482 would limit wallet rebroadcast to transactions the node newly accepts into that pool. The wallet could still relay transactions that had dropped out if the node accepts them again.

It would suppress repeat announcements for transactions already in a node’s mempool, while other wallet rebroadcasts could still reveal which node recognizes a transaction.
