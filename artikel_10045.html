Flaws in VMware and KVM need attention, if you have time while fixing Java, PHP, and everything else

Tanggal: 2026-11-21

Critical Virtzilla bugs allow authentication bypass, as a nested virtualization issue got Digital Ocean ducking

If you’ve got a moment to spare in between sorting out emergency patches for PHP, Java, and PostgreSQL, VMware has just bid for any remaining space on your schedule by publishing two critical-rated security advisories.

VMSA-2026-0009 addresses CVE-2026-123890, a 9.8-rated flaw that VMware says means a malicious actor with network access to vCenter may exploit this issue to bypass authentication and gain unauthorized access to the system. vCenter is the tool admins use to manage fleets of virtual machines. The flaw is present in VMware’s flagship Cloud Foundation suite.

VMware also wants its users to address CVE-2026-123891, which allows attackers to read and write the database used by SDDC Manager, the tool for managing entire software-defined datacenters. Attackers can execute arbitrary commands and elevate privileges to root.

The prospect of an unknown party getting access to vCenter or SDDC manager is not pleasant. At least VMware has fixed its software.

The virty giant hasn't done the same to address a second advisory, VMSA-2026-0010, which warns that Cloud Foundation, Aria Operations, and VCF Operations HCX products all use Apache – which has a 9.8-rated remote code execution vulnerability (CVE-2026-119618).

VMware plans to ship new versions of its products with a patched version of Apache, but for now only has workarounds that disable the http2 protocol.

Admins who oversee virtual infrastructure also need to pay attention to Linux KVM, the subject of a curious incident over the last 24 hours.

This mess started with the November 18 disclosure of CVE-2026-99312, a bug which allows an attacker to use a guest virtual machine to inflict Denial of Service (DoS) or memory corruption attacks on the host.

It’s bad news whenever someone with access to a guest VM can attack the host, because it means gaining access to a single tenant can potentially harm all the other guest VMs or peer into the memory a guest uses.

This flaw, however, isn’t a worst-case scenario guest-host escape, because it only impacts users of AMD processors who employ nested virtualization – the practice of running a hypervisor inside a virtual machine. Nested virtualization isn’t commonly used in the enterprise, but clouds employ it to do things like powering OS emulators. The bug’s CVSSv3 score is therefore a modest 5.5.

Security researcher Oren Tomtov of Terra Security says the flaw meant he could access 127 GB of host RAM on a Digital Ocean “Droplet” – the junior cloud’s name for its cloudy VMs.

Yomtov says he told Digital Ocean and the Linux kernel security team about the flaw in October. Maintainers got busy and delivered a fix to the mainline kernel on November 2, full fixes landed on the 17th. The CVE then appeared on November 18.

Yomtov and Terra Security quickly posted their analysis of the flaw – but then took the posts down within hours.

The Register understands that Digital Ocean asked for the posts to come down because it needed more time to update its Linux implementations. The company has not responded to multiple requests for comment.

Terra’s analysis of the flaw asserts that it was introduced to KVM in 2022, when developers wrote a fix for CVE-2022-3344. The company believes 3.2 percent of CVEs in the Linux kernel were introduced by the fix for another CVE.

The good news about CVE-2026-99312 is it’s easy to defeat without an update, by disabling nested virtualization in KVM. ®
