So I'm trying to figure where switching to a standard user account actually protects me. I suppose it prevents me from accidentally deleting everything in /Applications without an additional password prompt, but that's not really a problem I worry about.
On a somewhat practical level it's not going to. It may limit the blast area to just your user account. There may be some things malware can't do because it's not an admin but it will still be pretty capable of owning your entire user account without any special permissions. Most malware doesn't take advantage of security vulnerabilities so much as tricking the user into authorizing activity they shouldn't. Because of all the different security features where even an admin can't modify core system files and signed code is almost a requirement, trojaned apps delivered as scripts have become the most popular infection vector. Click fix style delivery where someone searches for a remedy to a problem and they get instructions to just copy this command into a terminal and run it are common. As are trojans which are nothing more than Apple Scripts which load in the script editor but the instructions for installing the app just say to run command-R which launches the malicious script from the editor. As such if you are even somewhat savvy these things are pretty easy to see coming.

If you are a developer or have developer tendencies and are installing stuff at the unix layer in MacOS such as updated scripting languages or other utilities, even if you use something like Home Brew, the best thing you can do is stop installing that stuff directly in your system. Figure out what container/VM workflow works for you and install that stuff there with restricted access to the rest of your system and user account.

Developer supply chain attacks are becoming more of a problem. The Binance hack started on a Mac when one of the developers downloaded a trojan version of Home Brew. Binance caught it and shut it down very early but the problem was the trojan was able to exfiltrate some sensitive info which informed the intruders of ANOTHER more senior engineer they should target. I haven't seen reports of how that engineer was compromised.
