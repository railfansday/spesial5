Sooner or later someone on your team asks it. Maybe it’s a product manager, maybe the head of content, maybe a teacher who’s just marked forty near-identical essays: can we tell when people are pasting in ChatGPT output?

The short answer is no, not with certainty. Anyone who promises you that is selling something.

But you can get a useful signal, and you can show it to the people who actually make the call: editors, teachers, moderators. In this tutorial you’ll build a small Express app that takes some text, sends it to an AI detector API, waits for the result, and highlights the sentences that look machine-written.

I’m using the Quetext AI Detector API here. It scores each sentence, not just the whole document, and you can try it without a subscription. Most detection APIs follow the same submit, poll, fetch pattern, though. If you switch providers later, you’ll rewrite one file.

Put the key in an environment variable. Don’t hard-code it, and don’t let it anywhere near the browser.

You’ll make three calls. Analysis takes a few seconds, so the API hands you a ticket and makes you come back for the result. Keep the Quetext API docs open in another tab while you follow along; they list every endpoint, field and error code.

Every request sends your key in an X-API-Key header. The minimum input is 50 words, which sounds annoying until you realise no detector can say anything useful about a two-line comment.

And remember this number: 10 requests every 5 seconds, per account. Progress checks count. It’ll come back to bite you in the production section if you ignore it.

A quick security point. Those sentences came from your users, then went through an outside service. Treat them as untrusted. That’s why the code uses textContent and never innerHTML, as the OWASP XSS prevention cheat sheet recommends.

The demo keeps an HTTP request open while it polls. Fine on your laptop. Not fine with real traffic.

Submit the text, save the report id with a pending status, and respond straight away. A worker (BullMQ, a cron job, a serverless queue, whatever you already use) does the polling and updates the record once it’s done. The UI says “Checking…” until the result shows up.

Here’s how it goes wrong. It’s Monday morning, 20 editors open their review queues and click “Check” at roughly the same time. Each request polls on its own, and within a few seconds you’ve hit 429s across the board, because the 10-per-5-seconds limit covers your whole account, not each user.

Use one worker that loops through every pending report, with a short pause between calls. Problem solved.

You pay per word, so don’t check every blog comment. Article submissions, assignments and paid freelance work usually justify the cost. Cache results against a hash of the text too. Someone who submits the same draft three times shouldn’t cost you three times.

AI detection doesn’t catch copying. Someone can lift a 2019 blog post word for word and it’ll score 0% AI, because a human wrote it. Just not this human. If originality matters to your product, the same API has plagiarism endpoints that work exactly the same way. The API documentation covers both.

Developers skip this part. It’s also the part that ends up in angry support tickets.

In 2023, Liang and colleagues at Stanford ran essays written by non-native English speakers (all human, written for the TOEFL) through seven AI detectors. On average, the detectors labelled more than 61% of them as AI-generated. Simple vocabulary and textbook grammar read as “predictable,” and predictability is exactly what detectors look for.

Picture an international student getting an automatic zero because a script said so. You don’t want to be the person who built that.

Do that and the detector is a fast first pass that points people at what’s worth a closer look. Your humans still make the call.

You send text, the service checks how predictable each sentence would be to a language model, and you get back a probability that a machine wrote it. Most of these APIs are asynchronous. You submit, get a report ID, poll until it’s ready, then fetch the result. The better ones score individual sentences as well as the whole text, which makes building a sensible review screen much easier.
