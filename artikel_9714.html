NVIDIA's Dory Shows Why Thinking Longer Doesn't Make AI Smarter

Every team that uses AI develops the same reflex within a month. The answer comes back wrong, so someone turns up the thinking. Reasoning effort from medium to high. A bigger thinking budget. The model that "thinks longer."

Sometimes that works. Often you pay more, wait longer and get the same wrong answer.

It's hard to see why while "thinking" stays a vague word for whatever the model does before it replies. This autumn NVIDIA shipped a model that turns thinking into something you can count, and the reason becomes obvious.

The model is called Dory. It has four billion parameters and one unusual setting: how many times to run its middle layers.

Its layout is 8 input layers, a 20-layer core and 8 output layers. Every token passes through the input layers once, the core as many times as you choose, and the output layers once.

This design is a looped transformer. With two or more loops, Dory's authors report better average results than selected larger models across twelve benchmarks.

Two things about those numbers are worth a second look.

First, thinking harder is no longer a metaphor here. It's 20 layers, run again.

Second, the stored number never moves. The weights on the fourth pass are the weights on the first. If you could put a counter on them it would read: used 4 times, changed 0 times. The model isn't learning anything while it loops. It's refining a working state that it throws away when the answer is done.

So a looped model gets more computation per token. It doesn't get one extra fact.

Here's the fastest way I know to feel what that means. Two facts:

Alice finished the race before Bob. Bob finished before Cara.

For the first question, more passes help. The model has to connect two facts, and connecting is what computation does.

For the second, you can loop four times or forty. The working state gets more refined. The missing fact stays missing. One query against a results table answers it in milliseconds.

Loops add computation, not information. I call the check the Alice test: before you raise the thinking level, ask whether the answer is already in what the model has.

It sounds too simple to matter until you sort a week of real failures with it. The model didn't know the current price. It quoted the old contract version. It guessed what was in the logs. Every one of those fails the Alice test, and every one of them gets "fixed" by somebody turning thinking up.

That's the expensive mistake: paying for effort that can't succeed.

Even when thinking is the right tool, it isn't free. One of this month's reports is useful precisely because it priced the trade.

It also kills a comfortable assumption. More thinking isn't a ramp that only goes up. An extra pass can improve an answer, change nothing, or degrade a state that was already right. The only line that always rises is the bill.

Part of the confusion is that "loop" means four different things in AI, and each one invoices you differently.

Of these, only the agent loop brings in new information, because only tools reach outside the model. The first two are thinking. If your failure is a missing fact, they can't save you, however much of them you buy.

Looped transformers are a real advance: depth as a dial instead of a bigger file. Pointed at the right failure, that's cheap capability. Pointed at a missing fact, it's a slower and more expensive way to be wrong.
