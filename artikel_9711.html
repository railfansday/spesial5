Google's OKF cut LLM hallucination 81% on DFIR telemetry — because the format, not the model, was the problem

Tanggal: 2026-11-13

Posted on Nov 13 • Originally published at sushantpoudel2028.com.np

DFIR tooling still hands its telemetry to LLMs as one big JSON dump. At scale that is a context-exhaustion engine: latency climbs, the model starts hallucinating, and the analyst has to re-verify everything it said.

Our new paper asks a narrow question: does the shape of the serialization matter more than the model?

We benchmarked Google's Open Knowledge Format (OKF v0.1) — a graph-native, selectively traversable format — against flat JSON, using 7,680 inference cycles across five open-source model architectures with escalating decoy densities (four difficulty tiers).

The useful part is not "OKF is better". It's the mechanism: when the model can traverse to the relevant subgraph instead of ingesting a monolithic dump, context stays small and grounded — so the failure mode that produces hallucination never gets loaded in the first place.

If your incident-response agent ingests JSON telemetry, this is a format decision you can test before you touch the model.
