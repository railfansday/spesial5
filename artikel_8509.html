I believe this may be a bug, but it could be intended behavior.

When you “click here” to to select situations that may apply, and then choose “discount rate” it adds an input to allow changing discount rate as expected.

If you change the discount rate and recalculate, you get different NPV as expected.

If you then uncheck discount rate (or even uncheck the click here for additional scenarios), and submit again, it still uses the discount rate the user supplied. It does still show the rate inout box, so if you’re paying attention before submitting you may realize this.

You have to either reload (losing all your inputs) or manually change the discount back to get the default rate again.

It seems like unchecking discount rate (or unchecking “click here” to select situations) should restore the default rate in the calculation (currently 3.11) and hide the input box.
This is the intended behavior. The goal is for an input to change only if the user changes the input. Checking the boxes just changes what is displayed in the interface.
