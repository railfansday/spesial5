Viggle Remake is a video-to-video editing model built from rank-256 LoRA adapters on MiniMax-H3. It supports character replacement as well as broader edits to objects, backgrounds, weather, lighting, and style. The maintainer is Viggle.

Use it to recast people or characters, change outfits, add or remove objects, and alter a video's setting, weather, lighting, or style while retaining source motion, camera, timing, and soundtrack. The repository describes both single-shot use and workflows that split longer films into windows.

The reference sampler handles one window of about 12 seconds; longer videos require windowing, which the MCP workflow can perform. The base MiniMax-H3 files total about 144 GB, and the reference sampler requires the base text encoder and one GPU with at least 80 GB memory at bf16; ComfyUI alternatives are documented for smaller cards. A six-section prompt is required, and timestamps must fit the requested frame count. Painted reference frames determine identity and appearance; pinned frames also constrain composition. Audio is carried from the source rather than generated. Documented failure cases include non-humanoid characters in a long take, fine-detail artifacts, and timing drift in multi-shot clips rendered without pins. The model cannot verify identity or consent; use footage and likenesses only with appropriate rights and consent, and label generated content as AI-generated.

Viggle-Animate is described as replacing a character, while Remake also supports object insertion or removal and changes to setting, weather, and lighting. Viggle-Animate is the supplied internal alternative. Other supplied alternatives include LTX-2 Retake, Luma Ray 3.2 Reframe, Ray2 Flash Modify, and Luma Modify Video; the supplied descriptions do not establish a quality, speed, or cost ranking. The README identifies Remake as the “Viggle-Animate v2” previewed on the Viggle-Animate card; that is a version relationship, not evidence that the separate Animate model has Remake's full feature set.

The model consists of two PEFT LoRA adapters, swap and edit, each rank 256 and about 2.67 GB, applied to the MiniMax-H3 base transformer. Lower-rank variants at ranks 128 and 64 are also provided, at about 1.34 GB and 0.67 GB respectively; the README describes their output as near-identical. The required base files are about 144 GB. The repository also contains ComfyUI assets and merged int8 and GGUF transformers. The reference sampler uses bf16 and requires an 80 GB-or-larger GPU. It renders at 24 fps, with frame counts from 90 to 345 following 17n + 5; the README recommends up to 294 frames. At short edge 736, the documented output size is 1280×736. No training data, training procedure, or measured benchmark results are supplied. The weights are derivatives of MiniMax-H3 and are subject to the MiniMax H3 Community License; the supplied code directories are Apache 2.0.

The reference sampler takes a source video, a prompt in MiniMax-H3's six-section format, and one to four painted reference images. Each reference can optionally be pinned to the source frame it was painted from. Select swap to replace people or characters, or edit for other edits such as object changes and background, weather, or lighting changes. The prompt's timestamps must fit the selected frame count. The sampler accepts a seed and short-edge setting; ffmpeg must be available on PATH.

The sampler produces a rendered video window and carries over the source soundtrack; it does not generate audio, so silent input produces silent output. The MCP workflow can split a longer video into windows and splice the rendered results with the soundtrack. The README documents 24 fps output and a 1280×736 size when --short-edge 736 is used.

The reference sampler also requires an ffmpeg binary on PATH and an 80 GB-or-larger GPU for bf16. The prompt must follow the six-section format, and the reference images must be painted frames.
