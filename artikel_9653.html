Rate Limits, Kill Switches, Permissions: Crypto's Lessons for Agent Oversight

Speaking on June 30, 2026, the Bank of England's Deputy Governor Sarah Breeden raised market-wide guardrails, circuit breakers or kill switches for instance, as one way of handling AI agents in financial markets. Crypto venues have been running kill switches, permission scopes and rate limits on software traders, account by account, for years. That track record suddenly matters to a lot more people than crypto traders.

In crypto, programmatic trading is nothing special. South Korea's Financial Supervisory Service has put API trading at about 30% of the country's crypto turnover, and automated traders there can fire off dozens of transactions per second. Exchanges had to answer "which software acted?" long before anybody started calling that software an agent.

What they came up with was the API key. A key belongs to an account, comes with a defined set of permissions and has a human owner. So every automated order can be traced back to someone who allowed it.

Steven McWhirter, Global Head of Policy at Binance, frames the requirement this way, "When software can investigate, decide and move money, we need to be able to say with confidence which agent acted, on whose authority, and who remains accountable."

Next to what the paper behind that quote proposes, an API key is a blunt instrument. Even so, it already covers two parts of the question, which agent and on whose authority, and the account holder covers the third. For years that was enough to keep high-speed software trading traceable.

Mainly that the controls have to be mechanical, and safe by default. Binance's own setup shows how. An API key with no IP restrictions is limited to reading data, and you can't switch on withdrawal permission until IP restrictions are in place.

Rate limits follow the same thinking. Go over them and you get an HTTP 429 response; keep going and you'll face automated IP bans that stretch from 2 minutes to 3 days for repeat offenders. Trading systems also have to keep proving they're alive. If one stops sending its heartbeat, a countdown endpoint cancels all open orders, which is a dead man's switch by another name, and options market makers have had a kill switch since 2022.

Banks are starting to staff up for this. Capgemini found that just 10% of financial firms run AI agents at scale, yet 48% of financial institutions are creating roles to supervise them.

And where banks do run agents at scale, customer service tops the list at 75%, with fraud detection at 64%. So the stakes face the customer from the very first day. Supervisors need levers to pull. These are levers, and they already exist.

Binance's Know Your Agent policy paper takes those mechanics and turns them into a general framework. It argues for least-privilege mandates and a clear split between agents that fetch information, agents that recommend transactions and agents that control or move value, with identity, monitoring and approval requirements getting stricter as authority goes up. Delegation can't go beyond the original mandate. And institutions have to be able to suspend, restrict or revoke an agent while keeping an audit trail.

Every one of those principles has an exchange counterpart. Read-only keys are least privileged in action. Gating withdrawal permission behind IP restrictions is a tougher requirement for moving value. Kill switches are revocation.

Seen that way, the paper takes controls that already work for one kind of software actor, the trading bot, and extends them to any agent that might touch money. The IMF has made a similar case. Its April 2026 note on agentic payments argues that kill switches should act as a layered governance capability.

Several big venues now offer agent toolkits with permission scoping built in. OKX's Agent Trade Kit doesn't register order tools at all if the connected key lacks trading permission. Coinbase for Agents only lets transfers go to a user's own portfolios, with no withdrawals to outside addresses, and caps each payment at 5 USDC. With Bybit's official MCP release, API keys can be scoped to read-only queries, to specific trading permissions or to full execution. Binance's Agent OS adds Model Context Protocol access under permissions and limits the user sets.

Nobody coordinated, and yet the venues ended up with much the same defaults. That's roughly what an operating manual looks like before someone writes it down. Defaults only protect the people who keep them, though. It's still the account owner who decides how wide an agent's permissions go.

Agent oversight in traditional finance doesn't need to start from scratch. There's no call for triumphalism here, either; crypto just ran into the problem first. For banks, the harder shift is cultural, not technical. It means treating revocation as routine and starting every agent on the narrowest permission that works. Good defaults are where accountability begins.
