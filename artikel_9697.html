Financial Modeling Prep groups its API into a few broad MCP tools (chart, statements, calendar, company, quote and more), each with an endpoint parameter. It's a smart design: Claude sees 27 tools instead of hundreds, but can still reach as-reported statements, revenue segments, DCF models, 13F filings and earnings-call transcripts.

In my test it returned the same 342.37 close for AAPL, plus a VWAP. Vodafone on the LSE worked as VOD.L, with the first close of the window at 110.96, which matches Yahoo exactly. Its P/E TTM of 38.91 came with about 60 other ratios in one call.

Then I asked for the earnings calendar with limit: 5.

It returned 4,000 rows and 611,957 characters. The limit was ignored, and because the response was capped at 4,000 rows, Monday and Tuesday (November 9 and 10) were missing entirely. So what's the catch? Yahoo doesn't offer a public API. yfinance reads Yahoo's website endpoints, and Yahoo's terms limit that to personal use. When Yahoo changes something on their side, the library breaks until a volunteer fixes it, and your agent goes blind in the meantime.

It also means rate limits you can't see. Yahoo throttles heavy traffic from a single IP, and an agent looping over 50 tickers is exactly that kind of traffic.

Best for: personal projects and quick experiments. Don't build a product on it.

Massive is the new name of Polygon.io, and its MCP server (401 stars, MIT, marked "experimental") takes an unusual approach: instead of one tool per endpoint, it exposes three, search_endpoints, call_api and query_data. The model searches the API docs, then calls what it needs. There's also a hosted version at mcp.massive.com.

Docs only. That three-tool design is worth copying. A server with 100 tools sends 100 tool descriptions to the model before the first question. Massive sends three, and the model discovers the right endpoint on demand. It costs an extra call per question, but it keeps the context window free for the actual data.

If you still have an old Polygon key in your environment, POLYGON_API_KEY works as a deprecated alias.

Massive is built for US market data at high resolution: the pricing page highlights websockets and 20+ years of history. It lists Stocks Advanced at $199/month, with Financials & Ratios as a separate $29/month add-on (individual use only) and extra datasets such as NYSE order imbalances at $49/month.

Best for: US intraday and high-frequency analysis.

Financial Datasets was designed for LLM agents rather than retrofitted. Its open-source server (2.3k stars, MIT) has 10 focused tools: income statements, balance sheets, cash flows, prices, news and crypto. There's also a hosted endpoint at mcp.financialdatasets.ai.

Docs only. The tools are named exactly like the questions an analyst asks: get_income_statements, get_balance_sheets, get_cash_flow_statements, get_current_stock_price, get_historical_stock_prices and get_company_news, plus four crypto tools. That naming makes it easy for a model to pick the right one.

The site lists 27,530 tickers including delisted companies, and 30+ years of history. The pricing is simple:

Best for: fundamentals-driven agents that need clean statements, not breadth.

Alpaca's official MCP server (1.1k stars, MIT) is the only one on this list that writes. It can place and cancel orders for stocks, ETFs, options and crypto, manage positions and watchlists, and read market data.

Docs only. Setup is one command once you have keys from a free paper account:

It defaults to paper trading (ALPACA_PAPER_TRADE=true). The README warns plainly that the server "can place real trades" once you set that flag to false. Two more details from the docs: the latest 15 minutes of market data need the Algo Trader Plus plan, and short-selling locates aren't available in paper trading.

If you connect it, design for mistakes. Keep paper trading on while you test prompts, ask Claude to confirm every order before sending it, and cap position size in your instructions. A model that reads "sell half" as "sell all" is a bad day in a live account.

Best for: pairing with a research server like EODHD: one MCP to think, one to execute.

No MCP server makes an agent correct on its own. Here's what I'd still validate by hand:

What is a financial MCP server? It's a server that implements the Model Context Protocol so an AI assistant like Claude, ChatGPT or Cursor can call financial data APIs as tools: prices, fundamentals, news, filings. The model decides which tool to call and reads the result.

Is there a free MCP server for stock market data? Yes. The open-source Yahoo Finance MCP and the SEC EDGAR MCP are free. EODHD has a free plan (20 calls/day, 1 year of end-of-day data) and Alpha Vantage gives 25 requests/day. All of them run out quickly once an agent starts making several calls per question.

Which MCP server works with Claude Desktop? All eight do. The EODHD APIs v2 endpoint and the hosted Alpha Vantage, Massive and Financial Datasets servers connect as remote connectors. Yahoo Finance, Alpaca and SEC EDGAR run locally through uvx or Docker.

Can an MCP server place trades? Only the ones built for it. Alpaca's MCP can place orders (paper trading by default). The EODHD APIs MCP tools are all read-only, so a research agent can't trade by accident.

Do MCP servers return the same numbers? Prices do: EODHD, FMP and Yahoo all returned 342.37 for AAPL on November 6, 2026. Calculated fundamentals like P/E differ by up to about 2.4% between providers, because each one uses a different price and earnings definition.

The model is no longer the bottleneck. Claude can reason about a balance sheet just fine.

The MCP server you connect decides what your agent knows, how much context it wastes, and whether it still works next month.
