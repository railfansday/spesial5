CVE-2026-111181 Operational Response for Node.js Middleware

Tanggal: 2026-11-19

An effective response to CVE-2026-111181 starts with a precise question: which deployed Node.js services load an affected body-parser release, and can a compressed request reach that parser? The vulnerability is a network-reachable process crash, so a package version without runtime configuration data is only part of the answer.

The issue is a high-severity denial-of-service vulnerability in body-parser, published by the Express security team and recorded in GitHub as GHSA-27r3-jxmh-p828. CVE-2026-111181 has a CVSS 3.1 score of 7.5 with vector CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H, and the weakness is CWE-248.

Affected releases are older than 1.20.9 and versions 2.0.0 through 2.3.0. Fixed releases are 1.20.9 and 2.4.0. A request that advertises a compressed body and then supplies trailing bytes can cause an uncaught stream error after the parser has completed the normal body read.

The parser creates a decompression stream and connects the request to it. It reads the decoded request body and calls the next middleware while the decoder may remain connected. The successful read has detached its error listeners. Trailing data after a valid compressed member then reaches the decoder and raises an error after completion.

The pipe re-emits the exception, and the Node.js process exits because the application has no handler for the late error. A matching route is unnecessary when parsing is global before routing. Authentication is not consulted when the parser runs before the auth middleware. The attacker needs network access to a reachable parser path.

The immediate consequence is worker availability. An orchestrator may restart the process, but repeated triggers can keep the service in a failure cycle and distract monitoring with generic restart alerts. The CVSS vector records no confidentiality or integrity impact, so the investigation should focus on process termination and service disruption.

The availability impact can spread beyond the target route. A worker may drop in-flight requests, affect dependent services, and consume capacity while health checks recover. The reviewed reporting described a public reproduction but did not report confirmed in-the-wild exploitation.

Inventory applications that declare body-parser directly and applications that receive it transitively. Run npm ls body-parser in the built application, inspect the lockfile used by the image, and confirm the version inside the deployed container or serverless package. A source check that occurs before packaging is not enough.

Identify whether the parser is global or attached to selected handlers, whether it processes compressed bodies, and whether it executes before authentication. Those facts determine the practical attack path. The parser may be used with an Express application or a plain Node.js HTTP server.

ZoomEye Search app="Node.js" returned 5,569,018 matches. The selected CVE Filter returned 0 for vul.cve="CVE-2026-111181". The larger Search count is the Exposure, but it represents Node.js product fingerprints, not confirmed vulnerable middleware.

The query does not show package versions, Express use, parser placement, or accepted encodings. The zero Filter result does not prove absence. Treat the broad count as a prompt to reconcile internet-facing and internal Node.js services against the dependency inventory.

Update to body-parser 1.20.9 or later, or 2.4.0 or later, rebuild the deployment artifact, and verify the runtime version. If compressed request bodies are unnecessary, set inflate to false so encoded requests are rejected before a decompression stream is created. Test the compatibility effect before deciding to use this workaround.

Add restart and uncaught-exception alerts, preserve process logs for recurrence analysis, and check that patched images are the ones actually receiving traffic. The reviewed sources provide a public reproduction and a fixed release path. The response should prioritize services that expose the parser to untrusted networks and cannot yet demonstrate a fixed resolved package.
