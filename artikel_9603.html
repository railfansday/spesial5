CSP basics: allow only what you mean to run, not block everything

Tanggal: 2026-11-27

Posted on Nov 27 • Originally published at ismyappok.com

Someone told you to add CSP, so you pasted the one line default-src 'self'. What actually changed? It is easy to end up with no idea.

CSP is not a way to block all scripts. It is an allowlist: you name what may run on the page, and everything else is stopped. Start from default-src 'self' and add only the sources you really use.

Picture the front desk at an event. There is a guest list, and only people on the list get in. Anyone else stays outside, even if they are standing at the door.

CSP (Content-Security-Policy) is one of the headers a server sends with its response. It tells the browser where this page may load scripts, styles, images, and frames from, and which inline code (written directly in the HTML) it may run.

Nothing about the page looks different. What changes is whether the browser runs or stops code you did not expect to be there.

A malicious script can be slipped into a form field on your page. This attack is called XSS (cross-site scripting).

It is not the input field itself that is dangerous. If the text is treated as text (escaped) when it is displayed, the script does not run.

CSP is the last resort at that moment. Even a script that made it onto the page will not run if it is not on the list.

The more your site has forms, logins, payments, or contact pages, the more this matters. A purely static profile page has less to protect, but adding CSP still does no harm.

As with the guest list at the desk, only the sources you list load on the page.

Start with default-src 'self'. default-src is the fallback for every other directive, and 'self' means "only this site (the same origin)".

From there, add only what you actually use.

'none' means "load from nowhere". It is a good idea to add object-src 'none' and base-uri 'self' from the start. object is an old plugin entry point, and a base tag can rewrite where links on the page point.

Do not use * or http:. * means "from anywhere", which defeats the allowlist. http: allows sources that are not encrypted.

'unsafe-inline' allows scripts and styles written directly in the HTML. 'unsafe-eval' allows eval() and similar calls that run a string as code.

Both weaken CSP a great deal. MDN warns that they defeat much of the purpose of having a CSP.
