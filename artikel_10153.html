Yeah, crypt() *should* return a NULL pointer, *not* some arbitrary string when there's a fault. Entirely musl's bug.

For legacy reasons, Crypt() is not allowed to return a null pointer. Some old applications do not expect a null pointer and will crash. On error, it instead returns a string that starts with *. In GNU C the string starts with * and then has a partial, invalid hash. In Musl C it just has the *. Crypt() never returns * on success.
