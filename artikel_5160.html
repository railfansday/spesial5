Coinbase’s blockchain got faster. Some apps can still connect but get no data

Tanggal: 2026-11-09

Apps still using Base’s retired Flashblocks feeds can connect without receiving updates. They need a new data route, not another reconnect.

Coinbase’s Base blockchain retired its Flashblocks data feeds in the Nov. 5 Denim upgrade, requiring apps using them to migrate. The old WebSocket endpoints still accept connections but no longer deliver data, according to Base’s migration instructions.

Denim activated on mainnet at 18:00 UTC on Nov. 5. Base’s upgrade overview describes complete canonical blocks every 200 milliseconds, each with its own hash, state root and receipts. These are the chain’s blocks rather than previews of a block still being built.

The compatibility trap is that an open connection no longer establishes that an app is receiving updates. Reconnecting to a retired Flashblocks endpoint leaves the underlying integration problem unresolved.

Denim retired Flashblocks. Apps must move their data route to canonical block and RPC streams.

Developers must also review what their apps expect from the pending block tag. Base still accepts that tag, but it now resolves to the latest canonical block. It no longer exposes Flashblocks preconfirmation state, and there is no direct equivalent for that former preview.

That change matters for requests reading balances, transaction counts or simulated contract results against pending state. An application retaining the old assumption can mistake an accepted response for a preview even though it is reading canonical state.

Transaction handling changes too. Apps can keep polling eth_getTransactionReceipt, but a receipt becomes available once the transaction enters a canonical 200ms block. Preconfirmed receipts and preconfirmed transaction results are no longer available.

Base recommends inventorying Flashblocks subscriptions, WebSocket connections and pending-tag requests, along with flashblock_index usage and node flags. It advises testing migrated integrations on Base Sepolia or Vibenet.

Base’s Denim upgrade notice, still marked “Verifying” on Nov. 9, carried a Nov. 5 update at 18:14 UTC reporting an investigation into periodic transaction inclusion delays and a higher than expected rate of empty blocks. The notice contained no subsequent resolution update.

A 200ms block cadence describes how often blocks arrive; it does not promise that every submitted transaction enters the next block. Inclusion also remains separate from finality. In its Denim announcement, Base says a block becomes safe when its batch is posted to Ethereum and final when Ethereum finalizes that batch. Apps needing those stronger guarantees still have to distinguish them from the arrival of a canonical block.
