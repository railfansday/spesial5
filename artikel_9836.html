Create, Fill, Encrypt and Sign PDFs in .NET With One Free NuGet Package

Tanggal: 2026-11-10

Sooner or later, most business apps need PDFs. Reports and invoices have to be generated, forms filled from your data, files protected with a password, archived in a long term format, or signed before they go out.

sgcPDF .NET covers all of those jobs in one NuGet package. Everything happens in code, headless, with nothing to open on screen, so the same calls work in a console app or in a background service.

This tour has one section per task: create a document with text, a table and an image, build and fill a form, extract text and images, encrypt with AES-256, save as PDF/A-2b, and sign with PAdES B-B. Every sample was compiled against the published packages and run, and the results quoted below are what it printed.

Create a console app and add the packages:

You only need the second package for the signing sample at the end. It brings in esegece.sgcSign.Community, which supplies the signing key provider.

The packages target netstandard2.0, net472, net6.0, net8.0, net9.0 and net10.0. Through netstandard2.0 they also reach .NET Framework 4.6.2 and later, Mono and Xamarin. The samples use net8.0:

Each sample below is its own file, a static class with a Run() method, because C# allows top level statements in one file only. Drop the files into the project and call the one you want from Program.cs, for example CreateSample.Run();. Everything lives in the esegece.sgcPDF namespace, plus esegece.sgcSign for the signing key.

TsgcPDFDocument is the entry point. Add a page, draw on it and save:

Positions and sizes are in points (1/72 inch), and the origin is the bottom left corner of the page, so y grows upward. The y you pass to DrawText is the text baseline. The table is the exception: DrawOnPage takes the top left corner, and the rows grow downward from there.

The table header text is white, so give SetHeaderBackground a dark colour. A light one leaves the header row unreadable.

The sample expects a logo.png in the working directory, but any PNG, JPEG, BMP or TIFF file will do. It prints Saved 01_create.pdf, 1 page(s) and writes a 21.7 KB file. Opened again, Info.Title reads back as "Quarterly report", and the PNG is stored as a compressed image object. Here is page 1, rendered to PNG with the library's own raster renderer, TsgcPDFRendererRaster:

doc.AcroForm handles interactive forms. This sample builds a page with a text field and a check box, opens the file again to fill it, then saves a flattened copy in which the values become ordinary page content:

Two details are easy to miss. AddTextField and AddCheckBox take the two corners of the field (x1, y1, x2, y2), while DrawRectangle takes x, y, width and height. And generated fields have no visible border, which is why the sample draws a rectangle under each one, so the form reads well on screen and on paper.

The text field reads back as Ada Lovelace and the check box as Yes. In the flattened copy, AcroForm.FieldCount() returns 0 and the page text contains "Ada Lovelace", so the value is now part of the page itself. AcroForm also offers combo boxes, list boxes, radio groups, buttons and signature fields, and it exchanges field data as FDF or XFDF.

This sample reads the report from sample 1 back, the text page by page and the images as PNG files:

Use ExtractTextW, which returns Unicode text. ExtractText returns an ANSI string. The text comes back line by line, from the title through the paragraph, and the table arrives as space separated rows such as North 1,240 EUR 49,600.

The extractor finds the one image and reports it as page 1, 120 x 80, DeviceRGB. The PNG it saved was byte identical to the original logo.png. It can also save JPEG files with SaveAsJPEG, or hand you the PNG bytes in memory with GetPNGBytes.

This sample encrypts the report with a user password to open it and an owner password for full rights, and allows the user nothing but printing. Then it opens the file twice, once with the password and once without:

Use doc.Encryption.SetupEncryption with a permissions value, as above. The shorter doc.SetEncryption(method, user, owner) also encrypts, but it grants every permission, and Encryption.Permissions is read only, so you can't narrow them afterwards. Give the owner password a different value from the user password, otherwise the restrictions don't hold.

To open an encrypted file, call SetPassword before LoadFromFile. With the user password the file opens with 1 page, method emAES_256 and permissions ppPrint, ppPrintHigh, and the first line of text reads "Quarterly report". Without a password, LoadFromFile throws EsgcPDFEncryptionError with the message "Invalid password for encrypted PDF document". A wrong password throws the same error. The owner password opens the file too, with Encryption.IsOwnerPassword set to true.

In the saved bytes the encryption dictionary reads /V 5 /R 6 /CFM /AESV3, which is AES-256 at revision 6, and the title no longer appears in plain text. The other methods are emRC4_40, emRC4_128 and emAES_128.

For long term archiving, set a PDF/A level on the document, then check the saved file with the built-in validator:

PDF/A requires embedded fonts, and the standard 14 fonts are not embedded. That is why this sample registers a TrueType font with AddTrueTypeFont and draws with DrawTextTT. AddTrueTypeFont looks the font up by name among the installed system fonts, which was tested on Windows. On Linux or in a container, pass a .ttf path to AddTrueTypeFontFromFile instead.

The output is PDFALevel = paNone, valid = True, errors = 0, warnings = 0. The paNone is expected, because PDFALevel is not read back from the metadata of a loaded file. Check conformance with TsgcPDFAValidator instead. The file passes the library's own validator with no errors and no warnings. As a control, the same validator rejects the plain report from sample 1 with 7 errors, among them the missing metadata, the fonts that are not embedded and the missing output intent, so it really checks.

The saved file carries XMP metadata with PDF/A part 2 and conformance B, an sRGB output intent, the embedded font, and no encryption. Besides paA2b, TsgcPDFALevel offers paA1b, paA3b, paA1a, paA2a, paA3a, paA4 and paA4f.

Signing comes from the second package, esegece.sgcPDF.sgcSign.Community. This sample makes a self-signed test certificate in code with the BCL CertificateRequest, exports it to PFX bytes in memory, signs the report from sample 1 to PAdES B-B, and verifies the result. No certificate file touches the disk:

The verifier finds one signature and prints valid = True, subfilter = ETSI.CAdES.detached, modified = False, trusted = False. ETSI.CAdES.detached is the PAdES subfilter. The signer comes back as "Demo, sgcPDF Demo Signer", with the organization listed first.

The trusted = False is the expected result, not an error. A self-signed certificate verifies as valid and unmodified, but it isn't trusted, because no trust store knows it. In production you sign with a certificate from a trusted CA, loaded from its PFX file with key.LoadFromFile(file, password).

Verification also catches changes. In a tamper test, one byte flipped inside the signed range of a copy made VerifySignature return false.

B-B needs no network access. For B-T and above (paBT, paBLT, paBLTA), set signer.TSAURL to a time stamp server. The verifier itself is in the core package, so an app that only checks signatures needs just esegece.sgcPDF.Community.

The Community edition is free for commercial and non-commercial use by individuals and organizations under EUR 1M annual gross revenue and with no more than 5 developers. Above either threshold, a paid licence is needed. It has the same feature set as the paid editions, with no functional limits, so everything in this tour runs exactly as shown.

There is one thing you may notice. Now and then, the Community edition prints a short licence notice to stderr when the first document or parser is created. It appears at most once per process and not on every run, and most runs print nothing at all. Because it goes to stderr, output you redirect from stdout stays clean. It doesn't block: timed runs with and without the notice differed by about a millisecond.
