How a Stack Works: A Quick Walkthrough with Java

Tanggal: 2026-11-07

A browser's Back button, an undo feature, and the JVM's own method call stack all share one idea: the last thing added is the first thing removed. That structure is a stack, and it earns its name honestly - it behaves like a stack of plates. You add a plate to the top, you take a plate from the top, and you never slide one out from the middle.

Let's build the browser-history version in Java and watch it work.

That restriction is the whole point. Because you can only touch the top, "last in, first out" (LIFO) is guaranteed - no indexing, no searching, no surprises. Here is the full life of a small browser-history stack, animated:

Java has a legacy Stack class, but you should not use it in new code. The official JavaDoc for java.util.Stack says it directly: "A more complete and consistent set of LIFO stack operations is provided by the Deque interface and its implementations, which should be used in preference to this class." Their own example is Deque stack = new ArrayDeque(); - and that is what we will use.

Check before you pop. Calling pop() on an empty stack throws NoSuchElementException. The while (!history.isEmpty()) guard in the demo is not decoration - it is the standard pattern. If you would rather get a signal than an exception, poll() returns null on an empty stack instead of throwing.

Declare the type as the interface. Writing Deque history = new ArrayDeque<>(); instead of ArrayDeque history = ... means the rest of your code only depends on the stack operations, and you could swap the implementation later without touching it.

All three operations are O(1) - constant time, however big the stack grows. The restriction is what makes it fast.
