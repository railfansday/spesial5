Port 22 and port 3306 exposed: what it means and how to close them

Tanggal: 2026-11-19

Posted on Nov 19 • Originally published at qsa.sh

When a scan lists 22/tcp or 3306/tcp as open on your public IP, anyone on the internet can connect to your SSH server or your MySQL/MariaDB server and read its version before logging in. For SSH, the fix is key-only login plus a source allow-list or a VPN. For MySQL, the fix is bind-address = 127.0.0.1 and an SSH tunnel for remote admin work.

The free scan (curl qsa.sh) checks the top 1,000 TCP ports of the IP you connect from. Both ports are on that list: in nmap's nmap-services frequency data, 22/tcp ranks 5th and 3306/tcp ranks 14th among TCP ports, and both appear in the NmapTop1000 list that naabu 2.7.0 uses. The free output shows open ports, service versions, a severity count, and the top 3 findings in full. The Full tier ($5/month) scans all 65,535 ports and returns the full finding list. See how it works for the exact scope of each tier.

The vulners script matches on the upstream version string. Distributions often backport security fixes without changing that string, so check your distribution's security tracker before acting on a CVE line.

SSH provides remote shell access, scp/sftp file transfer, and port forwarding. RFC 4253 requires both sides to send an identification string in the form SSH-protoversion-softwareversion as soon as the connection opens, so the server software and version are visible to anyone who connects.

Keep your current SSH session open until you have tested a new login in a second terminal. A bad setting can lock you out.

1. Switch to key-only login. Copy your public key to the server and confirm a key login works:

Then disable password logins. On Ubuntu, /etc/ssh/sshd_config starts with Include /etc/ssh/sshd_config.d/*.conf, and sshd uses the first value it reads for most keywords, so a drop-in file overrides the main file:

Both PasswordAuthentication and KbdInteractiveAuthentication default to yes. With UsePAM yes, keyboard-interactive login through PAM works like a password prompt, so set both to no. PermitRootLogin defaults to prohibit-password; no blocks root entirely. sshd -t checks the file, and sshd -T prints the effective settings. The service is ssh.service on Ubuntu; other distributions may name it sshd.service.

2. Allow only known source addresses. With ufw, add the allow rule for your admin IP, then remove any broader rule for port 22. ufw evaluates rules in order and the first match wins:

Replace 203.0.113.10 with your own address. In a cloud provider, apply the same source restriction in the security group or network firewall. If the source cannot be pinned, ufw limit ssh/tcp denies an address that opens 6 or more connections within 30 seconds. OpenSSH 9.8 and later also apply PerSourcePenalties by default, which refuses connections for a period from addresses that repeatedly fail authentication.

3. Move SSH behind a VPN or a bastion. With WireGuard or another VPN, allow port 22 only from the VPN subnet and close it to the public internet. With a bastion host, only the bastion accepts public SSH, and you reach internal servers through it:

4. Keep OpenSSH patched through your distribution's updates.

Port 3306 is the default port for the MySQL and MariaDB client protocol. When a client connects, the server sends its initial handshake packet first, and that packet includes the server version string. Nmap reads the version from there.

MySQL 8.4 also runs X Plugin by default on port 33060, and mysqlx_bind_address defaults to *. Port 33060 sits outside the top 1,000 list, so the free scan does not check it. The Full and Deep tiers scan all 65,535 ports.

1. Bind the server to localhost. The MySQL 8.4 default for bind_address is * (all IPv4 and IPv6 interfaces), and MariaDB listens on all addresses by default. MariaDB notes that many of its packages bind to 127.0.0.1 instead, so check the effective value. Add this under the [mysqld] section of an option file:

If the application reaches the database from another server, use that server's private interface address instead of 127.0.0.1. If every client uses the local socket, skip-networking stops TCP listening entirely. MySQL reads several option files and the last value it reads wins; mysqld --verbose --help (or mariadbd --help --verbose) lists the files and their order. bind_address only changes at startup, so restart the database service, then confirm the listener:

The local address column should show 127.0.0.1:3306.

2. Firewall the port. Allow 3306 only from your application servers' private addresses, in ufw or the cloud security group:

If MySQL runs in Docker, a port published as -p 3306:3306 binds to all host addresses. Publish it as -p 127.0.0.1:3306:3306, and read Docker published ports skip UFW before relying on ufw.

Run nmap from a different network than the server, such as a second VPS or a laptop on another connection. A scan from inside the same network can bypass rules that apply only to internet traffic.

-Pn skips host discovery and -sV reports service versions. After the fix, 3306 should show closed (reachable, with nothing listening) or filtered (a firewall drops the probes). Port 22 should show filtered from any address outside your allow-list. From an allowed address, confirm that the server offers only key login:

The output should list publickey and no password or keyboard-interactive. The script starts an authentication attempt with a username, which nmap classifies as intrusive, so run it against your own server only.

Then run curl qsa.sh from the server itself. It prints the detected IP and a 15-second countdown before anything is sent, and Ctrl-C cancels. The free scan runs once per IP per 24 hours. A Full key allows one scan per hour, which covers fix-and-verify cycles. To re-scan on a schedule and get alerted when results change, use the cron monitor script.

SSH is built for network access, and many servers keep it reachable. With key-only authentication and a patched OpenSSH, password guessing has nothing to work against. A source allow-list or VPN then limits which addresses can reach the version banner at all.

A new port number changes where the service listens and leaves its exposure the same. A scan of all 65,535 ports finds it, and the common alternative 2222 is on the top 1,000 list the free scan uses.

Common causes: a later option file sets a different value, the server was never restarted after the change, or a Docker container publishes 3306 on all host addresses. Check ss -tlnp to see which process owns the listener and which address it uses.
