OAuth 2.0 in Chrome Extensions: Setup, Tokens, Pitfalls

Tanggal: 2026-11-23

Posted on Nov 23 • Originally published at extensionbooster.net

Originally published on ExtensionBooster.

Adding OAuth 2.0 to a Chrome extension trips up a lot of developers because the usual web redirect flow simply does not fit. This walkthrough covers the four setup steps, a small token helper you can drop into a Manifest V3 project, and the mistakes that cause most "it worked yesterday" auth bugs.

A typical web app sends the user to Google, then Google redirects back to an HTTPS callback URL. Extension pages are not served over HTTPS, so that pattern breaks.

Chrome solves this with the Identity API (chrome.identity). It handles:

Your extension never sees a password. It asks Chrome for an access token and sends that token to Google APIs such as Gmail, Drive, Calendar or Contacts.

Only ask for the scopes you need. Common ones cover basic profile, email, read-only contacts, Gmail, Drive, Calendar and Sheets. Swapping userinfo.email for contacts.readonly is the pattern Chrome's own OAuth tutorial uses for the People API.
