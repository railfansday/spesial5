Your agent keeps re-deciding settled questions. Give each decision a scope.

Tanggal: 2026-11-12

If your coding agent keeps reopening questions you already settled ("should we use the ORM here?", "can I change this public API?"), the problem usually isn't the model. The decision exists only in someone's head, an old chat, or a long rules file where it competes with fifty other lines.

A rules file grows by addition. Old guidance stays next to new guidance, nothing says which part of the codebase a line applies to, and the agent gets all of it on every task. It follows some lines and quietly drops others.

A decision your agent can use has five fields:

Before a task, select the Accepted decisions whose scope matches the files or task type, and put those at the top of the prompt. Ten relevant decisions beat two hundred lines of history.

At the end of a task, ask the agent: "Did you make or discover any decision the next task should know? Write it as a Proposed entry." A person reviews it once. After that it's reused, without asking again on every task.

With several people and agents, the file becomes the bottleneck.
