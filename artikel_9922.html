Introducing Replica and the Open Source Accessibility Framework, new open source projects for collaboration and inclusion.

In 2026, public contributions on GitHub soared to 2.5 billion, more than double last year’s total of 1.12 billion. It goes to show how open source remains a powerful mechanism for developers to build, share, and grow communities.

Open source is how I began my GitHub journey. I contributed to Processing Foundation by adding alt-text to images on the p5.js website. This was the first time I felt included in a software development space as someone with a background in traditional fine arts and design. It was the first time I made a fork, opened a pull request, and merged code on a repo that wasn’t mine.

Working at GitHub, you hear stories like mine everywhere. Open source is foundational to us not only as a business but also for who we are as the people who build it! We recently launched two new open source projects to share with the community: Replica, an open-source design harness, and the Open Source Accessibility Framework.

I attended John Maeda’s session with Qianqian Ye, Director of Creative Technology at Processing Foundation, at GitHub Universe titled, “Sketching with code in the age of AI.” This session talked about the power of the open source community and reminded me how important it is to our developer ecosystem. Open source accelerates innovation. It is the reason AI tooling understands different coding languages so well, how developers hacked agent harnesses to be more efficient, and why new AI companies have formed.

This moment resonated with me. Qianqian asked:

“What do you think the role open-source community plays nowadays in the age of AI?”

“I worked in the WordPress open source community, where I learned that PHP stands for people helping people. And so if anything, I’m just sort of optimistic that the open source world is the way of how we should do things in general, in society. And I’m really excited how, at GitHub, we care so deeply about open source.”

In 2025, 60% of the top growing open source projects were AI focused. At GitHub, it is no different. A few weeks ago, GitHub’s design team introduced Replica, which considers the role of designers in the era of AI and focuses on reinforcement learning. Replica started as an internal project, but it proved to be so useful that our design team shared the tool so developers and designers everywhere could also benefit.

GitHub Replica does a lot of reinforcement learning. It’s an open source design harness to enable you to do the kind of things you hope to do in prototyping playground

With Replica, anyone can create AI-generated prototypes within their design system and refine them side-by-side with GitHub Copilot. You can also publish prototypes to a Replica Hub to collaborate with teammates, receive comments, and iterate.

With reinforcement learning top of mind, the system learns what good looks like from each interaction and from the comments on the prototypes; it gets better over time. Because Replica is open source, you can hack it and adapt it to fit your teams’ products and workflows however you see fit.

Developers pushed code changes to GitHub 17.9 billion times in the last year, more than 2024 and 2025 combined. Commits across all repo types (public and private) climbed even faster to 34.3 billion, more than three times where they stood two years ago. Merged pull requests more than tripled to 1.3 billion over the same period, an average of 3.5 million a day. AI has helped us all build faster. With this volume, and more to be expected, we must keep accessibility top of mind so that the code that is being shipped is accessible to all.

As the home for all developers, we want every developer to feel welcome and to be able to contribute to the future of global software development using everything GitHub has to offer.

The Open Source Accessibility Framework, created in collaboration with external contributors from the disability and accessibility communities, launched last month. It helps make accessibility an inherent part of how projects are created. It is an accountability model with four phases so developers can turn projects and accessibility goals into public, trackable progress. A core component of this is the new ACCESSIBILITY.md file, a file now visible on repository overview pages, giving a project one durable place to explain its accessibility goals, contributor expectations, supported environments, known limitations, and process for reporting barriers. Read more about the ACCESSIBILITY.md file.

Going back to John and Qianqian’s Universe talk, John asked:

“How does an open source community keep something lasting that long? What’s the secret?”

“I think the secret is one of the most obvious ones. Community.”

The GitHub repo firstcontributions/first-contributions ranked fourth among the fastest-growing community projects in 2026 by contributors, helping developers take their first steps into open source. We hope you can join our open-source community: hack away at our new projects or start your own.
