The 8tx is the interesting one to me. The useful promise of confidential computing [google.com] is protecting a customer's running workload even from the infrastructure hosting it. That's a worthwhile feature for renting somebody else's computer. I'd want to know exactly what customers can verify before handing over their keys: which software is running, what hardware is trusted, and whether protection covers the whole CPU-to-TPU path.

The application inside that protected environment still gets to use the data, though. If it logs your documents or an agent sends them to the wrong service, encrypted memory won't save you. You can run a data leak inside a perfectly secure enclave. I like seeing this capability become part of accelerator design, but the software handling the inputs and outputs deserves just as much scrutiny as the chip.
