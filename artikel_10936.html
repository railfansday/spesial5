Prompt caching reduces LLM token costs by reusing a previously processed prompt prefix so the provider skips the need to re-tokenize and re-encode it on subsequent requests. For Node.js developers making repeated API calls with stable system instructions, few-shot examples, or long reference documents, prompt caching can deliver up to 90% cost reduction on cached tokens.

The problem is that three major providers — OpenAI, Anthropic, and Gemini — each implement prompt caching differently. Opt-in mechanisms, minimum token thresholds, TTL behavior, cache-hit indicators, and discount rates all vary. Developers must piece together incompatible documentation.

The result is a single factory function that constructs cache-optimized requests and a unified logger that verifies cache hits regardless of provider.

Prerequisites: Node.js 20+, TypeScript 5+, an API key for at least one of the three providers, and familiarity with async/await and REST API consumption.

All three providers cache from the beginning of the prompt forward — only the prefix qualifies. A "stable prefix" is any content that does not change between requests: system instructions, few-shot examples, long reference documents, or boilerplate context. Keep the prefix byte-identical across calls. Any mutation, even a whitespace change, invalidates the cache and forces a full re-processing pass.

Prompt design matters. Front-load all static content and append variable content (the user's actual question, dynamic context) at the end.

The CacheAwareRequest holds the provider-agnostic input shape. The CacheUsageReport normalizes the output so that calling code never needs to know which provider-specific field indicates a cache hit. The cachedTokenDiscountPercent reflects the provider's discount rate on cached tokens, while estimatedCostSavingsPercent approximates actual savings relative to total tokens.

OpenAI caches automatically. There is no flag to set, no resource to create. The only requirement is that the prompt prefix must be at least 1,024 tokens long. The system message is the natural place for the stable prefix.

The systemPrompt string should contain the full stable prefix. As long as it exceeds 1,024 tokens and remains identical across calls, OpenAI will cache it automatically within its TTL window.

Anthropic requires explicit opt-in via a cache_control breakpoint. The breakpoint is placed on the last content block of the stable prefix. Everything before (and including) that block is cached; everything after is processed fresh.

The cache_control: { type: "ephemeral" } annotation marks the boundary. On the first call, Anthropic reports cache_creation_input_tokens. On subsequent calls within the 5-minute TTL, it reports cache_read_input_tokens instead.

Gemini uses a two-step process. First, create a cachedContent resource via a separate API call, specifying the content and an explicit TTL. Then reference that resource in subsequent generateContent calls. The minimum prefix is 32,768 tokens.

The cached content object must be stored and reused. If the TTL expires, the resource must be recreated. In production, persist the cached content name to a database or cache store to survive process restarts; the in-memory Map used in the factory below is lost on every cold start, causing redundant cachedContent creation and additional billing.

The Gemini path stores cached content objects in a Map keyed by a SHA-256 hash of the full system prompt, avoiding both redundant cache creation on repeated calls and cache key collisions that could occur with prefix-based keys. A secondary inflight Map ensures that concurrent requests with the same prompt do not trigger duplicate cache creation calls.

OpenAI exposes cache data at response.usage.prompt_tokens_details.cached_tokens. When this value exceeds zero, the request hit the cache.

Anthropic splits caching into two fields: response.usage.cache_creation_input_tokens (populated on the first request when the provider writes the cache) and response.usage.cache_read_input_tokens (populated on subsequent requests that read from it). Check whether cache_read_input_tokens > 0 to confirm a hit.

Check response.usageMetadata.cachedContentTokenCount. If it exceeds zero, the cached content resource was used for that request.

The cachedTokenDiscountPercent reflects the provider's discount rate applied to cached tokens specifically. The estimatedCostSavingsPercent approximates the actual savings relative to total tokens in the request — for example, if only 100 of 10,000 tokens were cached at Anthropic's 90% rate, the estimated savings would be ~0.9%, not 90%. The hash comparison across requests reveals whether the prefix changed. The token estimate uses a 1.3x multiplier on word count as a rough approximation (+-30% error); production systems should use provider-specific tokenizers (e.g., tiktoken for OpenAI) for precision.

Cache misses happen for several concrete reasons. You changed the prefix between requests (even whitespace or trailing newline differences count). Your prefix falls below the provider's minimum token threshold. The TTL expired — Anthropic's 5-minute default is particularly aggressive. You switched the model parameter between requests. Or, in Gemini's case, you did not pass the cachedContent name to the generation call.

Run with npx tsc && node dist/demo.js openai. Swap the argument to anthropic or gemini to test other providers. The first request populates the cache; the second reads from it.

Realistic savings depend on reuse frequency within the TTL window. OpenAI provides a 50% discount on cached input tokens. Anthropic provides 90% on cached read tokens, though Anthropic bills cache creation calls at 25% above standard input pricing. Gemini provides 75% for Gemini 1.5 Pro (the Flash rate is not confirmed at time of writing). Anthropic reports reduced latency on cache hits, but none of the three providers publish fixed latency benchmarks for caching; consult each provider's official prompt caching documentation for current figures.

These savings only materialize when the same prefix is reused frequently within the cache's TTL. A prefix that changes on every request, or one that falls below the provider's minimum token threshold, will never trigger caching, and you will pay standard pricing.
