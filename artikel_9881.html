Every game dev I know has the same quiet dread: the bug a player finds in the first five minutes that nobody on the team ever hit.

So when Aura open-sourced Autopilot, an Apache-2.0 agent that plays your game to find bugs, I cleared an evening. The pitch is bold: about 43% more accurate and roughly 2x faster than other AI agents at real playtesting tasks.

I wanted to see it with my own eyes. Here's what I ran, what it found, and what it cost.

Autopilot is not one big model clicking around. It's four parts working together:

The clever bit is the harness. Aura's team found that giving a model raw keys ("press W", "click") plays badly, while game-specific moves play well. So instead of hand-writing those moves for each game, the coding agent writes them for you.

Then it remembers. Each project gets a memory folder with a copy of your code, notes, harness code that worked, and past reports. Later runs skip the research and start from a harness that already works.

So the "43% more accurate, ~2x faster" headline is against that unnamed competitor: 100% vs 57%, and 262s vs 508s. Against Claude Code it's 100% vs 71%, and about 1.7x faster.

That's a real result, but a small one: seven tasks, one game, one attempt each, and the vendor ran it. I'd treat it as a promising signal, not a law.

- The Start button never comes back after Game Over, so you're stuck.

- The player can walk 240px off the right edge of the screen and hide there.

- Moving diagonally is about 1.4x faster than moving straight.

I gave it the laziest prompt possible: explore the game for bugs, five minutes of play. No hints about what I'd planted.

It also found a fifth issue I hadn't planted: the hidden player moves when you hold a key on the title screen, before any game starts. That's a real bug in the demo. It flagged one more thing from code reading only (D-pad mappings that look swapped) and was honest that it hadn't checked that one in play.

No false alarms. Every claim pointed to a moment in the trace.

The run went through my Aura plan, and the report logged about $1.11 of model usage.

One surprise: I'd set the coding agent to OpenCode with Gemini, but in Aura mode the report shows Aura ran it on Claude Opus 5.5 for me. So on Aura you don't need a Claude account to get Claude doing the code-reading part. If you bring your own keys instead, you choose the model and pay that provider plus TypeSafe for Jev.

So on speed and cost, the plain LLM wins easily, and that's fair: my bugs were all visible in the code. If that's your kind of bug, a good model reading your source is hard to beat.

But the difference I felt was trust. Gemini said I could hide off-screen. Autopilot walked there and showed me x=720. Gemini mixed real bugs with design choices, and I had to sort them myself. Autopilot's list had nothing to throw away, and it found a real bug I didn't know the demo had.

And code-reading has a hard ceiling. It can't catch bugs that only show up in play, like physics, timing, level layout or a door you can clip through. That's the space Autopilot is built for, and my test didn't even reach it.

My result doesn't confirm Aura's "43% more accurate, 2x faster" claim, and it doesn't refute it. That was against other playing agents on 7 Unreal tasks. What I can say is that on a cold run, with a lazy prompt, on Linux, which isn't even officially supported, it caught everything I hid.

The repo is at github.com/ramenvr/autopilot. If you try it on your own project, tell me what it finds. I'd love to hear about a bug that only shows up in play.
