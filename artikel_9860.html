PNG to Android VectorDrawable: The Fill Rule That Eats Your Icon's Hole

Tanggal: 2026-11-10

Posted on Nov 10 • Originally published at perfectvector.com

This post was drafted with AI assistance and reviewed by the PerfectVector team.

Android Studio won't trace a PNG. Vector Asset Studio imports a Local file (SVG, PSD) and turns supported geometry into VectorDrawable XML (Android Developers). So a PNG icon takes two conversions: trace the pixels into a real SVG, then import that SVG. Each step can quietly change your icon, and the SVG in the middle is the cheapest place to catch it. Before importing, confirm the file is actually paths: an SVG can wrap a bitmap in an element, and that won't become a vector drawable.

The mapping from SVG to VectorDrawable is close but not one-to-one. Here's a 24 dp ring icon, written both ways:

viewBox becomes viewportWidth/viewportHeight (the coordinate space the paths live in), while width/height in dp is only the default display size. Change the viewport and you re-map the geometry; change the size and you just scale it. d becomes pathData with the same command syntax. The trap is the hole. Both circles in that path run in the same direction, so the hole only exists because of the even-odd fill rule. Render it with the default nonZero rule and you get a solid green disc. The VectorDrawable reference lists android:fillType as SDK 24+ with nonZero as the default, and the same API level for gradient fills. Tracers love even-odd holes, so test icons with counters on your minimum API level, not only in the Studio preview.

The importer also supports only a subset of SVG. Per the same Android page: one clipping mask per group, only centered strokes, no blend modes, no dashed paths, no filter effects (drop shadows, blurs), no text (convert it to shapes) and no pattern fills. An icon can look perfect in a browser and still lose a shadow, a mask or a label on import. Flatten those in the SVG master, keep that master, and regenerate the drawable from it rather than hand-editing two versions.

Finally, know when to stop. Android recommends limiting a vector image to 200 x 200 dp, notes that the first load of a vector drawable can cost more CPU than the equivalent raster, and says detailed art such as many launch icons works better as raster. Simple icons are the sweet spot. Photos, texture and soft shadows should stay PNG.
