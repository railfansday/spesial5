AWS App Runner alternatives: ECS Express Mode and where else to run your container

Tanggal: 2026-11-25

Posted on Nov 25 • Originally published at ownkube.io

AWS App Runner is closed to new customers, and AWS says it does not plan to add new features. Existing customers can keep using it, including creating new services, and no end-of-life date has been announced. AWS recommends Amazon ECS Express Mode as the replacement. Outside AWS, Render, Railway, Google Cloud Run, Lightsail container services and Ownkube cover the same job of running a container from a repo or an image behind an HTTPS URL.

If you already run on App Runner there is no deadline. The reason to look now is that a service with no new features tends to be the one you have to move later in a hurry, and new accounts in your organization can no longer use it.

AWS's own availability notice is short. App Runner stopped taking new customers on April 30, 2026. AWS "continues to invest in security and availability" but does "not plan to introduce new features". Accounts that already use it can still create new services.

That leaves teams in two groups. If your account already has App Runner, you can stay as long as the feature set is enough. If you are starting fresh, or a new AWS account in your organization needs the same setup, App Runner is not an option.

ECS Express Mode is the path AWS recommends. You give it a container image and two IAM roles, and it creates an ECS service on Fargate, an Application Load Balancer with TLS, health checks, autoscaling, security groups and a default URL in your account. AWS's guide says provisioning typically takes three to five minutes.

Express Mode itself is free. You pay for the Fargate tasks, the load balancer, CloudWatch logs and data transfer it creates. Services that use the same networking setup share one load balancer, so the second and third services cost less than the first.

App Runner could build straight from a GitHub repo with a managed runtime. Express Mode needs a container image in a registry. AWS's migration path for source-based services is a Dockerfile, an ECR repository, an OIDC provider and IAM role for GitHub Actions, and the amazon-ecs-deploy-express-service action. It works, and you now own a CI pipeline you did not have before.

App Runner only charged memory while a service sat idle. Express Mode keeps at least one Fargate task running behind a load balancer, and the load balancer is about $22 a month before traffic. For one small service that can cost more than the container.

AWS documents a blue/green migration that runs both services side by side and shifts traffic with weighted Route 53 records, from 10% up to 100%. A custom domain needs its ACM certificate added to the new load balancer and a host header rule before you shift.

We priced one web service with 1 vCPU and 2 GB of memory, serving traffic all day at about 40% average CPU. Prices are list prices for US East (N. Virginia) as of November 2026, and leave out egress, logs and a database.

App Runner bills the full vCPU whenever a service is handling requests, so a service that is busy all day pays for all of it. Its pricing page shows the better case: the same 1 vCPU / 2 GB service active eight hours a day is about $25.50 a month. If your traffic stops at night, App Runner's idle pricing is hard to beat, and Cloud Run's request billing is the closest match to it.

On Ownkube, an app with 2 GB of memory needs the Personal plan ($5 a month, loaded into your wallet as credit), because Pay as you go caps each app at 1 vCPU and 1 GB. Ownkube regions are Mumbai and Germany, not US East.

Pick it if the app has to stay in your AWS account: it reads from RDS in a private subnet, uses IAM roles for S3 or SQS, or sits under compliance rules that name AWS. You keep every underlying resource and can change any of them later. You also take on the image pipeline and the fixed load balancer cost. Our Fargate pricing guide has the full rate card and worked bills, including the NAT gateway trap.

Lightsail sells container nodes at a fixed monthly price, from $7 for a Nano node to $40 for a Medium with 1 vCPU and 2 GB, with HTTPS load balancing and 500 GB of transfer included. It stays inside AWS and the bill is the same every month. It does not build from a repo, and it pulls images only from public registries or Lightsail's own. See Lightsail pricing explained.

Cloud Run is the closest thing to App Runner's idle pricing. With request-based billing, an instance is billed only while it handles requests, it scales to zero, and there is a monthly free allowance. It builds from source or runs an image. Moving to it means a second cloud account, and a database in Cloud SQL or elsewhere. Google Cloud Run pricing explained has the rates and two worked bills.

Render runs web services, workers and cron jobs from a repo at flat instance prices, $25 a month for 1 CPU and 2 GB, with Postgres beside them. Flat pricing suits an app that is busy all day. See Render pricing explained.

Railway builds from a repo and bills CPU and memory on what each service actually uses, so a quiet service costs little. The bill arrives after the month. Hobby ($5) and Pro ($20) include that much usage each month. See Railway pricing explained.

Ownkube is a cloud for personal software. It builds from your GitHub or GitLab repo, with or without a Dockerfile, or runs a public image, and gives the app a *.ownkube.app URL with TLS. There is no load balancer, NAT gateway or registry to pay for separately. Managed Postgres starts at $4 a month and a Valkey cache at $2, on the same canvas as the app.

Billing is a prepaid wallet. Pay as you go starts with a $5 top-up, Personal and Team load their monthly fee as credit, and unused credit never expires. Apps sleep when idle and wake on the next request, which is the nearest thing to App Runner's idle pricing.

App Runner services usually come in two shapes, and both move the same way. A source-based service deploys from the repo it already uses, and an image-based one keeps its Dockerfile.

Copy the port and environment variables from the App Runner console first. Secrets set by bare name are prompted for with hidden input.

Most App Runner apps talk to RDS. The simplest move is to bring the database along. Add a Postgres database on the canvas and link it to the app, which injects DATABASE_URL, then restore a dump through a private tunnel:

Run the dump from a machine that can reach RDS, and the restore from a second terminal while the tunnel is open. Test on the *.ownkube.app URL, then move the domain. Custom domains come with the Personal plan (3) and Team (20), with two DNS records per host, and DNS stays at your provider. If the app reaches S3 or SQS through an IAM role, or needs other resources inside your VPC, keep it in AWS on Express Mode.

Stay if your account already has App Runner, the service is stable, and you do not need anything new from it. AWS still patches it, and there is no shutdown date. Spiky or night-quiet traffic is where App Runner's idle billing still wins, and moving to an always-on task plus load balancer can cost more. Plan the move, test Express Mode on a non-critical service, and go when there is a reason.

No end-of-life date has been announced. App Runner is closed to new customers and will get no new features, but existing customers can keep running and creating services.

Amazon ECS Express Mode. It creates a Fargate service, an Application Load Balancer, autoscaling and networking in your account from one container image and two IAM roles, and AWS publishes a migration guide with gradual DNS traffic shifting.

It can be for a single small service. Express Mode has no fee of its own, but it keeps at least one Fargate task running behind a load balancer that costs about $22 a month. Services that share a networking setup share one load balancer, so the cost per service drops as you add more.

No. It needs a container image. For a source-based App Runner service, AWS suggests building the image in GitHub Actions, pushing it to ECR and deploying with the Express Mode GitHub Action.

For an app that is busy all day, metered platforms such as Ownkube and Railway cost the least in our table. For an app that is idle most of the time, App Runner itself and Cloud Run's request billing are hard to beat.
