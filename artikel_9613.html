07 Java 调试案例讲解

Tanggal: 2026-11-11

调试（Debugging）就是查找并改正程序错误的过程。 核心是观察程序的实际执行过程，逐步缩小问题范围，找到“从哪一步开始，实际结果与预期不一致”。

以下使用 IntelliJ IDEA，Java 环境沿用课件中的 JDK 17。快捷键按课件的 Windows 键位说明；若自行修改过键位，以按钮提示为准。

红点表示断点位置，执行高亮表示程序当前停留的位置。判断某个结果为什么还没出现，先检查产生结果的语句是否已经执行。

变量区显示当前选中方法中的变量及其值。例如，停在 main 中可以查看 a、b；进入 add 后，可以查看 x、y。

表示 main 调用了 add，当前正在执行 add，main 正在等待它返回。最上方通常是当前执行的方法，下面是调用它的方法。

点击不同的方法记录，可以查看该次调用对应的变量。后面的数字是代码行号，不是调用次数。

程序暂停时，在 Debugger 中的 Evaluate expression ... or add a watch 输入区域填写表达式，按回车可查看结果。

表达式中的变量必须在当前查看的位置可用。例如选中 add 时使用 x、y，选中 main 时使用 a、b。

只有输出语句执行之后，Console 才会出现对应内容。程序停在 System.out.println(ret); 这一行时，并不表示 30 已经打印。

步过只是通常不进入方法内部逐步查看，方法本身仍然执行。 如果方法内部另有断点，也可能在内部停下来。

如果刚进入 add 就使用步出，剩余的打印和 return 仍会执行，然后回到 main 的调用位置。

步出不会取消这次调用，也不会丢掉剩余代码。 返回后界面可能仍高亮调用所在行，继续单步即可观察后续赋值和输出。

普通 F7 可能按调试器的过滤规则跳过某些 Java 类库方法，例如 System.out.println() 的内部实现。确实需要查看这些方法时，可以使用 Alt + Shift + F7。

“强制”是指绕过普通步入的过滤规则，并不意味着任何方法都一定有可供查看的源码。本章只需掌握它与普通步入的区别。

程序停在断点 A 时，按 F9（Resume Program），程序继续正常执行，命中断点 B 后暂停。此时 ret = 30，但 30 尚未打印。

例如停在断点 A 时，把光标放到 System.out.println(ret);，执行后会在这行暂停，便于查看 ret。

目标位置之前的代码仍会执行；如果途中先命中其他断点，会先在那个断点暂停。目标行也必须是本次执行能够到达的位置。

Ctrl + F2 是停止，不是可继续执行的暂停。 停止之后，要再次运行就需要重新启动。参见 IDEA 调试会话说明。

禁用适合暂时保留某个断点，删除适合不再需要的断点，屏蔽适合临时让程序不因这些断点而停下。

循环执行很多次时，普通断点会反复暂停。如果只想检查 i == 20 的情况，可以设置条件断点。

条件应是结果为 true 或 false 的表达式。这里写 i == 20，不是赋值表达式 i = 20，也不需要写 if 或分号。

调试时每一步都应带着一个检查目标：输入是否正确、哪一步计算有误、返回结果是否符合预期。 找到第一个出现偏差的位置，通常就能明显缩小错误范围。
