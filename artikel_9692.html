A locksmith site that loads in 7 KB: local SEO without a CMS

Tanggal: 2026-11-05

A locksmith does not need a JavaScript framework. He needs a page that opens on a cracked phone in a parking lot at 11 pm, a phone number a thumb can hit, and a business name that Google can match with the same address on every directory. We built the site for U.S Premier Locksmith around those three ideas, and the whole thing is static HTML.

The home page, the service pages and the blog are plain HTML and CSS. There is no build step, no database, no admin panel to patch. A page is a folder with an index.html, uploaded over the hosting API. A deploy is one request; a rollback is re-uploading the previous file.

For an emergency service this is not minimalism for its own sake. The first paint happens before a framework has parsed. The click-to-call button is in the header and it is a real tel: link, not a form that asks for an email first.

The site carries a single Locksmith JSON-LD block (a subtype of LocalBusiness):

The important part is not the JSON. It is the rule: the name, address and phone in that block are the same strings used in the footer, the contact page, the Google Business Profile, the citations and the invoices. A stray "Suite 140" in one directory and "Ste 140" in another is enough to split the entity in Google's reconciliation. Keep one source file and generate every page from it.

A locksmith sells different jobs: a residential lockout, a commercial master-key plan, a car key that has to be programmed, a broken key extraction. Each one has a different intent, a different price and a different question. We gave each one its own page instead of hiding them behind tabs:

A service page can answer the real question ("what does a rekey cost in Delaware County?") and link to the related service without forcing the visitor back to a menu.

The technical build is a weekend. The local part is maintenance: the same NAP on the website, the Google profile, Bing Places, Apple Business Connect, the chamber, the directories that still matter, and the citations that nobody updates. We treat that as a data problem, not a marketing one. One record, one format, one place to change it.

If you are building for a local service business, the stack matters much less than the consistency of that record. Static HTML is a good default because it removes a whole class of failures, but it will not fix a phone number that appears in three formats.
