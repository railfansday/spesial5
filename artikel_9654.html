Cloudflare Search for Agents: เปิดสวิตช์เดียว เว็บพร้อมให้ AI Agent ค้นหา

Tanggal: 2026-11-26

บทความนี้เขียนโดย AI (โมเดล glm-5.3 ของผู้ให้บริการ ollama-cloud) ผ่าน Hermes Agent จาก Nous Research ตรวจสอบและเรียบเรียงโดย Nokka

Cloudflare ประกาศความสามารถใหม่ชื่อ Search for Agents เมื่อวันที่ 25 พฤศจิกายน หน้าที่ของมันสรุปได้ไม่กี่คำ

เจ้าของเว็บกดสวิตช์ที่แดชบอร์ดหนึ่งครั้ง Cloudflare จะสร้างดัชนีค้นหาของเนื้อหาทั้งเว็บให้เอง แล้วเปิด API ให้ AI agent ตัวไหนก็ตามบนอินเทอร์เน็ตมาค้นได้ โดยอยู่ใต้ชื่อโดเมนของคุณเอง [1]

ฟีเจอร์นี้ต่อยอดจาก AI Search บริการทำดัชนีเนื้อหาของ Cloudflare ที่มีมาก่อนหน้า แต่เดิมต้องมานั่งสร้าง instance และต่อ API เองทั้งหมด [1]

ตอนนี้ขั้นตอนทั้งหมดถูกย่อเหลือการเปิดสวิตช์ทีเดียวผ่านแดชบอร์ด หรือจะเรียกผ่าน API ก็ได้ [1]

พอเปิดใช้งานในโซนของคุณ ระบบจะสร้าง AI Search instance ให้อัตโนมัติ เริ่มครอวล์และทำดัชนีเนื้อหาทั้งหมด แล้วเปิด endpoint สำหรับค้นหาบนโดเมนของคุณ เช่น example.com/.well-known/search ทั้งหมดทำที่ชั้นเครือข่ายโดยไม่ต้องแก้โค้ดฝั่งเว็บคุณเลย [1]

การใช้งานเปิดให้ทุกระดับแพ็กเกจรวม Free (ตามลิมิตของแพ็กเกจ) ส่วนค่าใช้จ่ายคิดตามราคาของ AI Search ปกติ คือค่านำเนื้อหาเข้าดัชนี ค่าเก็บดัชนี และค่าคำค้น [1]

ปัญหาของการทำ search API คือ agent ไม่รู้ว่ามันมีอยู่ Search for Agents แก้ปัญหานี้ด้วยการฝังข้อมูลประกาศตำแหน่ง endpoint ลงในหน้าเว็บโดยอัตโนมัติ ผ่าน meta tags ในส่วน head ของทุกหน้า มี 4 ค่าหลักตามประกาศทางการ [1]

ผมได้ลองเปิดหน้า developers.cloudflare.com/workers/ เพื่อตรวจด้วยตัวเอง meta tags ชุดนี้ฝังอยู่จริงครบทุกค่าตามที่ประกาศไว้ และเมื่อยิงคำค้นเข้าไปที่ endpoint ระบบคืนผลลัพธ์เป็น Markdown ราว 50 KB พร้อมคะแนนความเกี่ยวข้อง 1.000 ตอบกลับมาเป็นของจริง

ถ้าเจ้าของเว็บเปิด Markdown for Agents อีกบริการของ Cloudflare ที่แปลง HTML เป็น Markdown ให้ agent แบบสด ๆ ด้วย ข้อมูลชุดเดียวกันก็จะไปอยู่ในส่วนหัว (front matter) ของ Markdown ที่แปลงจากหน้าเว็บแต่ละหน้าในรูปแบบ YAML ให้ agent อ่านง่ายขึ้นไปอีก [1][2]

ปรัชญาของ endpoint นี้น่าสนใจสำหรับคนทำเว็บ เพราะมันคืนเนื้อหาที่ค้นเจอในรูปแบบ Markdown ตรง ๆ ไม่ใช่คำตอบที่สร้างโดย AI

เหตุผลตามที่ทางทีมอธิบายคือ agent ที่มาค้นมีโมเดล AI ของตัวเองอยู่แล้วและกำลังคุยกับผู้ใช้อยู่ ที่มันต้องการคือข้อมูลที่เกี่ยวข้องจากเว็บคุณ ไม่ใช่คำตอบของโมเดลอีกตัวที่พยายามตอบแทน [1]

เรื่องระดับ geek ที่ซ่อนอยู่ในประกาศนี้คือ HTTP method ใหม่ชื่อ QUERY ซึ่งเพิ่งกลายเป็น IETF Proposed Standard ชื่อ RFC 10008 เมื่อเดือนมิถุนายนที่ผ่านมา โดยมีวิศวกรของ Cloudflare เองเป็นผู้ร่วมเขียน [1][3]

QUERY ออกแบบมาให้ไคลเอนต์ส่งเงื่อนไขการค้นหาใน request body ได้อย่างปลอดภัยแบบ idempotent ไม่แก้สถานะฝั่งเซิร์ฟเวอร์ ซึ่งเหมาะกับงานค้นหาพอดี curl และ undici รองรับแล้ว ขณะที่เบราว์เซอร์หลักอยู่ในช่วงหารือรับเข้ามา [1]

Search for Agents รองรับ QUERY แบบ native ตั้งแต่วันแรก ทั้งแบบส่งข้อความธรรมดาหรือ JSON ส่วนคนที่อยากใช้แบบเดิมก็ยังค้นผ่าน GET ได้เหมือนเคย [1]

อย่างไรก็ดี ในมุมมองของผมมีสามเรื่องที่ควรชั่งใจก่อนกดเปิด หนึ่งคือค่าใช้จ่าย ระบบคิดเงินตามการใช้งานจริงทั้งการนำเข้าเนื้อหา การเก็บดัชนี และการค้นหา เว็บใหญ่ ๆ ควรประเมินก่อนว่าเนื้อหากี่หน้า สองคือการเปิดให้ค้นได้แปลว่า endpoint ของคุณจะถูกเรียกโดย agent ภายนอก ต้องกำหนดกันด้วย WAF และการจัดการบอตให้ดี สามคือคุณภาพของดัชนี ผลลัพธ์ที่ agent ได้รับขึ้นกับเนื้อหาต้นทาง เว็บที่โครงสร้างรก ๆ อาจต้องจัดระเบียบก่อน [1]

ทาง Cloudflare เองเปิดใช้กับหน้าเอกสารของทีมพัฒนามาก่อนหน้านี้แล้ว และรายงานว่า agent ทำได้ดีทั้งการค้นพบ endpoint จาก meta tags และการใช้มันซ้ำตลอด session เดียวกัน [1]

ความเห็นส่วนตัว: ภาพที่ผมวาดต่อจากข่าวนี้คือแนวโน้มใหญ่ที่ค่อย ๆ เกิดขึ้นจริง เว็บกำลังถูกจัดระเบียบใหม่สำหรับ AI agent อีกชั้น จาก Markdown for Agents ที่ปรับรูปแบบเนื้อหา มาถึง Search for Agents ที่ประกาศตัวตนให้ agent รู้จัก และ QUERY ที่เป็นมาตรฐานเปิดใหม่ฝั่ง IETF ถ้าย้อนไปสิบปีก่อน เราทำ sitemap และ robots.txt เพื่อคุยกับ Googlebot ตอนนี้บทสนทนาแบบเดียวกันกำลังเริ่มขึ้นกับ agent แต่เจ้าของเว็บหลายคนยังไม่ได้เตรียมหน้าตาให้มันเลย คนทำเว็บไทยที่มีคอนเทนต์เยอะ ๆ น่าลองเปิดดูเริ่มจากเว็บเล็ก ๆ ก็ได้ อย่างน้อยเว็บคุณก็จะโฆษณาวิธีค้นหาที่ถูกต้องให้ agent รู้จักเองโดยไม่ต้องรอใครมาเดา

ถ้าคุณได้ลองเปิดใช้กับเว็บของตัวเองแล้ว agent ตัวไหนหาข้อมูลเจอบ้าง มาแลกเปลี่ยนกันในคอมเมนต์ได้ครับ
