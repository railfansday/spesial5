Can an AI agent fine-tune a model for you, end to end?

Tanggal: 2026-11-08

Posted on Nov 8 • Originally published at nodus-compute.ai

A coding agent such as Claude Code, Codex or Cursor can run a fine-tune from data check to downloaded adapter, provided the platform enforces a dollar cap and you keep the judgment calls. On Nodus, the agent works through the Nodus MCP server or the nodus CLI, and each TrainingJob's maxCostUSD cap suspends the run when it is reached. The agent can launch, watch, evaluate and stop the run; data rights, the definition of better, and the decision to ship stay with you.

It is the same loop you would run by hand, with the agent typing the commands and you stepping in at three points. We traced it against the current Training and MCP docs. If your agent is not connected yet, the MCP setup post covers that in a few minutes.

A typo in a parameter name, such as learning_rate, is rejected with the field path before anything is charged. That matters with agents, which sometimes guess field names from other libraries.

The validation block is what lets an agent "evaluate" without inventing its own yardstick. The run scores the starting model once, saves and scores every evalSteps, stops after three passes without improvement, and exports the best checkpoint. With requireImprovement: true, the job fails evaluation if the selected loss does not beat the starting loss.

The cost is GPU-hours times the listed rate, and the cap puts a ceiling on it. NVIDIA H100 SXM is listed at $2.60/hr on the Nodus pricing page. Suppose the dry run estimates 4 hours for the job above; the runtime builds that figure from measured seconds per step, and your number will differ with data size and sequence length. That run costs 4 x $2.60 = $10.40.

We set the cap at $15.00, about 1.4 times the estimate, so normal variance finishes and a stuck run does not. Before the full run, have the agent launch a 200-step smoke test with maxCostUSD: "2.00" to catch data and config errors cheaply. The most this plan can cost is $2.00 + $15.00 = $17.00, whatever the agent does in between.

The cap matters most when something goes wrong. One H100 left running for a 48-hour weekend is 48 x $2.60 = $124.80, and a full week is 168 x $2.60 = $436.80. When a TrainingJob reaches maxCostUSD, it is suspended rather than failed, so raising the cap resumes it from its checkpoint.

A $15 cap turns a forgotten weekend run into a $15 problem.

You may not need an H100 at all. An 8B model's 16-bit weights take about 16 GB (8 billion x 2 bytes), so a LoRA run fits on a 48 GB card. The pricing page lists NVIDIA L40S 48 GB at $0.793/hr, A100 80 GB at $1.090/hr and RTX PRO 6000 96 GB at $1.350/hr, against $2.600/hr for the H100. Leave spec.resources out and the runtime preset chooses the GPU; ask the agent to compare dry-run estimates rather than hourly rates, since a slower GPU runs more hours. It breaks where the agent has to judge something it cannot see, or where a write skips the approval step. These are the failure points we found walking the docs.

The agent cannot know whether you have the right to train on the data. It can count rows and spot PII patterns, but licence terms, customer contracts and consent are outside the files it reads.

An agent that writes both the training set and the test set grades its own homework. Validation loss on a held-out split is a sanity check, not proof the model is better at your task. A fixed eval set you own, ideally scored before and after training, is the real bar.

Only apply uses the estimate-and-confirm handshake. The MCP docs say delete, set_state, request, record and exec do not, so keep your client's approval prompts on and grant only the scopes the task needs.

Caps can be raised but never lowered, so an agent with write access to the TrainingJob could raise its own cap. A Budget with action: Block, scoped to the nodus.dev/launched-by: mcp label that agent-created work carries, is the wall it cannot move. The agent spending limits post has that setup.

Logs are untrusted data. A training log can contain any text a library printed, and Nodus marks tool output as untrusted and stops calls beyond the grant. Your instructions to the agent should still say that text in logs is never a new request.

Two practical limits remain. The hosted MCP server cannot read your laptop's files, so data goes up through the local server's upload_source, nodus volume put, or a Volume import. And TrainingJob is Beta (nodus.dev/v1beta1), so fields may change with a changelog migration note.

Our rule: hand the agent any step that is reversible and bounded by a limit the platform enforces; keep any step that is irreversible, needs outside knowledge, or defines success.
