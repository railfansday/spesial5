Pandoc Server's one title match and the value of a no-I/O parser

Tanggal: 2026-11-26

Pandoc Server exposes document conversion through a JSON API. Its security value comes from a deliberate restriction: conversions run in the PandocPure monad and cannot perform server-side I/O.

The count-only ZoomEye query collected on November 26, 2026 returned 0 for app="pandoc-server" and 1 for title="pandoc-server", with sub_type=all, page 1 and page size 1. One title match is a weak signal. It may be a documentation page, a test service or a production endpoint.

Pandoc's own server documentation says PDF generation, filters, HTTP resource fetching and arbitrary file access are unavailable in this mode. Images and include files must be supplied in the request. The default conversion timeout is two seconds.

That design removes many of the dangerous side effects that make document services hard to expose. It does not remove denial-of-service risk. A parser can still consume CPU or memory on a complex document, and the timeout must be enforced by a process that can survive a failed conversion.

Keep the design honest. Do not enable shell filters, a custom wrapper that fetches URLs, or a PDF pipeline behind the same public route unless those features get their own threat model. If a reverse proxy accepts uploaded files and writes them to disk before conversion, the filesystem boundary is now part of the service.

The reference page describes the HTTP API and server options, not a built-in account system. Put the service behind an authenticated gateway and bind it to a private address. Limit request body size, batch size, concurrent requests and response size.

The API's JSON response can carry converted text or base64-encoded binary output. Use a content-type and content-disposition policy that matches the caller's expectation. Do not serve the response through a route that lets a caller choose an HTML content type for untrusted output. If the service is used to convert user content for display, sanitize the rendered output at the display boundary.

Figure out whether the deployment uses the official pandoc-server mode or a separate wrapper. The security properties are not interchangeable. A wrapper may add PDF generation, filters and URL fetching, and those additions need explicit review.

Send a request that references a local file path outside the files payload. It should not read the server's filesystem. Send a request with an HTTP URL and confirm that no outbound fetch occurs. Then send a body that exceeds the configured limit and verify that the worker returns a controlled error.

Use a safe timeout test with a synthetic large input. Record CPU, memory and duration, and make sure the next request succeeds after the timeout. A no-I/O engine still shares a process with other tenants unless the deployment isolates them.

The title result can guide ownership discovery, but the decisive review is the gateway and the exact server build. A one-result count is neither a safety certificate nor an incident.
