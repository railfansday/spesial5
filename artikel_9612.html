What Is OpenRoot? I Started an Open-Source Developer Program for Useful Projects

Tanggal: 2026-11-26

Posted on Nov 26 • Originally published at openroot.dev

I'm Kristofer Jussmann, and I started OpenRoot, an open-source developer program and builder community. The idea is simple: build something useful, host it in the open, keep direction of your own work, and have a place that will help people find it.

This post is a hub for what OpenRoot is, why I started it, how you can join or contribute, and four projects I have been shipping inside the OpenRootdev GitHub organization: Harneloop, ToolIndex, ViperMesh for Blender, and Account Switcher (acswi).

OpenRoot is a developer program and builder community for useful open-source projects. Builders apply or join the community, host work in the OpenRootdev GitHub organization, keep rights to their own code, and can receive free, best-effort promotion in the newsletter and on social channels. Reviewed project milestones can unlock points toward eligible, available rewards.

The canonical website is openroot.dev. The GitHub organization is github.com/OpenRootdev. Public program documentation lives in OpenRootdev/developer-program and in the program guide. I operate OpenRoot; general questions go to hello@openroot.dev.

The program is live. Applications are open for review, approved accounts can use the private portal, and milestone claims are open for manual review. As of 26 November 2026, the site listed 43 members in the GitHub organization and 17 open-source member projects. Those numbers will change.

I started OpenRoot because I wanted useful open-source software to have a home where the person building it keeps direction of the work, can get the project seen without paying for a feature, and can work toward reviewed rewards if real results show up â€” stars, downloads, or meaningful use, not a purchased audience.

A lot of good tools stay hard to find. Paid launch slots are one path; I wanted a free, best-effort path as well: newsletter and social promotion, the option to come back for highlights and deep dives as a project grows, and a GitHub organization where people can learn, contribute, or start a repository. Promotion is not a guarantee of reach or success. Builders still own growth, users, and maintenance.

OpenRoot is not an English-only or AI-only collection. The newsletter often covers agents, automation, and AI-powered 3D because that is work I spend time on, but the program is open to any software category that meets the published requirements.

There are two public paths, and they are not the same.

The developer program is for people creating, or exploring, a project intended for other people to use. Apply at openroot.dev/apply with your email, exact GitHub username, and a project or idea. You need a GitHub account. You do not need existing users, a finished idea, a particular language, or a public repository from day one. Applications are stored privately for manual review. Applying does not create a portal account, grant GitHub access, or guarantee a reward.

After approval, you accept an invitation to the OpenRootdev GitHub organization, create a repository there (or complete a reviewed transfer or code copy of an existing project), and can sign in to the portal. You retain rights to your own code and lead the project. This is not a work-for-hire arrangement. You get repository-level Admin for your own project, not organization-wide Admin. You can keep a repository private while you develop it; projects must be public before they can earn rewards. Send releases you would like considered for promotion to hello@openroot.dev.

Joining and unlocking rewards never require a fee. OpenRoot will not ask you to send passwords, sign-in codes, tokens, API keys, or payment details. Enter portal sign-in codes only on openroot.dev.

The community is separate. If you mainly want to learn, contribute, or meet other builders, you can join the community with GitHub, or chat on Discord without a GitHub account. Community membership does not include a portal account or reward eligibility. You can still read and fork public repositories, open pull requests, and, under current organization settings, create repositories. You can apply to the developer program later.

An AI agent can also help fill an application through the documented JSON endpoint, but the human applicant must read and accept the terms themselves. See openroot.dev/apply/agents and llms.txt.

These four are the projects I want people to find first. Every one is open source and lives under OpenRootdev.

Harneloop is an open-source, public-alpha framework for evolving an AI agent's harness â€” the instructions, tools, context, and checks around a model â€” by inspecting real task artifacts and promoting a change only when a test supports it. The model does not need to be retrained. It is on PyPI as harneloop v0.0.2 (Apache-2.0, Python 3.11+). The project home is the GitHub repository; a separate GitHub Pages site is not set up. As of 26 November 2026 it had 7 GitHub stars.

ToolIndex is a free, human-reviewed directory of apps, agent skills, MCP servers, and CLIs. Every listing explains setup, shows the licence, records what a reviewer actually checked, and links straight to the tool's source. People and agents can browse without an account, an API key, or JavaScript. You can also submit a tool through the site or by connecting an agent to https://toolindex.org/mcp. The source is OpenRootdev/toolindex (MIT). As of 26 November 2026 it had 2 GitHub stars.

ViperMesh for Blender is a free, MIT-licensed local MCP server and Blender addon that lets a compatible AI assistant work inside your Blender scene with reusable actions, a persistent connection, and built-in 3D checks. You do not need a ViperMesh account. The current documented release is v1.3.0. Source and releases are at OpenRootdev/vipermesh-blender. As of 26 November 2026 it had 3 GitHub stars.

Account Switcher, or acswi, lets you sign in to each account once and then switch command-line tools and desktop apps from a window, the tray, or a terminal. It is for people with several accounts in the same app on Windows or Linux â€” work and personal, clients, test accounts. This is an early version: GitHub CLI, Azure CLI, Discord, and Cursor have been switched on real Windows accounts; other built-in apps are covered by automated tests so far; Linux support is new and has not yet switched real Linux accounts. It is MIT licensed. As of 26 November 2026 it had 1 GitHub star.

Member-project promotion through the newsletter and socials is completely free, on a best-effort basis. It is not limited to one feature: highlights, showcases, and deep dives can return to a project as it grows. Timing and format depend on editorial fit and capacity. OpenRoot does not guarantee coverage, reach, or results. Builders still manage wider marketing.

Approved members also get free AI code review on pull requests from the Openroot-review agent; members choose how it runs in the portal.

Rewards are separate from promotion. You do not need to earn or redeem a reward to be considered for a feature. Reviewed milestones unlock points you can spend on eligible, available non-cash rewards. Points are not cash, and rewards are not guaranteed. Organic growth only: no bots or bought stars. Claims are reviewed manually; include the repository, milestone, dated evidence, and previous claims, currently via hello@openroot.dev.

The first eligible star milestone is 20 stars, which unlocks 800 points after claim approval. Later reviewed star, download, and usage milestones are published on the rewards page. Current reported offers include budget-limited AI model API allowances and a one-month DeepLearning.AI offer; availability and exact terms are confirmed before issuance. This is not an automatic maximum award.
