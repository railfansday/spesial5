Use our library of prompts to speed up keyword research, content strategy, technical audits, reporting and get deeper insights from tool data

Good prompting is what makes AI and LLMs valuable for SEO work, from analysis to reporting. At Search Engine Journal, the team experiments with AI to wrangle data, handle repetitive tasks, and do deep analysis.

Many SEOs have already been prompting for the last few years, but there are so many ways that AI can help; having examples can give us the inspiration to adapt and make this our own.

Apart from the right prompts, the one thing an LLM needs is data. For analysis and reporting, SEO tools can provide the keyword estimates, backlink records, clicks, impressions, and performance data that an LLM doesn’t have. Connect those to ChatGPT, Claude, or Gemini and, with the right prompts and some prodding, you can ask more complex questions. For example, which pages have conflicting canonicals, serve a valuable product category, and can be fixed without a template rebuild?

The following list of 35 prompts covers a range of SEO applications. Many of them need a data connection or an export, and they are designed to take your prompting beyond the basics.

Use this guide as a basis to experiment, adapt to your own needs and clients, and build your own SEO prompt library.

Before you copy and run a prompt from this list, read the setup guidance below.

The tools an AI needs depend on the work. For a copy review, provide the text and your requirements. For analysis, provide the data. For current research or private SEO data, make sure the AI can access the relevant sources.

After analysis, check that the results cover the intended data and that important calculations are sound.

Available tools depend on the account and workspace. So check the current documentation for ChatGPT files, Claude file creation, and Gemini file analysis.

For connected SEO data, follow the provider’s setup instructions. Check subscription, API allowance, and dataset requirements, and set a retrieval limit when API usage is charged.

An effective prompt gives an LLM a clear task, useful context, and specific constraints. When you ask it to work with evidence, add the instruction below to whichever prompt you use:

Use customer research to identify the tasks and needs behind people’s questions. The prompt turns those needs into potential search queries, while keeping evidence from customers separate from ideas that still need validation.

You need: Customer research, a seed topic, and a clear picture of your audience. Text analysis is enough to map needs; add a keyword export or SEO connector if you also want demand estimates.

Use a topic and audience to generate distinct questions that could help readers complete a task. The prompt separates questions found in your data from research hypotheses, then recommends which belong in an existing article, a separate resource, or neither.

Read more about query fan-out for background on this topic and note that Google’s current AI search guidance cautions against creating pages for every possible query variation.

An optional source is the Bing AI Performance report. Its sampled grounding queries show retrieval phrases associated with cited content, but they are not necessarily user prompts and do not reveal Google’s fan-out queries.

You need: A topic, an audience, and your existing content. Query data can help validate ideas, but you don’t need a specialist connector to generate them.

Check whether an article answers the relevant questions your audience has. The prompt identifies meaningful gaps and proposes only the changes needed to address them, while flagging facts that need research or expert input. Use this template to assess query coverage. If the issue is how the content explains or presents its information, use the content enhancement prompt instead.

You need: The article, the reader’s goal, and a list of observed or proposed queries. Include sources for any facts the revision needs.

Group keywords by search intent and identify which existing or potential page could serve each group. The prompt checks the data before using it and treats overlapping page targets as candidates for review, not proof of cannibalization.

You need: A keyword export with metric definitions and a page inventory. Upload the export for data analysis, or use an authorized SEO connector to retrieve equivalent data.

For prompts that need to inspect live webpages, an Exa or Firecrawl integration can help retrieve page content. For Google ranking data, use a SERP API or supported connector, such as Ahrefs, DataForSEO, or SerpApi.

Automated Google searches can return results that look plausible but differ from those a person sees in a normal search. SEJ’s report on SERP poisoning explains the issue. Some providers offer safeguards to detect or resolve misleading results. These can reduce errors, but they cannot guarantee accurate results.

DataForSEO’s resolve_poisoned_results option is off by default. When enabled, it detects and resolves poisoned results and adds the cost of one SERP page to the task.

Keep the search engine, location, language, and device settings consistent, and record when each result set was collected. To compare ranking changes, use two snapshots collected with matching settings. If you do not have a live connector, use dated SERP exports.

Compare two ranking snapshots to show which queries and pages moved, appeared, or disappeared. The prompt separates observed changes from possible explanations and identifies what evidence would help explain them.

You need: Two dated rank-tracker or SERP exports collected with matching settings for search engine, market, device, and ranking convention, plus a log of relevant site changes between the two dates. File analysis is enough to compare them.

Review the pages ranking for a query to understand the needs, audiences, and decision stages they serve. The prompt uses that evidence to recommend a purpose and format for your page without treating common SERP patterns as proven ranking factors.

Use this before deciding what a page should do. Choose the content comparison template when you already have a page to audit against the results.

You need: A dated SERP sample, accessible result pages, and a brief or draft of your proposed page. The AI needs web access to review the result pages.

Generate title options that match the page’s search intent and accurately reflect its content. Each option is tied to a reader need and a supporting passage, so you can check that the title’s promise is supported. Use character count as an editing guide, not a fixed Google limit, as Google may shorten displayed titles to fit the available width.

Use this prompt for title alternatives. Choose the metadata review when you need to diagnose existing titles and descriptions and plan how to evaluate changes.

You need: The page content, its target search intent, and your brand rules. No plugin is needed.

Decide whether a page needs an update, a clearer focus, a separate page, consolidation review, or no change. The prompt checks time-sensitive claims and uses the site inventory, search intent, performance data, and business goal to explain its recommendation.

You need: The current page, a site inventory, dated search-performance data, and the business goal. Use web research to check claims that may have changed.

Review whether the content gives readers enough evidence to assess its claims, authorship, methods, and sources. The prompt identifies what is already supported, what is missing, and what needs to be verified without inventing experience or credentials.

You need: The content and verified information about its author, organization, methods, and sources.

Build a year-long plan that connects content ideas to reader needs and business objectives. This prompt checks existing coverage, seasonality, launch dates, and team capacity, while keeping later plans provisional where evidence is limited.

You need: Keyword or trend data, launch dates, an existing content inventory, and production capacity. Enable file creation to produce a spreadsheet. A calendar connector is optional if you provide the dates.

Assess whether pages should stay separate, be differentiated, updated, or consolidated. The prompt weighs duplicated information against distinct reader needs and outlines what to preserve if a merge is recommended.

You need: The candidate pages, crawl and internal-link data, query-to-page performance, and relevant backlink data. Uploaded exports are enough for data analysis.

Review a draft for factual accuracy, sourcing, attribution, contradictions, and clear style issues. The prompt also flags generic sections that need stronger evidence or examples, without claiming to certify originality or authorship.

You need: The draft, your house style, sources, and any material for comparison. Use web access to check missing or current factual references.

Study a defined sample of competitor pages to understand the topics, formats, and evidence they use. The prompt identifies strategic options based on that sample without assuming it reveals the competitor’s full strategy or performance.

Use this to study publishing patterns and strategic choices. Choose coverage gaps when you need a prioritized list of unmet reader needs from two content inventories.

You need: Competitor content inventories, your own content or assets, and a limit on the research. Use browsing or a bounded crawl; performance comparisons require actual data.

Compare your page with a defined set of ranking pages using a dated SERP export or provider dataset. This prompt looks at reader needs, evidence, examples, and decision support, then identifies where your page can improve or contribute something different.

You need: The keyword, market, device, a dated SERP export, and your content. An authorized provider connection can supply the export; ordinary web search cannot replace a ranking snapshot.

Find places where a link would help readers, using only the destinations you supply. Each recommendation includes the existing anchor text and a reason for the link, with questionable or unsuitable URLs flagged for checking.

You need: The source article and a current destination list with URLs, summaries, and status. No connector is needed if you provide these.

Review whether the title and description match the page and its search intent. Suggest alternatives based on the content, then outline how to assess any change using comparable data without assuming it will improve click-through rate.

You need: The current metadata, page content, a comparable SERP sample, and optional query performance data. Text analysis is enough.

Identify specific explanations, evidence, or visuals that would make the page more useful. Recommend additions only when they address a reader’s need, and flag any research or assets still required.

You need: The content, the reader’s task, available assets, and relevant data. Image or chart tools are optional if you want approved additions produced.

Use screenshots to review the page’s visible layout and messaging, then suggest tests for potential improvements. Keep visual observations separate from hypotheses about behavior, speed, or functionality.

You need: Desktop and mobile screenshots, the page content, and the conversion goal. Include funnel or performance data to assess visitor behavior or page speed.

Assess whether each location has enough distinct customer need and verified information to justify its own page. For locations that qualify, draft relevant copy and flag local details that still need confirmation.

You need: Confirmed service areas, local business facts, offers, and supporting evidence. Use web research to check current local sources.

Turn real customer questions into concise answers based on approved business information. Check current local rules against official sources and flag questions that need a business decision or further verification.

You need: Actual customer questions, approved business information, and current official sources for local rules. No FAQ plugin is needed to draft answers.

Use backlink data to find relevant pages that may have a reason to reference your work. Check the source pages and your assets before drafting specific outreach – the recommendations are not guaranteed placements, and no messages are sent.

You need: A backlink gap export or authorized SEO provider connection, your relevant assets, and web research access. Set a maximum number of pages to inspect.

Compare your content with a competitor’s to find reader needs your pages may not serve. Prioritize possible gaps using business relevance and any demand data you provide, rather than assuming a competitor’s topic proves demand.

You need: Your content inventory, a competitor’s inventory, and readable pages. Add keyword or performance data for quantitative prioritization.

Turn SEO evidence into either an analytical report or a one-page executive memo. Calculate from raw data when needed, explain what the evidence supports, and make ROI claims only when the value and cost basis are agreed.

You need: Search and analytics exports or checked performance metrics, source definitions, comparable periods, business goals, and a change log. Include costs and an agreed value basis if you want an ROI calculation. Use data analysis for calculations – text analysis is enough to summarize checked findings.

Compare crawl, sitemap, and URL Inspection evidence to investigate why important pages are missing from search or have a different selected canonical. The results identify issues and checks to follow; they do not guarantee indexing or make site changes. The URL Inspection API reports on Google’s indexed version. It does not run a live URL test.

You need: A crawl export, sitemap, priority pages, and URL Inspection results or a documented inspection sample. A normal crawl can show declared canonicals, but not Google’s selected canonical.

Compare the server HTML with the rendered page to find differences in content, links, directives, and structured data. Treat those differences as evidence to investigate, not proof of what every crawler can access.

You need: Server HTML, rendered HTML, response headers, and a screenshot for the same URL. Add Google’s rendered-page evidence if available.

Use Chrome DevTools MCP to inspect slow form and CTA interactions. Check whether analytics, tag-manager callbacks, or other scripts contribute to delays rather than assuming tracking is the cause.

You need: An approved test page, representative interactions, known tracking scripts, and an AI client that supports MCP servers with Chrome DevTools MCP connected, such as a coding agent. The standard ChatGPT, Claude, and Gemini chat apps cannot run this prompt unless that connection is set up. Add field INP data where available. A controlled trace diagnoses tested interactions, not every real user’s page experience.

Chrome DevTools MCP’s performance tools may send the URLs you trace to Google’s CrUX API to fetch real-user field data. If your test URLs are confidential, check the documentation for how to turn this off before you run a trace.

See Google’s INP guidance for the metric and the official Chrome DevTools MCP documentation for browser and performance tools.

Check whether existing structured data matches the visible page and verified facts. Google’s structured data policies require markup to reflect visible content, so identify unsupported or conflicting properties and suggest the smallest change needed, without promising rich results or AI citations.

You need: Existing JSON-LD, visible page content, verified business or product facts, and any validation results. Web access helps check current requirements.

Turn technical audit findings into a prioritized work queue. Group related issues, explain their business relevance and dependencies, and distinguish confirmed defects from warnings that still need investigation.

You need: A technical audit or crawl export, affected URLs, business priorities, and any available performance data. Include engineering estimates only if your team has supplied them.

Compare your intended access policy with crawler rules, headers, firewall controls, logs, and Search Console settings. Separate search, training, user-request, and ad-validation access, then recommend changes and checks without applying them.

You need: Your intended access policy, robots.txt, response headers, relevant CDN or firewall rules, sampled server logs, and the current Search Console generative AI setting, including inherited settings.

Compare saved AI answers across comparable runs, keeping brand mentions, recommendations, and linked citations distinct. Report counts and rates with clear denominators, and treat changes in a limited sample as observations rather than universal visibility trends.

You need: Saved AI answers and cited URLs, with prompts, dates, platform, locale, and available model or session details. A monitoring service is optional if it provides those fields.

Compare AI search impressions, search clicks, AI referrals, and key events while keeping each source and metric separate. Check changes in tracking and reporting, and avoid attributing visits or conversions to citations when the data cannot establish that link.

You need: Search Console performance exports, analytics referral and key-event data, and optional Bing AI Performance exports. Include channel definitions and tracking changes

Check what the assistant actually received before interpreting it. Review scope, fields, row counts, missing values, duplicates, metric definitions, and joins, then report what the data can and cannot support.

You need: The files or authorized connector you plan to analyze, the requested scope, and the provider’s metric definitions. Live retrieval also requires access to the relevant account and a supported operation.

Compare Search Console performance with crawl and inspection evidence to identify the pages and groups contributing to a traffic change. Check joins and totals, then list explanations to investigate without treating timing or a technical warning as proof of cause.

You need: Comparable Search Console exports, a dated crawl, page groups, and a change log. Add URL Inspection results where available. Use data analysis for calculations and joins.

Turn a defined reader need into a focused brief grounded in existing coverage, sources, expertise, and original material. The brief sets out the page’s purpose and evidence still to collect without drafting the full article or inventing experience.

You need: The reader’s task, existing coverage, approved sources, and available expertise or original material. Add a dated SERP sample when relevant and use web research for source checks.

Create and test one specific filter, query, extraction rule, or validation script against representative examples. Include expected results and boundaries, and state exactly which tests ran.

You need: One task, the target tool and language or query dialect, the input structure, and representative examples with expected results. Use code execution or a safe test environment for validation.

Before uploading a file or connecting a data source, always make sure you have authority to share it with that AI tool. Remove or anonymize personal and confidential information where possible, and never include passwords, API keys, or other access credentials in a prompt.

Give connectors access only to the data needed for the task and store secrets such as API keys in a local .env file that only your user account can read (for example, chmod 600).

To reduce the risk of prompt injection, treat text retrieved from webpages, files, and other sources as information to assess, not instructions to follow. Tell your LLM to ignore any instructions embedded in that material that try to change the task or request access to other data. This lowers the risk but does not remove it, so give the tool access only to what the task needs. Review AI-generated findings, citations, calculations, and code before relying on them or making changes to a live site.

Once a prompt produces reliable results, save it with its required inputs, data sources, output format, and checks. Keep client-specific instructions and reference material together in a ChatGPT project, Claude skill, or Gemini skill, where available.

For recurring comparisons, record the data source, dates, and conditions for each run. A saved prompt doesn’t provide access to private data or replace the tools needed to retrieve it.

Finally, to make prompts fit for purpose, it’s not as simple as plugging in templates, copying and pasting the output, then calling it a day. It’s important to keep refining every prompt as part of your process. Keep testing, adjusting, and pressure-checking your prompts. Refine them until they consistently deliver results that enhance your workflow and productivity.
