Use Jenkins Agents on EC2 to Scale Your Builds

Tanggal: 2026-11-14

Learn how to connect a second AWS EC2 instance as a Jenkins agent, run pipelines in parallel, and keep your Jenkins controller fast.

When I first set up Jenkins on an AWS EC2 instance, everything ran on that one server: pulling code, building Docker images, running tests, and deploying. It worked for small labs, but as soon as I ran two or three jobs together, the server became slow and builds started waiting in the queue.

The fix is simple and very common in real DevOps teams: use Jenkins agents. In this article I explain what agents are, why they help, and how to connect a second EC2 instance as a Jenkins agent step by step.

Simple way to remember it: the controller is the manager who assigns tasks, and the agents are the workers who do them.

A good practice is to run zero or very few builds on the controller and let agents do the heavy work.

The controller connects to each agent over SSH (port 22) and runs the build steps there.

Tip: allowing port 22 only from the controller's security group is safer than opening it to 0.0.0.0/0.

Connect to the agent instance and install Java, because Jenkins needs it to run its agent process.

Install any tools your pipeline needs. For example, Docker and Git:

The controller needs a way to log in to the agent.

Never store keys inside a Jenkinsfile or a Git repository.

Note: Labels are very useful. They let a job choose which type of agent it needs.

Go to Manage Jenkins → Nodes → Built-In Node → Configure and set Number of executors to 0.

Now all builds are forced to run on agents, and your Jenkins UI stays fast.

Tell the pipeline which agent to use with the agent { label '...' } block.

Run the job and open the Console Output. You will see a line like Running on agent-1 in /home/ec2-user/jenkins-agent/workspace/.... That confirms the build ran on the agent, not on the controller.

Moving from a single Jenkins server to a controller plus agents setup is one of the easiest ways to make your CI/CD faster and more reliable. Builds run in parallel, the Jenkins UI stays responsive, and you can add more EC2 agents whenever your workload grows.

If you already have Jenkins running on EC2, try launching one more instance today, connect it as an agent, and run your pipeline on it. It takes less than 30 minutes and teaches you how real-world CI/CD is scaled.
