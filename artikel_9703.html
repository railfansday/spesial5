MCP server o CLI di DevTools per agent: come scegliere lo strumento giusto

Tanggal: 2026-11-25

Posted on Nov 25 • Originally published at frontendfacile.it

Esplorazione profonda vs esecuzione mirata: due pattern diversi, due costi diversi.

Scegliere tra un MCP server e una CLI skill basata su DevTools è soprattutto una questione di intento: stai cercando di capire cosa sta succedendo, oppure sai già cosa far fare all’agent e vuoi solo eseguirlo in modo efficiente?

Un MCP server dà all’agent accesso a un insieme ricco di tool e capacità, pensato per situazioni in cui:

È il pattern giusto quando ti trovi davanti a un problema complesso e poco definito: comportamenti intermittenti, regressioni difficili da riprodurre, flussi con tante variabili (cache, storage, network, performance, rendering, estensioni, feature flag…). In questi casi l’agent deve poter “girare intorno” al problema, interrogare lo stato del browser e correlare segnali diversi.

Questa potenza ha un costo: portare “tutta la cassetta degli attrezzi” significa spesso un overhead iniziale (anche in termini di token/contesto) perché l’agent deve conoscere e tenere a mente più strumenti, possibilità e output.

La CLI skill è l’equivalente di un set minimo e mirato: l’agent può lanciare comandi specifici del browser senza caricarsi dietro tutto l’arsenale.

Esempi tipici: ripetere una sequenza nota di verifiche, raccogliere una metrica mirata, automatizzare un controllo puntuale, eseguire un’azione singola sul browser senza dover orchestrare un’esplorazione.

In altre parole: esplorazione pesante vs esecuzione leggera.

Molti workflow reali beneficiano di un approccio a due fasi:

Un MCP server è ideale quando l’agent deve navigare l’incertezza e costruire una comprensione del problema. La CLI di DevTools brilla quando l’incertezza è già stata ridotta e serve solo un’esecuzione rapida, mirata e con meno overhead. La scelta giusta non è “qual è più potente”, ma “qual è più adatto allo stato del problema”.
