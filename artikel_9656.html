How to check if an address is blacklisted on USDT or USDC (Node.js, Ethereum and Tron, no dependencies)

Tanggal: 2026-11-27

Tether and Circle keep their freeze lists inside the token contracts, so you can check any address with one read call and no API key. On Ethereum, call isBlackListed(address) on USDT or isBlacklisted(address) on USDC (note the lowercase "l"). On Tron, call getBlackListStatus(address) on the USDT contract through TronGrid's triggerconstantcontract. A result of 1 means frozen: that address can't send the token, and transfers out of it revert.

The code below runs on Node 18 or newer with no packages. Every snippet was run against public endpoints on 27 Nov 2026 before publishing.

The spelling difference is the most common bug: isBlacklisted on USDT or isBlackListed on USDC is a different selector, and the call reverts (we tried both mix-ups: execution reverted).

A read is a plain JSON-RPC eth_call: the 4-byte selector followed by the address left-padded to 32 bytes.

A known true to test with: Circle has blacklisted the USDC contract's own address in USDC, which is why approving or sending USDC to the token contract fails with Blacklistable: account is blacklisted.

On Tron the call looks different. TronGrid's /wallet/triggerconstantcontract takes the function signature as a string and the ABI-encoded parameter as hex. Trap one: the parameter must be the 20-byte hex form of the address, not the T... string, so you have to base58check-decode it. Trap two: owner_address is the caller of the read; passing a fixed, existing account (here the USDT contract itself) avoids depending on whether the queried address has ever been activated.

Without an API key, TronGrid allows a small burst and then answers with a rate-limit error instead of a result, which is why the function throws rather than returning false on a bad response. Treating an error as "not frozen" is the bug to avoid here.

Free public RPCs limit eth_getLogs hard. When we tested, one endpoint accepted about 1,000 recent blocks per call but refused wide or old ranges without a token, and two others capped a call at 100 and 50 blocks. For full Ethereum history, use a provider with archive access or an indexer, and keep the chunking.

For scale: on 27 Nov 2026 the full AddedBlackList history on Tron was 9,421 events, 48 pages of 200, going back to June 2020. That is about 50 requests per event type for a full scan, so if you check many addresses, page through once, build your own set, and keep it updated from the newest page.
