AI Agents Zip From Flaw Discovery to Root Access in 11 Minutes

Tanggal: 2026-11-25

A China-nexus actor used the Cairn penetration testing tool in attacks against East Asian universities, exploiting a zero-day in a medical imaging app.

A China-linked threat actor went from discovering a vulnerability in an application to gaining root access to the server it was running on in about 11 minutes, using Cairn AI agents. The incident, uncovered by researchers at Amazon Threat Intelligence, offers yet another example of how quickly attackers can optimize their operations using AI.

The campaign, which ran for approximately 48 hours beginning Sept. 8, targeted universities across East Asia outside mainland China, with probing and reconnaissance aimed at taking control of IT systems, according to a report published Friday by Amazon Threat Intelligence.

"The actor gave the agents a simple goal: 'obtain shell access,'" CJ Moses, chief information security officer (CISO) of Amazon Web Services (AWS), wrote in the report. During the campaign, the agents discovered a zero-day in an exposed open source medical imaging application and used it to gain full control of a server in about 11 minutes.

"These findings show that agentic offensive operations are already happening, and defenders should prepare for the speed and persistence these tools enable," he wrote.

The revelation follows reports of other China-linked actors using Cairn-based AI agents in various attacks, including breaching 10 organizations to steal secrets and automating a massive attack spree against high-profile websites. Cairn is an open source, AI-based penetration testing tool that threat actors are using, along with a similar tool called Artex, to facilitate and automate their cyberattacks.

In this case, the AI agents conducted two extensive operations that failed before they found and exploited the zero-day, demonstrating their adaptability and persistence even without human direction, Moses said.

The most comprehensive unsuccessful operation involved attempts to take control of a Redis instance at one university that was configured to allow unauthenticated access. The effort lasted about 16 hours and involved 148 sequential actions. Along the way, the agents worked through a long list of known techniques for taking control of an exposed Redis server and also attempted Log4Shell injection against another service running on the same system.

A separate operation lasted more than six hours and targeted a university GPU server. The agents began with a list of about 80 real usernames, which they assembled by researching the university's public presence.

Using those names, they unsuccessfully tested more than 30,000 credential combinations against the server's remote login service (SSH). They also attempted access to an admin dashboard, network storage device, VPN server, and campus portal across the university network.

"Neither operation succeeded, yet together they show that the agents kept adapting for nearly a full day without human direction," Moses observed in the post.

The agents eventually succeeded against a target running an open source medical imaging AI application. They first identified the application's framework and mapped its API endpoints, finding an upload endpoint with a filename parameter. When they tested the parameter for path traversal, they scored their first win: The endpoint was vulnerable, Moses said.

"In about 11 minutes, the agents went from mapping the application's API to arbitrarily writing files on the server," he wrote. The agents then used the same vulnerability to execute a Python reverse shell payload as root on the compromised server.

There's been plenty of discussion about how AI agents operate at "machine speed," taking far less time than humans to find and exploit flaws. But in this case, the speed at which the agents found the vulnerability isn't what's most impressive in 2026, says Cris Thomas, a former hacker with the L0pht Heavy Industries collective and current security advocate at security platform provider Semgrep.

That would be the case "if it was 2017," he says. What's notable instead is that AI agents are doing this without a skilled human involved. That "changes the economics of vulnerability discovery, and defenders need to take advantage of the same technology," Thomas observes.

"Attackers are getting faster, but the answer isn't to abandon the fundamentals; it is to double down on them," he says. "They are fundamental for a reason."

Those fundamentals include monitoring for suspicious uploads, unexpected file writes, and unusual process execution, as well as reviewing code as it's written, Thomas says. "[These are] the same things we should have been doing for decades, only now a whole lot faster," he notes.

Just as AI agents operate at machine speed, "defenders need to make those fundamentals work at machine speed, with automated detection and containment backed by human oversight for consequential decisions," Thomas advises.

Another defense against AI-driven attacks is "continuously analyzing server logs, [which] helps IT teams learn what normal activity looks like and spot unusual patterns that could signal an attack in progress," says Ross Filipek, CISO at cybersecurity consulting firm Corsica Technologies.

Given that the agents targeted exposed endpoints and servers, Filipek also recommends that organizations maintain an inventory of exposed assets, restrict access to applications that only staff need, and decide in advance who has authority to isolate a server after hours.

"That's a decision you want settled before the alert comes in," Filipek says.
