XRP Ledger: Ripple Boasts Up to 23% Drop in Node Memory Use

The XRP Ledger continues to evolve with node memory usage reduced by up to 23% since the release of xrpld version 3.3.0. The release included several new amendments, as well as bug fixes and build improvements in August 2026.

RippleX developer Valentin Balaschenko shares a deep dive on how the memory consumption decline was achieved in an official blog post.

Memory growth in XRPL nodes was observed in late summer 2025. Operators reported increasing memory usage on their validators that did not decrease, including on nodes configured identically to others that were unaffected, and across different hardware platforms. The cause turned out not to be a memory leak but the memory allocator retaining memory the application had already freed, and a fix was shipped in xrpld 3.3.0.

A memory regression identified in one release during that period was addressed within weeks, but this had no observable impact for operators. The observed memory behavior existed before the regression and persisted after the fix. The underlying issue remained unresolved at the time. Operators monitoring node caches asked why memory did not come back after a cache sweep, the routine pass that clears expired entries.

Hussein Zangana (Vet), XRP Ledger Foundation director of community, mentioned this development in an X post: "Up to 23% memory savings on XRP Ledger nodes since 3.3.0. Given how expensive RAM is at the moment, this improvement is especially useful. Measured on (non/dUNL) validators as well as stock nodes, savings range from 13-23% depending on history."

The fixCleanup amendment was activated on the XRP Ledger this week on November 4, 2026, hardening and improving the XRP protocol.

The fixCleanup3_4_0 amendment is a collection of fixes for Single Asset Vaults, the Lending Protocol, Automated Market Makers, the permissioned DEX, trust lines, NFTs, MPTs, Escrow, Sponsorship, transaction signing, and permission delegation.

The fix upgrade changes VaultClawback to reject pseudo-account holders and updates VaultDeposit, VaultWithdraw, and VaultClawback to round more precisely, so vault assets can't over- or under-deliver. It changes VaultWithdraw to allow a fixed-share withdrawal to move zero assets from a fully impaired vault rather than failing. It also exempts an IOU issuer from their own global freeze on NFT offers in their own currency.
