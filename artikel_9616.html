Java 方法的使用：定义、传参、重载与递归

Tanggal: 2026-11-11

方法就是把完成某个功能的代码放在一起，起一个名字，需要时通过这个名字调用。 同一段逻辑可以反复使用，也能把复杂任务拆成几个更容易理解的小任务。

理解一个方法，先看三件事：接收什么数据（参数）、完成什么操作（方法体）、交回什么结果（返回值）。 方法也可以没有参数，或者没有返回值。

定义方法不会自动执行方法体，调用才会执行；方法结束后，会回到调用处继续执行。 同一个方法可以被多次调用，每次使用这次传入的数据重新执行。

有返回值不代表一定要用变量接收，但不使用它，就得不到这次计算的后续用途。 是否输出，取决于有没有执行打印语句。

在 main 中调用 int result = getSum(10) * 2;，先得到 55，再计算出 110。

因此，“类型匹配”不等于必须逐字相同。反过来，不能把一个 double 返回值直接赋给 int 变量。

条件表达式本身就是 true 或 false，可以直接返回。调用 System.out.println(isLeapYear(2024)); 会输出 true。

执行到 return 就会结束本次方法调用，不会继续向后执行。 对本章这些有返回值的方法，要保证每条可能正常结束的分支都能返回结果，不能只在某个 if 分支中返回，其他情况却没有返回值。

void 不表示“返回 0”，而是不返回任何值。这种方法可以执行到末尾结束，也可以使用不带值的 return; 提前结束。

选择返回值时，问自己：调用者是否还要使用计算结果？需要就返回；如果任务只是打印内容，不需要交回结果，就可以用 void。

例如，只有 getSum(int n) 时，getSum(10) 合法，而 getSum(10.9) 会编译失败，因为 double 不能直接传给 int 形参。

形参不要求与调用处的变量同名。add(a, b) 中的 a、b 与方法里的 x、y 是不同变量。

Java 始终按值传递参数。 对这里的 int 来说，复制的是整数值，x、y 不是 a、b 的别名，所以交换的是副本。

五次调用依次返回 1、2、6、24、120，相加得到 153。每次进入 factorial，都会重新创建并初始化自己的 result，不会沿用上一次的值。

这样写是把内部循环封装进方法，使任务更清楚；并没有消除内部循环，也没有自动减少运算次数。

两个整数相加、两个小数相加、三个小数相加，做的都是“相加”，没必要分别起三个名字。可以使用同一个方法名，通过参数列表区分。

本章在同一个类中判断重载：方法名相同，参数列表不同。 编译器根据调用处的参数个数和类型等信息，确定调用哪个方法。

前三种差异满足一种即可，并不是要求同时满足。把两个 int 形参换个位置，类型序列仍是 (int, int)，也不能构成重载。

返回值类型不参与重载的区分。 例如 double result = add(1, 2);，在上例中调用的仍是 add(int, int)，然后把返回的 int 转换成 double，不会因为左边是 double 就选择小数版本。

对于本章的普通方法，方法签名可以理解为“方法名 + 参数类型列表”，不包括形参名字和返回值类型。例如 add(int, int) 与 add(double, double) 的签名不同，所以可以重载。参见 Java 语言规范：方法签名。

描述符包含返回值类型，并不意味着 Java 源代码允许仅凭返回值类型重载。 这两层规则要分开理解。参见 Java 虚拟机规范：方法描述符。

一个方法在执行过程中调用自身，就是递归。 它适合把原问题转化成“规模更小、解法相同”的子问题。

调用 factor(5) 得到 120。这个版本的输入要求是 n >= 1，不能传入 0 或负数，否则 n - 1 会不断远离出口；示例还要求结果不超出 int 范围。

return n * factor(n - 1); 不是遇到 return 就立刻跳走，而是先算出它后面的表达式，再把结果返回。因此，必须等待 factor(n - 1) 完成，才能乘以本层的 n。

每一层调用都有自己的 n。进入 factor(3) 不会把上一层的 n = 4 改成 3。

每次方法调用都会建立一个栈帧，保存这次调用的参数、局部变量、执行位置等信息；这些尚未结束的调用组成调用栈。

可以把它想成一叠记录纸：调用新方法时放上一张，方法返回时取走最上面一张，继续处理下面那张。因而，最后进入的方法先返回。

在最深处，调用关系是 main → factor(4) → factor(3) → factor(2) → factor(1)。factor(1) 返回后，恢复的是 factor(2)，不会直接跳过中间几层回到 main。在 IDEA 调试时，可以通过调用栈查看这些层次。

对 1234，num / 10 得到前面的 123，num % 10 得到最后一位 4。要从左到右打印，就先处理前面的部分，再打印当前最后一位。

返回时依次打印 2、3、4。递归调用之前的代码在向下调用时执行，之后的代码在返回后执行。 如果把打印放到递归调用前，就会先打印末位，顺序变为 4、3、2、1。

这里没有显式写 return 作为出口：当 num <= 9 时，跳过递归调用，打印后方法自然结束。输入 0 也会正确打印 0。

对 1729，把问题拆成“最后一位 9 + 前面 172 的各位数字之和”。剩下一位数时，直接返回这个数。

注意两类题的区别：求 1 到 n 的和，每次用 n - 1；处理一个整数的各位数字，每次用 num / 10 去掉最后一位。

递归适合表达问题的拆分关系，但不代表一定更高效。判断时既要看能否到达出口，也要看是否反复计算相同的子问题。
