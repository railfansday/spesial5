Claude Code 401, 403, 404, 429 or 529: what does each error mean?

Tanggal: 2026-11-21

Short answer: 401 is a bad key, 403 is a valid key that isn't allowed to do this, 404 is almost always a wrong base URL, 429 means you're sending too much at once, and 529 means the upstream model is overloaded.

These five come up more than anything else when Claude Code is pointed at anything other than the default endpoint. The fixes apply to the official API, gateways and self-hosted proxies alike. The curl examples use api.niceai.dev as a sample host; replace it with your own.

Claude Code's error messages are often incomplete. One direct request tells you whose problem it is:

404 and /v1. Claude Code appends /v1/messages to whatever you set. So ANTHROPIC_BASE_URL must be https://host, not https://host/v1. OpenAI-style tools (Codex, Cursor, Cline) are the opposite: they want /v1. Count how many times /v1 appears in the failing URL.

401 vs 403. 401 means "I don't know who you are". 403 means "I know who you are, but no". Don't rotate the key on a 403; check balance and model access first.

429 vs 529. 429 is about you: too many parallel sessions, or several people sharing one key. 529 is about the upstream: press Esc, wait, or switch models. Cranking up retries for either one only makes the queue longer.

Settings didn't change anything. Restart Claude Code after editing settings.json; running sessions keep the old values. If a value is in both settings.json and your shell, the file wins. /status shows the base URL Claude Code is actually using.

Is 529 my fault? No. It's the model provider saying it's at capacity.

Why does a 404 mention /v1/v1/messages? Because /v1 is in your base URL and Claude Code added another one.

Can I see which URL Claude Code is calling? Yes, /status inside Claude Code.

The sample host in the commands is NiceAI; its docs keep a longer error-code reference at https://wiki.niceai.dev/guide/error-codes
