Common security risks in file upload and sharing platforms stem from unrestricted file intake and uncontrolled delivery. Intake risks include malware injection, active content execution (e.g., malicious scripts in SVG/HTML), and denial-of-service via resource exhaustion. Sharing risks include broken access control, permanent or guessable links, and data leakage via unstripped EXIF metadata.

A user uploads a file, and a week later someone else opens it from a link. Every step between those two moments is a place where the feature can be abused.

The common security risks in user file upload and sharing platforms fall into two groups. Upload risks are malicious files (malware, scripts hidden in SVG or HTML, files that claim to be one type and are another) and uploads large or numerous enough to exhaust your servers. Sharing risks are share links that never expire or can be guessed, missing per-file access checks, files served from your own domain, and metadata such as GPS coordinates that leaves with the file. Malicious and oversized files are stopped at intake. Access checks and link lifetime are set at delivery.

Filestack, our API for uploading, processing and delivering files, has a feature at each of those points. Security policies put a signed, expiring permission on every upload and every link. Virus Detection scans each file and stores a copy only when it’s clean. Our CDN serves files from its own domain, and image transformations make copies without location data. Together they make up our secure file upload layer, and for this post we wrote a short Node script that signs the upload policy and the share link.

The main security risks of file uploads are files that carry malware, files that run code when opened, files whose type is not what they claim, and uploads that use up storage, memory or processing time. Together they make up OWASP unrestricted file upload, the class of bug where an application accepts a file without checking what it is or where it ends up.

An infected file is stored and later downloaded by other users

An SVG or HTML file carries a script that runs when someone opens it

A file named photo.jpg holds something else

Very large files, or thousands of small ones, fill storage or stall processing

A crafted filename or path writes outside the intended folder

Malware is stopped by scanning every file before other users can download it. A virus detection API scans each file after it lands and reports whether it carries a known virus or other malware.
