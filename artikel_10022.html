Oracle reveals fix-this-ASAP-grade Java4Shell bug that allows attacks on many third-party apps

Tanggal: 2026-11-19

Attackers can crash the JVM or achieve unauthenticated RCE

The United States Cybersecurity and Infrastructure Security Agency (CISA) has urged Java users to immediately patch a high-severity flaw in the software, which attackers can use to crash the Java virtual machine or achieve unauthenticated remote code execution (RCE).

Oracle revealed the flaw in its monthly patch dump for November, which offers 655 patches, 62 of them rated critical, affecting 62 products.

Several of the flaws are rated more dangerous than the Java problem, CVE-2026-114938, which Big Red didn’t single out as worthy of special attention despite CISA’s warning.

The cyber-agency’s decision seems apt because vulnerability research and red teaming outfit Calif.io, which discovered the flaw, used its X account to claim news of the problem had leaked before public disclosure and the release of Oracle's fixes.

By then, Calif had already tested the flaw, which it named “Java4Shell,” and found applications including Keycloak, Atlassian’s Jira and Confluence, Jenkins, Apache Kafka Broker, and Elasticsearch are susceptible to RCE.

Calif, which also helped to find the PHP2Shell flaw, says the flaw is a memory-corruption vulnerability in OpenJDK's Base64 decoder.

“Base64 is a very common way of representing binary data as text. It is used in authentication protocols, to encode file uploads, and to deliver network messages,” the company explained. “To decode Base64 faster, OpenJDK uses specialized x86-64 CPU instructions to process many bytes at once.”

“We discovered a bug in that optimized machine-level code that lets malformed input overwrite neighboring memory. With careful exploitation, the corruption can reveal sensitive memory, as Heartbleed did, or lead to remote code execution. The corruption itself can be triggered by just 64 A characters followed by a single =:”

Calif applied the CVSS 4.0 bug-rating scheme and gave the flaw a critical-rated score of 9.2/10.

Infosec outfit SentinelOne’s analysis suggests the flaw “sits in the Java standard library, so exploit traffic is specific to each application.”

“Any Base64 value an application passes to java.util.Base64.Decoder can carry the payload, including HTTP Basic credentials, SAML artifacts, CSRF tokens, and MIME encoded words. In default configurations of the affected applications listed above, attackers can reach this code path prior to authentication.”

Cisco’s Talos security team pointed out that the flaw is present in OpenJDK Java versions 17.0.6 and later running on x86-64 CPUs with AVX-512 VBMI (Vector Byte Manipulation Instructions) support enabled.

“These vulnerabilities have already been tested against a suite of Java applications with success, but the attack surface is likely much larger as additional targets are tested and confirmed,” Talos advised.

Cisco’s infosec experts urged adoption of the fixed versions of Java Oracle posted on Tuesday but noted it is possible to mitigate the flaw on x86-64 machines by starting the JVM with support for AVX-512 disabled.

Akamai’s Chief Information Security Architect Jan Schaumann, writing on the Openwall project’s mailing list, expressed a little discomfort with Calif’s work.

“Calif.io set their priorities on publicity-maxxing, it seems,” he wrote, pointing out that the flaw-finding firm’s announcement of Java4Shell opens by stating “After we disclosed PHP2Shell, we realized many people didn't know what PHP was. So we decided to go after something a little more familiar: Java.”

Talos’s analysis of Java4Shell includes the interesting observation that it “has not observed in-the-wild exploitation of this vulnerability yet. However, we anticipate probing attempts may pick up soon after public disclosure.”

That second sentence perhaps supports Calif’s assertion that news of the flaw leaked before disclosure.

Java4Shell deserves a place high up on patch priority lists.

So do the six 10.10 flaws Oracle reported, three in its Access Manager product, one in the Oracle Platform Security for Java, another in the WebLogic Server, and one in Business Intelligence Enterprise Edition.

Big Red also repaired five 9.9-rated bugs, in Oracle Text, Hyperion, RDBMS, and Autovue.

The November patch dump also includes 28 flaws rated 9.8/10.

By Tenable Security’s count, 249 of the patches are for high severity bugs. Oracle’s Hyperion enterprise performance management accounts for 267 of the bugs.

Such is life in the age of AI-powered flaw finders – which Calif says burned through just $200 worth of tokens to find Java4Shell. ®
