Gemini Omni 1.2 Flash Is 30% Cheaper. Your 1.1 Calls Move to It on December 3 Anyway

Tanggal: 2026-11-06

Posted on Nov 6 • Edited on Nov 6 • AI-assisted

Google cut the price of its video model on November 5. Gemini Omni 1.2 Flash is generally available in the Gemini API, makes clips up to 15 seconds long, and costs about $0.07 per second of 720p video. Omni 1.1 Flash costs about $0.10 per second at the same resolution, according to Google's pricing page.

The line in the release notes that will reach your code is easier to miss. The Gemini API changelog says that starting December 3, 2026, requests to gemini-omni-1.1-flash automatically route to gemini-omni-1.2-flash and bill at 1.2 rates. You don't have to change anything for that to happen, which also means nothing in your deploy history will show the day the model changed.

Google is specific about the weak spots. The post says development is ongoing "to further improve things like fast sports action, rapid script changes and complex physics" (Google). Google DeepMind's model page shows a side-by-side win rate of 62% to 38% for 1.2 over 1.1 on visual consistency, which The Next Web reports as testers preferring 1.2. That is a vendor's number, and it leaves room for plenty of clips where 1.1 looked as good or better.

The model ID is gemini-omni-1.2-flash, and calls go through the Interactions API. This is the basic sample from the Omni docs, with the prompt string split to fit:

The same docs say: "When you don't set the duration, the model defaults to 10 seconds." Ask for more than 15 and you get an invalid argument error.

Longer clips, lower price per second. The price per call depends on how long you ask for.

Omni bills video as output tokens: $12.00 per 1M for 1.2, against $17.50 per 1M for 1.1 (pricing). The pricing page converts that into seconds:

The 720p clip total is Google's figure. The other three totals in the last column are my arithmetic from the page's token rates at $12 per 1M tokens.

A 4K clip costs three times a 720p clip of the same length, so the upscale step is where a video budget goes. The 30% cut is also per second. If your product moves from 10-second clips to 15-second ones, the bill per call goes up slightly: a 15-second 1.2 clip at 720p is about $1.04, and a 10-second 1.1 clip at the same resolution works out to about $1.01 by the same arithmetic at 1.1's rate.

There is no free tier for either model: the pricing page lists free-tier input and output as "Not available", and the rate limits page lists Free as "Not supported". A paid Tier 1 project gets 8 requests per minute and 40 per day. Tier 3 gets 40 per minute and 2,000 per day. Limits apply per project, not per API key. The changelog says paid-tier limits doubled with this release.

The deprecations page is plain about it: "Effective December 3, 2026, the endpoint is automatically routing API requests to gemini-omni-1.2-flash". The Omni docs add that this happens "with no code changes required." Omni 1.1 Flash was released on August 27, 2026, and the older gemini-omni-flash-preview was shut down on October 22, per the same deprecations page.

The switch is cheaper and needs no code change. What changes is the model answering your request, and Google's model page shows the two are not the same:

On December 3, the same model ID leads to a different model.

Google did the same thing with its December 1 reroute of gemini-2.5-pro to Gemini 3.8 Flash: the ID stayed fixed while the model and the price behind it changed.

The launch post names "audio cues" among the reference inputs (Google). The API docs say: "Uploading audio inputs or audio references is unsupported in the current version of the API." Audio inside a reference video is ignored. The blog covers several products at once, including Flow and the Gemini app, so the cue may live there. On the API, build against the docs.

Multi-turn editing chains turns with previous_interaction_id. The docs also say setting store=false "means the generated video won't be editable in subsequent turns." If your team turns storage off for data reasons, editing is off too, and every change becomes a new generation at full price.

A hit on the preview ID points at a model the model page lists as shut down.

Moving early also gets you the lower price now instead of on December 3.

A reroute like this is a quality change you never deployed. Catching it takes three habits: trace which model actually answered each request, keep an eval set you can re-run the week a vendor swaps the model behind an ID, and watch cost per request instead of the monthly total.
