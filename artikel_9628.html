HairDeck by hyz317 converts a single character image into stylized hair cards, assigning per-card UVs and colors and generating spring-bone chains for animation. Its image pipeline combines an Image DiT, Card VAE, Color DiT, and Chain DiT; the resulting hair meshes can be exported as GLB and attached to the supplied avatar body for VRM 0.x export. The checkpoints are released under Apache-2.0.

Use it to generate animation-ready stylized hair-card assets from a character image, including card geometry, colors, and spring-bone chains. It also supports producing multiple hair variations and exporting a hair-equipped avatar as VRM 0.x.

Local setup requires Linux, Python 3.12, and a CUDA GPU; SAM 3 and DINOv3 licences must be accepted, and their weights, along with BiRefNet-matting and Dora-VAE, are fetched separately rather than bundled. Video previews require ffmpeg. The supplied evidence does not specify supported image dimensions, GPU memory requirements, or detailed input-image constraints.

The supplied abstract compares HairDeck with CHARM, describing HairDeck's unordered-set diffusion approach versus CHARM's autoregressive sequence of control points. It reports lower Chamfer distance, lower card-orientation error, and faster runtime on CHARM's test set, but provides no numerical evaluation details here beyond 44% lower Chamfer distance, more than half the orientation error, and 33× faster runtime. These are abstract-reported results, not a general guarantee. HairDeck research.

The image-to-hair pipeline uses four released components: Image DiT generates hair-card tokens conditioned on an image; Card VAE decodes card-token latents into geometry; Color DiT predicts per-card colors conditioned on the tokens and image; Chain DiT generates spring-bone chains conditioned on card tokens. A separate Point-cloud DiT generates tokens from point clouds and is used in the point-cloud generation and evaluation path, not the described image pipeline. The image model uses DINOv3 ViT-L/16 features; the point-cloud model uses Dora-VAE 1.1 features. DiT checkpoints contain EMA weights, while the Card VAE checkpoint contains model weights. Checkpoints are safetensors, with training configuration in metadata; the supplied code is used to load them. No parameter counts, training hardware, or image-pipeline benchmark measurements are specified in the supplied model documentation.

The primary workflow takes a single character image. The separate point-cloud path takes a point cloud and is used for point-cloud generation and evaluation. Matching normalization statistics are required for both paths. The documented command accepts an image filename, an output directory, and a number of variations via --n; no further image-format or resolution constraints are specified.

The image workflow generates hair-card geometry with per-card UVs and colors, spring-bone chains, and GLB hair meshes. The documented export workflow attaches hair to the provided avatar body and creates a VRM 0.x avatar; it also creates a head-turn video for the selected seed. The README says inference writes the requested number of variations and that video previews require ffmpeg.
