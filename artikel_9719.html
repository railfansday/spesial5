Pointers and method receivers can be confusing when you are learning Go. A common question is: if Go passes arguments by value, how can a method change a struct?

The short answer is that a pointer is also a value. Passing a pointer copies the pointer, not the data it points to. The original pointer and the copy can both refer to the same value.

Consider a function that accepts a struct:

When increment is called, Go copies counter into the parameter c. The function changes that copy, so the original remains 1.

Go still passes the argument by value. This time, the value copied into c is an address. Both the caller and the function can use that address to access the same Counter.

That is why the function can change counter.Value.

A method is a function with a receiver. The receiver can be a value or a pointer.

Mutation is one reason to use a pointer receiver, but it is not the only consideration. Copying a large struct may be undesirable. Some types also should not be copied after they have been used, such as types that contain synchronization primitives.

For consistency, Go code often uses the same receiver style for a type’s methods, especially when the type has a mix of methods that read and modify state.

Receiver choice also affects whether a type satisfies an interface.

The Deposit method has a pointer receiver. A *Account has that method in its method set, so it can satisfy Depositor. A plain Account value does not have the pointer-receiver method in its method set.

Assigning account without & would not satisfy this interface because Account does not have the required method in its method set.

This is separate from the convenience of calling account.Deposit(50). Go may automatically take the address of an addressable variable for a method call, but it does not automatically convert a value into a pointer when checking interface satisfaction.

When reading a function or method, check the type of the parameter or receiver:

Go does not pass the original variable “by reference.” It passes arguments by value. With a pointer argument, the copied value is an address that can still refer to the same underlying data.

That distinction makes pointer and receiver behaviour much easier to reason about, especially when debugging unexpected mutations or interface errors.
