Microsoft mega outage: Report reveals testing gaps and emails that never arrived

Tanggal: 2026-11-25

July bug overwhelmed newer servers, prompting promises of stronger safeguards and faster recovery

Some emails never reached their recipients during November's Microsoft 365 outage, the company has confirmed in a final report that also exposes gaps in its testing and recovery procedures.

The post-incident report details how a Windows defect brought down Exchange Online and disrupted features across other Microsoft 365 services. For affected users, the cloud became someone else's unavailable computer.

A preliminary report had already blamed a July code change, combined with a failover and reduced capacity. The final report confirms those findings and sets out Microsoft's plans to improve change auditing and recovery procedures, and add spare capacity. The defect affected Microsoft's gateway server configuration, not standard Windows deployments.

The epic outage (named the "Microsoft long weekend" by some wags) kicked off on November 12 and wasn't fully resolved until November 14.

Microsoft extended its delivery retry window to 48 hours, but some delayed messages destined for consumer mailboxes inactive for more than 30 days still expired, generating non-delivery reports. The company said all queued enterprise messages were eventually delivered, with none found permanently lost.

The report is grim, particularly in how the failure ramped up as US users came online to find gateway servers toppling over. At the worst point, more than 80 percent of North American gateway servers were unresponsive.

The problem proved elusive, and it took Microsoft some time to identify the change and deploy a fix.

Microsoft has had a week to ponder what it did and did not do, and the report has some next steps to avoid a repeat of November's events. Some are obvious, and some are a little surprising.

Working to reduce the blast radius of failures is an obvious one, and actions include partitioning and isolation to ensure failures can be contained before taking down traffic globally. Recovery procedures also need improvement, along with communication and capacity to ensure there is sufficient headroom.

Microsoft's load tests used older, lower-core-count hardware, making them less likely to expose a defect that worsened on newer machines. The company now plans to test newer hardware with more realistic traffic and peak loads, and broaden its failover testing.

Microsoft also plans to improve diagnostics and change auditing so engineers can identify troublesome Windows changes faster. July's defect had been running worldwide for more than three months before it brought the gateways down. ®
