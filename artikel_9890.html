What does fc stand for? Or, how do I remember to use fc when it would be useful?

In the KornShell, the alias r (``re-do'') is preset to fc -e - (equivalent to the POSIX fc -s). This is probably an easier command name to remember than fc (``fix command''), but it does not meet the Utility Syntax Guidelines. Renaming fc to hist or redo was considered, but since this description closely matches historical KornShell practice already, such a renaming was seen as gratuitous. Users are free to create aliases whenever odd historical names such as fc, awk, cat, grep, or yacc are standardized by POSIX.

I scroll the view using keybinds that are default in many terminal emulators, namely ctrl+shift+up, ctrl+shift+down, shift+pgup, and shift+pgdown. It seems also that ghostty has the ability to configure keybinds to adjust the selection, which may be of interest to you

Since my client is a library with a terminal front end, I do not even need to retrofit this kind of accessibility, I can just write a new front end.

I think it would be a worst-case for screen readers due to excessive redraws, but as far as copy-paste goes I use tmux, which has its own internal clipboard that is accessed through its key bindings. those bindings are also changeable.

If we are talking tmux, there is also tmux capture-pane -J -p -S -999 (basically output the last 999 lines of scrollback, ignoring linewrapping; then this goes into an editor)

As the question is about input accessibility more than output accessibility, I think tmux might be in fact useful.
