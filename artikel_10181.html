Taming Typography: Building a Modern CSS Reset

Tanggal: 2026-11-14

CSS can now make choices about type that used to sit outside a reset. text-wrap: pretty can prevent a stranded word, container query units can scale a heading to the column it occupies, and text-box can trim the half-leading built into a line box. Some of these features are experimental and browser support is uneven, so they need guardrails rather than blind inclusion.

I’ve put together tidy-typography.css, which gathers the useful parts into a default stylesheet: rendering and fallback rules, fluid sizing, vertical rhythm, wrapping, hyphenation, and OpenType detail.

Use it whole, or take the declaration that solves the particular irritation in front of you. I’ll walk you through all the details in this article and give you the full code at the end.

font-synthesis: none stops a browser from inventing bold or italic when the family lacks that face. The smoothing and text-rendering declarations are rendering hints, mainly for WebKit; results still vary by platform.

text-size-adjust disables mobile font inflation that can make a deliberately sized layout jump on rotation. font-size-adjust: from-font uses font metrics to reduce the apparent size change while a fallback swaps for a webfont.

(As with other snippets in this article, this ⁠:root block is a partial excerpt the final stylesheet combines it with additional custom properties defined later on.)

Viewport-based fluid type does not know how wide its element is. A heading in a narrow sidebar can therefore scale as though it fills the viewport.

container-type: inline-size makes the wrapper a container query, so its children can use cqi: a unit based on the container rather than the viewport. Replacing vw in clamp() lets the same heading scale appropriately in an article column or a 300px sidebar without component-specific media queries.

line-height includes space above the cap-height and below the baseline: half-leading. It becomes obvious when text must align tightly with another element. text-box-trim removes it, while text-box-edge measures from capital-letter caps to the alphabetic baseline. This is a metrics-aware alternative to font-specific negative-margin nudges.

Selectors Level 5 proposes :heading, matching h1 to h6 and [role="heading"]. It has not landed in browsers, so keep it behind an @supports selector() check.

Default heading wrapping can leave one short final line. text-wrap: balance distributes text across its lines and works best for blocks of up to about six lines. For paragraphs, text-wrap: pretty avoids a stranded final word without balancing the whole block. Both replace JavaScript orphan fixers. Editable text needs text-wrap: stable, which prevents each new word from reshuffling the paragraph.

hyphens: auto relies on the browser’s language dictionaries, so the document needs a correct lang attribute (for example ). Without one the browser has no dictionary to use and won’t be able to hyphenate text. Even with the correct lang, the defaults can leave tiny word fragments or several hyphenated lines in a row.

hyphenate-limit-chars controls the smallest breakable word and fragments; hyphenate-limit-lines prevents a ladder effect. hyphenate-limit-zone makes breaks less frequent, while hyphenate-limit-last protects the final word. Safari needs the prefixed equivalents, so declare both sets together.

Set code, variables, and headings to hyphens: manual: a broken code word can change meaning, and a hyphenated heading usually reads as an error.

Punctuation marks don’t carry the same visual weight as letters, so a quotation mark sitting at the start of a line can look slightly indented against the text below it. hanging-punctuation lets specified punctuation sit fractionally outside the text block’s edge.

The first value handles opening punctuation, and last handles closing punctuation at the end of a block, while allow-end lets punctuation hang past the right edge rather than force-wrapping. The result is a text block whose edges read as genuinely flush.

Underlines have a related problem. Browsers apply flat, one-size-fits-all thickness and position regardless of the font’s actual weight.

text-decoration-thickness: from-font reads the thickness the font’s designer intended. text-underline-offset gives descenders room to breathe, and text-decoration-skip-ink: auto interrupts the underline wherever a descender crosses it rather than drawing straight through the letter.

Variable fonts often include an optical size axis, or opsz. It lets a typeface use thinner strokes at large display sizes and thicker, more legible strokes when set small.

font-optical-sizing: auto lets the font make that adjustment based on its actual rendered size. The @supports block covers the older font-variation-settings syntax some browsers still need, while font-variant-ligatures and font-kerning enable the font’s own ligatures and kerning pairs.

Light text on a dark background genuinely reads heavier than the same weight on a light background. Where a font ships a GRAD, or grade, axis, the dark mode block dials that perceived weight down without changing glyph shape or width the way an actual weight change would. Fonts without a GRAD axis safely ignore the setting.

Mixing a monospace font into running prose often exposes a mismatched x-height at the same declared font-size. The size-adjust keyword, set once at the @font-face level, scales that font’s rendered output specifically, leaving the actual font-size value untouched.

Numbers in a table need identical widths so they stack into a clean column on the screen. Conversely, numbers in flowing text don’t need the same treatment and should sit naturally alongside the surrounding words.

The tabular-nums and lining-nums keywords give table digits a fixed width and full cap height. oldstyle-nums and proportional-nums let digits sit alongside lowercase letters without sticking up and disrupting the sentence’s texture.

font-variant-emoji makes the choice between full-colour and monochrome emoji explicit. Without it, the browser or platform gets to choose a fallback, and the result can vary more than you expect. Apply .emoji-color or .emoji-mono to containers where you want to enforce that choice, rather than setting it globally on the body.

Quote style and character order differ by language and region. English nests single quotes inside double quotes, British English reverses that convention, and French uses guillemets with a thin space.

The quotes property declares the order for each language through :lang(). The native q element then inserts the right pair through open-quote and close-quote. The same markup can render correctly in each locale without hardcoding characters into the content.

Wrapping the rules in :where() keeps them at zero specificity, so a project can override the quote style with one plain class.

Default sub and sup styling is synthesized. The browser just shrinks the text and shifts the baseline, rather than using glyphs actually designed for that position.

font-variant-position switches to the font’s own purpose-built sub and superscript glyphs where they exist, resetting vertical-align, font-size, and line-height so they don’t fight against the real glyph’s intended size and position. Most typefaces only include proper numerals rather than letters, so check the specific font before applying this broadly.

:where() always resolves to zero specificity, which is useful for a reset. Every rule here is an opinionated default, and wrapping it in :where() lets a project override a property with a plain class.

:is() solves a different problem: repetition. The heading selector list appears several times in a typographic stylesheet, and grouping it avoids the risk of forgetting a level.

Unlike :where(), :is() carries the specificity of its most specific argument.

Here’s the complete reset, combining the stable layers. Unsupported declarations are ignored by the browser, so the stylesheet can be adopted gradually.

Much of this CSS removes work that used to leak into other parts of a build. text-wrap can take over orphan handling from JavaScript, container query units keep a component’s type scale tied to its own width, and text-box-trim avoids the negative margins once used to compensate for leading. quotes, font-variant-position, and font-optical-sizing hand several smaller details back to the language and the font instead of a collection of one-off fixes.

Browser support will continue to change, especially for text-wrap and text-box-trim. Unsupported declarations are ignored, but that only helps when the unenhanced typography is acceptable in its own right.

Some of these rules are still too new for a baseline reset. A news article, a marketing page, and an editable product interface do not ask the same things of their text; the set that belongs in yours depends on the font, the content, and the browsers you still need to support.
