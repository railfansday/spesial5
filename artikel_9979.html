InferNode gives Bell Labs' Inferno OS a 64-bit second wind

Tanggal: 2026-11-27

Plan 9's successor finds a new role containing AI agents, though its developer says those features are optional

InferNode brings a modernized, 64-bit edition of Inferno, the distributed operating system that followed Plan 9 from Bell Labs.

For us, the strapline of the InferNode project distracts from the interesting part. It describes the project as a "Secure Runtime for AI Agents," but we think it's something far more interesting than another LLM tool.

Fair warning: this vulture has no interest whatsoever in AI agents, and we are not even going to look at this planned use of InferNode. We're interested in the OS, and here, its GitHub repository spells out the part that caught our attention: "a 64-bit Inferno® OS."

That grabbed us because Inferno is a very interesting OS, although it doesn't get much attention – for example, the official Inferno GitHub repository shows little activity in the last few years.

Inferno is the successor to Plan 9, which we've written and talked about before, including recent releases of its community continuation, 9front.

Plan 9 is what the team who invented Unix did next. Plan 9 is a very minimalist, natively clustered Unix: machines can freely mount one another's filesystems, display windows on one another, and start processes on one another. Plan 9 turns a network of machines running this Unix-like OS into a single machine. So, for instance, if you were working on a laptop with limited storage and compute power, you could compile a large complex project on a faster machine elsewhere on the network, using project files located on a third machine, while watching the process in your terminal on your screen, with no messing about with SSH sessions.

Plan 9 and 9front programs are compiled into architecture-specific native binaries. Different processor families can still work together across the network, but the same executable won't run unchanged on both an x86-64 laptop and an Arm64 server.

Inferno takes a different approach. It's contemporaneous with the far less ambitious Java. On Inferno, languages compile code for a VM called Dis, which is part of the kernel. This means that Inferno binaries execute directly on anything that the Inferno kernel runs on. The OS kernel is built to run bare-metal, or as a process on various other OSes, without needing a separate hardware virtual machine or hypervisor.

A single binary can run on all supported CPU architectures. Inferno applications are normally written in the Limbo programming language, whose documentation was written by Unix co-creator Dennis Ritchie. Limbo is one of the languages that influenced Go, but Inferno lets compilers for other languages target Dis as well. The binaries run anywhere. Inferno on Arm, or x86, or RISC-V, or running in a Windows or Linux or macOS process, your program just runs.

We've been trying to contact Vita Nuova, the company that maintains Inferno, for some years without success. Development appears to have slowed considerably. Moving the runtime to 64-bit also raises compatibility questions: some forks change Dis's word size and cannot run existing 32-bit bytecode unchanged.

We're aware of several efforts to build 64-bit versions of Inferno. Caerwyn Jones's Inferno64 is one of the more visible, and the GitHub repository (and indeed his X account) show considerable activity. However, Inferno64's Dis is not compatible with 32-bit Dis code. Another fork is Dinsmoor's Inferno64, which also shows recent activity, albeit with the assistance of the Claude LLM. Others include the long-quiescent Purgatorio and 9ferno, both inactive for years, plus Scott Guyon's more active fork. Dropping the compatibility goal altogether, Node9 replaces Limbo with Lua and Dis with LuaJIT.

There are more forks and variants than we've gone into here. Given that there have been quite a few efforts, and most haven't delivered final ready-to-use products yet, we were surprised when InferNode was suddenly announced on the Inferno-OS mailing list last week.

Developer Peter Finn said: "An experimental runtime for containing generative AI agents was the original motivation, but most of the work since has been on the OS itself, and the AI parts are ordinary file servers. For example, llmsrv at /mnt/llm and speech9p are started from the login profile, and if you delete those lines they're simply not there. There's also non-generative AI additions on object detection served as files at /mnt/vision, on the CPU or a GPU host, and voice calls between devices done by mounting each other's audio files over 9P. There's a GUI layer intended to facilitate hands-free AI agent use, but it too is optional."

He also said that InferNode's development was largely independent of the existing efforts, partly because the primary target was Arm64, not x86-64. Its 64-bit Dis runtime is incompatible with the 32-bit original: "The opcodes, file format and magic number are unchanged, but the word size isn't, so frame sizes, offsets and pointer maps all differ. Limbo source recompiles without edits. A 32-bit .dis is currently rejected at load time."

InferNode doesn't implement 9front's DP9IK authentication protocol, so it cannot connect to servers requiring that authentication. Dr Finn told us: "DP9IK is not quantum-safe. That's the reason. InferNode's current crypto policy is strict CNSA."

InferNode also includes some slightly unexpected components, related to its intended use for testing LLM agents – such as a wallet for the Ethereum cryptocurrency, which Finn said was "mainly to support agent payments."

The first release of Inferno was in 1996, the year after Java and the JVM were launched. Inferno is a much more ambitious project, but its core function – the ability to run identical binaries on multiple platforms, without recompilation – was close enough that they ended up competing in the market, and Java won. It was a pleasant surprise to see a modernized version of Inferno arrive this year, 30 years on.

Finn told us: "About a year ago I saw the potential for a 'break-out' moment for this tech as a runtime for containing AI agents. The flood of cybersecurity risks we would face on account of adversarial AI agents required new systems with small footprints and minimal attack surfaces. Inferno was a perfect candidate and it was an opportunity to show the world how visionary Plan 9's ideas were and how well they mapped on to pressing contemporary security issues."

"If InferNode succeeds, it is an opportunity for Plan 9's ideas to migrate out of hobby-land and really make an impact – as they deservedly should."

He has a point. On a related note, this vulture discussed the possibility of rebuilding the world's IT systems from scratch on last week's Kettle podcast. Perhaps the hour for tools like this really has come round at last. ®
