The brief is the most expensive document in software

Tanggal: 2026-11-19

Posted on Nov 18 • Originally published at tenlux.tech

The most expensive document in software is the one nobody wrote: the brief.

A brief is a short description of the task and the context. Not a spec, not a prototype — just enough to explain what is needed and why. It takes an evening, and it saves weeks, because every misunderstanding it prevents would otherwise surface after the first demo.

Skipping the spec is how "we agreed verbally" turns into an argument about the invoice.

Bad: "the app should let the manager approve photos". Good: "the manager opens the request, sees 8 photos with labels, approves or rejects with a comment; a rejected set returns to the driver with the comment visible; the driver sees the list of rejected angles".

The difference is not detail for its own sake — it is that the second version can be estimated, built and tested.
