You are a junior engineer on your first backend project, and you need to test a branch on the team's shared staging server. You SSH into the server, pull your code, and run the start command. However, the terminal returns an error message: Error: listen EADDRINUSE: address already in use :::8080. This error indicates that another process is already using port 8080, which is the port your application is trying to use.

You try changing the port, but the proxy routing traffic to your application expects it to be running on port 8080. You assume the previous version of the application is still running, but you do not know how to find it. You try running your new application as the superuser to force it through, and it starts, but immediately crashes with Permission denied: /var/log/staging-api/error.log. This error message suggests that your application does not have the necessary permissions to write to the log file.

You have wasted an hour trying to troubleshoot the issue, and you are still no closer to testing your branch. You need to understand how to manage different versions of your application, how to find and stop running processes, and how to handle permissions issues.

To follow along with this chapter, you need to have Git installed on your machine, and you should have a basic understanding of Linux commands, such as navigating the file system and running processes. You should also have a Git repository set up for your project. You can verify that Git is installed by running the command git --version in your terminal. The output should display the version of Git installed on your machine, such as git version 2.37.1.

In Git, a branch is a separate line of development in your repository. You can think of it as a separate copy of your codebase that you can work on independently of the main codebase. When you create a new branch, Git creates a new pointer to the current commit, and any changes you make will be committed to that branch.

To create a new branch, you can use the command git branch . For example, to create a new branch called feature/new-feature, you would run the command git branch feature/new-feature. You can then switch to that branch using the command git checkout feature/new-feature.

Git tags are used to mark specific points in your repository's history. They are often used to mark releases or milestones. To create a new tag, you can use the command git tag . For example, to create a new tag called v1.0, you would run the command git tag v1.0.

Git history refers to the record of all changes made to your repository over time. You can view the history of your repository using the command git log. This will display a list of all commits made to your repository, including the commit message, author, and date.
