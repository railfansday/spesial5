Google Cloud Run pricing explained: request vs instance billing in 2026

Tanggal: 2026-11-25

Posted on Nov 25 • Originally published at ownkube.io

Google Cloud Run bills a container by the CPU and memory it holds, per second, rounded up to the nearest 100 milliseconds. With request-based billing, the default, you pay $0.000024 per vCPU-second and $0.0000025 per GiB-second while a request is in flight, plus $0.40 per million requests. An app that scales to zero costs nothing while idle.

Instance-based billing charges for the whole life of each instance at lower rates, $0.000018 per vCPU-second and $0.000002 per GiB-second. That suits an app that runs all day.

The free tier covers a small app's compute. The database usually doesn't fit in it, so a Cloud Run app with Postgres starts at about $9 a month.

The rates below are Cloud Run's Tier 1 prices (us-central1 and other Tier 1 regions) from Google's pricing page as of 2026-11-25.

You pay for an instance while it starts, while it shuts down, and while at least one request is in progress. Between requests it bills nothing, unless you keep it warm as a minimum instance. Several requests can share one instance's CPU and memory when you set concurrency above one, so a busy service doesn't pay per request for compute.

You pay for each instance from start to shutdown, whether or not it is handling a request. Background threads, WebSocket connections and work after the response are all covered. It is the setting for apps that do work outside a request.

A minimum instance stays warm to avoid cold starts. On request-based billing, its idle time bills at $0.0000025 per vCPU-second and per GiB-second, about a tenth of the active CPU rate. Idle instances that aren't minimum instances aren't charged.

Tier 2 regions bill higher rates. They include Frankfurt, London, Zurich, Singapore, Sydney, Seoul and Warsaw. Mumbai, Belgium, the Netherlands, Paris and most US regions are Tier 1.

Outbound internet traffic bills at Google Cloud's Premium Tier networking rates. Cloud Run's free tier includes 1 GiB a month of transfer within North America.

The database is a separate product with its own bill. In us-central1, as of 2026-11-25:

SSD storage is about $0.17 per GiB a month. High availability doubles the instance price. The two shared-core types aren't covered by the Cloud SQL SLA.

Cloud Run jobs bill at the instance-based rate for the whole life of each instance, with a minimum of 1 minute. A nightly job that runs for 5 minutes on 1 vCPU and 1 GiB costs well under a dollar a month and usually fits the free tier.

New Google Cloud customers get $300 of free credit to try products, including Cloud Run.

Both examples use Tier 1 rates and assume the free tier isn't used by anything else on the billing account.

A 1 vCPU, 512 MiB service on request-based billing, busy for 40 hours a month and serving 500,000 requests. Postgres runs on db-f1-micro with 10 GiB of SSD.

Cloud Run itself is free here. The first request after a quiet spell waits for a cold start, unless you pay for a minimum instance.

One 1 vCPU, 1 GiB instance on instance-based billing, running all month (730 hours, or 2,628,000 seconds). Postgres runs on db-g1-small with 20 GiB of SSD.

Outbound traffic past the free GiB adds to both bills. In a Tier 2 region such as Frankfurt or London, the compute lines bill higher.

Cloud Run is very cheap for spiky or quiet traffic. A service that handles a few hours of requests a month can run for free, scale out under load and go back to zero. Very few hosts beat that for an API that is idle most of the day.

It also fits teams already on Google Cloud. IAM, Secret Manager, Pub/Sub and Cloud SQL sit next to the service, and committed use discounts cut the instance rates further for a steady load.

The bill grows in three places: instances that must stay on all day, Cloud SQL once you leave the shared-core types, and outbound traffic. Each of those is a separate meter or product to watch.

Ownkube runs in two regions, Germany and Mumbai. Cloud Run runs in dozens, so an app that needs to sit close to users on several continents fits Cloud Run better. Ownkube also has no equivalent of Google Cloud's IAM, Pub/Sub or BigQuery next to the app.

Billing works the other way round too. Ownkube is a prepaid wallet: Personal is $5 a month and Team is $20, each loads the same amount as credit, and credit never expires. When it runs out, apps pause with their data kept. A Google Cloud bill is postpaid, so set a budget alert before a launch.

Within the free tier, yes. Each month on request-based billing, the first 180,000 vCPU-seconds, 360,000 GiB-seconds and 2 million requests are free. A small service that scales to zero often stays inside it. A database on Cloud SQL is billed separately.

It depends on how long instances run. A service that is busy for 40 hours a month can cost $0. One always-on instance with 1 vCPU and 1 GiB costs about $47 a month on instance-based billing after the free tier, before a database.
