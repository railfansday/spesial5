Your 1M-Context Model Is Wasted on Sloppy Instruc

Tanggal: 2026-11-15

Posted on Nov 15 • Originally published at honeykiran.substack.com

I know the feeling. You watched the Opus 5.5 launch notes drop on September 22, saw "1M context, $4/$20, always-on thinking," and your first thought was the same one everyone had: finally, I can just point it at the whole repo.

(Illustrative scenario, not a real incident: imagine a nightly job that dumps an entire service's source tree into one prompt and asks for "a full review." It worked — technically. It also cost more than the compute it was reviewing.)

That's the trap of this release. The context window stopped being the bottleneck, and nobody updated the playbook. So here's the new playbook.

Forget the benchmark table for a minute. For anyone running agents, the release notes reduce to this:

Input / output | $4 / $20 per MTok | $5 / $25 per MTok

Thinking | Adaptive, always on | Configurable

Two rows do all the work. Cache reads fell 60% — the deepest cache discount on any current Anthropic model. And thinking can no longer be turned off: a request that sets thinking to disabled now returns a 400 error.

The fix: Stop pricing your runs per token. Anthropic's own framing for this release is cost per completed task — their launch material cites one customer going from 38 prompts over four days to 11 prompts in three hours on the same workload. The token price fell 20%; the task price is where the real number lives.

For two years, the failure mode of long agent runs was context starvation: the run died because the window filled up. Every workaround you've built — summarizers, compaction hacks, "only send the diff" — was a response to that.

Opus 5.5 ends that era and starts a dumber one: the run now fails because the instructions were mushy, and it fails expensively, inside a million-token window, while thinking the whole time. A vague directive at 8K tokens is a shrug. A vague directive at 800K tokens is a very confident, very detailed wrong answer that you paid output-token rates to receive — because thinking tokens are billed as output even when the thinking text never comes back.

A million tokens of context won't save instructions that were vague at 8K. It just makes the confusion more expensive.

The fix: Treat your system prompt like infrastructure. Version it, review it, and cache it — cache reads are $0.20/MTok against $4 re-sends, so a stable instruction block is nearly free to reuse across a whole session.

Before: one giant context, uncapped cost. After: budgeted lanes, bounded spend.

Adaptive thinking is always on, and the effort knob (low / medium / high / xhigh / max, default medium) is now the single highest-leverage setting in your stack. Three things to know:

Effort compounds. At a given effort level, Opus 5.5 thinks more per turn than Opus 5 did — most visibly at xhigh and max. Anthropic's guidance is blunt: don't touch xhigh/max without a measured gain.

The default changed under you. Opus 5 defaulted to high effort; Opus 5.5 defaults to medium. Any script you point at claude-opus-5-5 without an explicit effort parameter silently runs one level lower than it did the day before.

Cheap work doesn't need a thinker. Classification, labeling, bulk triage — every Opus 5.5 call carries a thinking cost. Route that work to Haiku or Sonnet and keep Opus 5.5 for multi-step work where an early mistake spoils later steps.

The fix: Pin effort explicitly in every call, and start at medium. Raise it only when you can measure the improvement in task completion — not vibes, completions.

The old pattern was one giant agent with one giant context. The new pattern is a planner that stays lean and workers that stay cheap. Give each lane its own model, its own effort level, and — this is the part most teams skip — its own dollar budget.

The new shape: a lean planner, cheap workers, and a guardrail with a dollar breaker.

Why this shape works: the planner holds the plan in cached context (cheap to re-read), workers execute narrow tasks with bounded output (cheap to run), and the budget is a circuit breaker. An agent that can't exceed $4 on a task is an agent you can run on a cron without a finance meeting.

The fix: Budget per lane, not per run. If you can't say what the planner is allowed to spend versus the workers, you don't have a budget — you have a hope.

Before any long-running job goes on a schedule, walk this checklist:

xhigh/max need a reason — a benchmarked task-completion gain, written down.

System prompt is cached — stable instructions, 1-hour TTL where the platform supports it.

Cheap lanes use cheap models — triage, classification, and bulk labeling never touch Opus.

Thinking-heavy output is bounded — max_output_tokens set; 128K is a ceiling, not a target.

Budget has a breaker — per-lane dollar cap with kill or pause on exceed.

Offline work uses Batch — 50% off ($2/$10) for anything that doesn't need an answer now.

Fast mode is opt-in — $8/$40 is for latency-sensitive paths only, never the default.

The fix: Make the checklist a pre-merge gate for agent configs, the same way you'd gate a Terraform plan. Configs are code; review them like it.

The whole playbook on one card - save it for your next agent config review.

If you're moving existing automation from Opus 5 to 5.5, the price drop is the easy part. The behavior changes are where the 3 AM pages live:

Thinking can't be disabled. Any request with thinking disabled returns a 400. If your harness toggled thinking off for cheap passes, that path is now an error, not a savings.

Effort default dropped. Covered above, but it bears repeating: unpinned scripts run at medium now, not high. Audit every call site.

Preserved thinking on new accounts. Newer API accounts must return prior thinking blocks unmodified. If your retry logic strips or rewrites them, retries will fail.

The fix: Run your migration as a bakeoff, not a version bump. Same tasks, both models, scored on cost per completed task — and keep Opus 5 in place until 5.5 wins that comparison, not the benchmark table.

Opus 5.5 didn't just get cheaper and bigger — it moved the bottleneck. Context starvation is over; instruction quality and token budgets are the new constraint. The teams that win this release won't be the ones with the biggest prompts. They'll be the ones with versioned instructions, pinned effort levels, decomposed lanes, and a dollar budget with a circuit breaker.

Start this week with one audit: list every agent call in your stack, write down its effort level and its budget. The ones with neither are your most expensive lines of config.
