Learning DSA in Public, Week 3: Finishing Two Pointers and Starting Sliding Window

Tanggal: 2026-11-20

Last week I finished Arrays & Hashing and started Two Pointers.

This week I completed Two Pointers with Container With Most Water, then moved into Sliding Window with Best Time to Buy and Sell Stock and Longest Substring Without Repeating Characters.

Same rule as always: if I can't explain it with an everyday picture, I don't understand it yet.

The big idea this week: don't re-check everything from scratch. Keep a moving frame, and only adjust it when a rule forces you to.

The problem: Pick two vertical lines that, together with the ground, hold the most water.

Picture it: Two fences hold water, but the water can only rise as high as the shorter one. Start with the fences furthest apart. Then move the shorter fence inward, since that's the only move that could find a taller wall to make up for the lost width.

Slow vs. fast: Trying every pair is O(n²). Two pointers moving inward: O(n) time, O(1) space.

What I learnt the hard way: I hit almost every kind of small bug on this one: a wrong variable name (height vs heights), a stray comma, comparing the wrong values, and return res indented inside the loop so it returned after the first round. The logic was right; the details weren't. Now I check names and indentation before I run anything.

The problem: Given daily prices, buy once and sell later for the biggest profit. If no profit is possible, return 0.

Picture it: Walk through the week with a sticky note showing the cheapest price you've seen so far. Each day, ask: "If I sold today, how much would I make?"

Slow vs. fast: Checking every buy/sell pair is O(n²). One pass with a running minimum: O(n) time, O(1) space.

The problem: Find the length of the longest stretch of a string with no repeated characters.

Picture it: A window sliding across the string. The right edge keeps adding new characters. When a repeat shows up, the left edge moves forward, dropping characters, until the repeat is gone.

Slow vs. fast: Checking every substring is O(n²) or worse. The window is O(n), because each character enters and leaves at most once.

What I learnt the hard way: I started left at 1 instead of 0, which skipped the first character and made every window one short. Python counts from 0, and that matters from the very first line.

If you're learning DSA too, which part of sliding window trips you up more: moving the left edge, or updating the answer?
