Deploying a Flask API to Kubernetes with KIND and Argo CD

Tanggal: 2026-11-15

After containerizing the Task Management API and working on its CI/CD pipeline, the next stage of my DevOps capstone was learning how to deploy and manage the application using Kubernetes.

For this stage, I used KIND to create a local node Kubernetes cluster and Argo CD to introduce GitOps-based deployment.

I also worked on the monitoring requirements involving Prometheus and Grafana.

Here's an overview of the implementation.

The architecture was designed to run the containerized API on Kubernetes, expose it through a Service, and manage its deployment through Argo CD.

I started by setting up KIND and preparing a multi-node cluster.

I used a KIND configuration file to define the cluster nodes and created the cluster.

I verified that the nodes were in the Ready state before proceeding.

Next, I created a Kubernetes Deployment for the Task Management API.

The Deployment used the Docker image published to Docker Hub.

The Deployment ensured that Kubernetes maintained the desired number of application replicas.

I created a NodePort Service to expose the application.

The Service mapped port 8000 to NodePort 30080.

This allowed access to the application through the Kubernetes cluster's exposed NodePort.

I also checked the Service endpoints to confirm that traffic could be directed to the application pods.

I separated application configuration from the container image.

I created a ConfigMap for non-sensitive configuration values and a Kubernetes Secret for sensitive values.

The Deployment was updated to load these values through environment references.

This made configuration management more flexible and avoided hardcoding application settings into the image.

I configured the Deployment to use a rolling update strategy.

The strategy allowed Kubernetes to replace application pods gradually rather than terminating all existing pods at once.

I also worked with rollback functionality to understand how to return to a previous Deployment revision when an update causes problems.

I created an 'argocd' namespace and installed the Argo CD resources in the cluster.

I checked the status of the Argo CD components to verify that the installation was progressing.

Argo CD provides a way to manage Kubernetes application deployments using the desired state defined in Git.

Monitor application synchronization and health.

The monitoring stage focused on understanding how to observe application and cluster performance.

Prometheus was selected for metrics collection, while Grafana was used for dashboards and visualization. Prometheus and Grafana were part of the capstone monitoring work. The monitoring and alerting components were the next stage to configure and validate alongside the Kubernetes deployment.
