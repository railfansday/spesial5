How Security Vendors Are Tackling Access-Control Challenges for AI Agents

Tanggal: 2026-11-23

News, news analysis, and commentary on the latest trends in cybersecurity technology.

Identity, runtime and development controls are converging as enterprises are tasked with keeping agents within their assigned tasks. But vendors' approaches vary, so CISOs face a choice.

As organizations expand their use of artificial intelligence agents to perform tasks traditionally done by employees, security teams must control not only which systems agents can access, but which actions they are authorized to take.

The Blueprint Alliance, an industry group advocating for coordinated controls, notes that 92% of organizations use autonomous AI agents, but only 34% secure them with the same rigor as they do for human users.

Many vendors have begun adding capabilities to better control agents. Their approaches overlap, leaving CISOs to determine how the new offerings fit into a coherent security architecture that keeps agents focused on their assigned tasks and prevents overpermissioning machine identities beyond what their human users can access.

Earlier this month, CrowdStrike introduced what it calls an AI Kill Switch, which gives security teams a way to block an agent’s access to AI models via connected gateways. The new AI Kill Switch, launched during CrowdStrike's Fal.Con Europe conference in Barcelona this month, extends Falcon Guardian, the AI detection-and-response offering that supports Windows, macOS, and Linux endpoints. Guardian discovers agents and controls which ones may run and connects prompts, identities, tool calls and skills to downstream actions in an execution graph.

The kill switch works with CrowdStrike's Falcon AI Gateway or connected third-party gateways. Its current enforcement point is model access, rather than every system an agent can reach. CrowdStrike says it will later extend the capability to terminate agent processes and revoke their access to enterprise resources.

"The hardest case is the agent that behaves abnormally without breaking a business process rule," CrowdStrike's chief product officer AJ Shipley said during an October 29 media roundtable discussion.

Discussing agent insider threat detection, Shipley described an approach that establishes a baseline of expected agent and user behavior and then detects deviations, even when no explicit policy violation occurs.

CrowdStrike also announced earlier this month agreements to acquire two startups — Fiddler AI and Dreadnode — extending its push into agent observability and pre-deployment security testing. Fiddler evaluates agents and helps explain their behavior in production, while Dreadnode tests models, applications and agents for security weaknesses before deployment. The Wall Street Journal reported a combined purchase price of approximately $495 million. The acquisitions have not yet closed.

CrowdStrike is one of several vendors addressing agent access controls. Anaconda is combining agentic software development with autonomous security testing; Cisco and Teleport are tying access to infrastructure identity; Okta is enforcing identity policy when agents call tools; and Fortinet is extending controls over execution and application behavior.

Anaconda, for instance, is approaching the problem through application development by pairing agentic software development with autonomous security testing. Last month, it expanded its AI Dev Factory, combining development agent swarms with autonomous red-team agents that probe models, agents and Model Context Protocol (MCP) servers for weaknesses. The release incorporates technology from Anaconda's August acquisition of Enkrypt AI, supporting red teaming across more than 300 attack categories and runtime guardrails that approve, modify or block risky behavior.

Anaconda's earlier acquisitions of Outerbounds, Kilo Code and Enkrypt AI collectively bring together production orchestration, agentic development and AI security. “Our roadmap out for all three acquisitions would have been about two or three years’ worth of engineering effort,” Anaconda CEO David DeSanto says, describing Enkrypt as the final component needed to accomplish this goal.

Testing agents is one requirement; limiting their authority in production is another. Cisco is approaching that problem through infrastructure identity, becoming Teleport's largest strategic investor in August. Teleport's open-source platform replaces passwords and permanent SSH keys with ephemeral certificates.

Teleport CEO Ev Kontsevoy describes an incident in which a customer deployed an agent to process data and update a database. When the intended database became unavailable, the agent found another and tried to update it. The agent was trying to complete its assignment rather than respond to an attacker. Its improvisation nevertheless exposed the difference between granting access and containing behavior.

"Would you say it's a security accident or what? Whatever it is, it's terrifying when it happens, particularly at scale," Kontsevoy tells Dark Reading.

Cisco and Teleport's partnership addresses containment through verified infrastructure identities and access granted "just in time, just enough," says Peter Bailey, Cisco's senior VP and general manager for security. "We want to be able to take action and stop action based upon identity," Bailey says.

On October 26, Cisco introduced Privileged Infrastructure Access, applying the partnership's infrastructure-identity approach to administrators and agents. Cisco says it provides temporary, identity-bound access to network infrastructure, records sessions and ends privileges when the task is complete.

Kontsevoy describes attaching privileges to tasks rather than permanently assigning them to accounts. A deployment ticket could identify the engineer, laptop and CI/CD pipeline involved. Each is granted necessary privileges, which disappear when the ticket closes. Teleport's MCP gateway also enforces policy and tracks relationships among initiating actors, agents and subagents, he says.

When an agent acts on an employee's behalf, controls must distinguish the agent's permissions from those of the person directing the agent to avoid inappropriate privilege escalation.

Consider a scenario in which an HR assistant runs on a service account that can read every employee record. A contractor asking the agent for the CEO's compensation could get the response since the assistant has access the contractor doesn't. According to Okta, this agent would be a "confused deputy," as it exercises authority the requester lacks.

To address this scenario, Okta's Agent Gateway treats agents as "first-class" identities; it preserves the distinction between their permissions and those of the users directing them. It requires a credential that identifies both the user and the agent and uses token exchange to preserve the delegation context. The gateway limits the tools available, while the downstream MCP server enforces the user's record-level access. Agent Gateway is now generally available as an addition to AI agents, an identity-security offering made generally available in April.

In an October 8 blog post, Okta described plans for Cross App Access support and a gateway-based kill switch. Officials said the latter "will make agent deactivation immediate, down to tokens already issued, by rejecting any request carrying a token issued to a deactivated agent."

Okta is not alone in extending identity controls to agents. At its Fal.Con conference in Las Vegas in September, CrowdStrike also announced Agentic Identity Provider, designed to establish trusted agent identities, broker time-limited access and link actions to initiating employees or systems.

Microsoft is pursuing a related approach through Project Perception, connecting agent identity, behavioral risk signals and access controls across its security products via its new Guardian Agent capabilities

Meanwhile, Fortinet is extending AI inspection across its existing network security products. Last month, the company announced the FortiGuard Inline AI Security Service for FortiGate customers and described expanded FortiAIGate capabilities incorporating Virtue AI technology, which Fortinet acquired earlier this year. Virtue AI adds policy-derived guardrails, continuous assessment, code analysis and agent red teaming. Fortinet executive vice president Anthony James describes more than 50 simulated application environments in which customers can test agent boundaries before connecting to real systems. James says Virtue can block an agent from communicating with MCP tools or servers not approved for its task and detect prompt sequences that progress from innocuous to malicious.

James says FortiAIGate began by monitoring communications to and from AI infrastructure. Customers deploying agents sought a deeper understanding of the application. Models, MCP servers, agents and skills “require a little deeper application knowledge than just interpreting the network traffic,” James says.

Overlapping approaches have prompted coordination efforts. In September, Okta announced the Blueprint Alliance with vendors including AWS, CrowdStrike, Google Cloud, Proofpoint, Salesforce, ServiceNow and Zscaler. The group aims to develop a shared architecture for securing agents across vendors’ products.

The alliance has outlined principles for agent identity, task-scoped access, monitoring and containment. Whether those principles translate into interoperable products and expanded adoption remains to be seen.

Taken together, these approaches point to a common requirement: keeping an agent’s access tied to its assigned task. Identity verification, security testing and runtime monitoring address different parts of that requirement, but no single control confirms that an agent will remain within its assignment.

Emerging control planes aim to connect those controls across tools and systems—limiting agents to their assigned tasks rather than letting AI software determine how far its authority extends.
