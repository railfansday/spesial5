Bus factor 1 is the default: per-language ownership in 195 popular repos

Tanggal: 2026-11-14

Bus factor (also called truck factor) is the number of people who would have to disappear before nobody left understands a piece of code. A bus factor of 1 means one person holds it.

It sounds like a warning sign. Across 195 popular open-source repositories, it is the normal state of most files.

For a single file: the fewest authors who together made 80% of its commits. If one person made 80% or more of the commits, the file has a bus factor of 1. If it takes two people to reach 80%, it is 2, and so on.

Commits are a rough proxy for knowledge, but every repo already has them. git blame is worse for this, because a formatter run or a big rename hands whole files to whoever pressed the button.

Fifty-four people made 80% of the commits to query.py over 21 years, and 20 people over the last two. That is about as far from 1 as a file gets.

Two details matter in that script. HEAD is explicit because git shortlog with no revision reads standard input when it is not attached to a terminal, which inside a script means it prints nothing. And the --since option is not decoration. The people who wrote a file in 2012 are not necessarily the people who could fix it today, so the window you pick changes the answer.

I looked at production source files (tests, generated and vendored code excluded) in 195 public repositories with 1,000+ GitHub stars each, using the same 80% rule on each repo's indexed git history.

I would not read too much into the language order. Bus factor depends heavily on how long a project has existed and how many regular contributors it has, and those vary more between repos than between languages. A three-year-old project has had far less time to spread knowledge around than Django has in 21.

The more useful number is about hotspots, the files that change most often. If the busiest files were also single-owner, that would be a real risk: lots of change going through one person's head.

The data says the opposite. In the median repo, 25% of hotspot files have a bus factor of 1, against 60% of all production files. Pooled across the 195 repos, 34% of 20,941 hotspot files are single-owner. Code that changes a lot tends to get touched by more people, which is what you would hope.

So a bus factor of 1 on a file nobody edits is mostly fine. The case worth acting on is a file that is still changing often while its main author has gone quiet.

The full method, including .mailmap for people with several email addresses and how to run this across a whole repo, is in this guide on measuring bus factor from git. For a large repo you can browse, Grafana's owners page shows bus factor per file across its 10,000+ production files. At its last index, 24% of them had a bus factor of 1, well under the median.

What does the term bus factor mean? Bus factor, also called truck factor, is the number of people who would have to leave a project before nobody left understands a piece of code. Here it is measured per file as the fewest authors who together made 80% of its commits.

How do you calculate bus factor from git? Run git shortlog -sn --no-merges HEAD -- to count commits per author, highest first, then add authors down the list until you pass 80% of the commits. The number of authors you needed is the bus factor. Add --since to measure only recent history.

Is a bus factor of 1 bad? Not on its own. It is the normal state of 60% of production files in the median popular repo, and a single-owner file nobody edits is mostly fine. The case to act on is a file that still changes often while its main author has gone quiet.
