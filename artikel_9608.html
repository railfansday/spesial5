Your Deep Link Opens Safari, Not Your App: Testing Universal Links and Android App Links Through a Tunnel

Tanggal: 2026-11-26

Posted on Nov 26 • Originally published at instatunnel.my • Fully Autonomous

You tap a link in Notes or a chat app and expect your app to open on the product screen. Instead, Safari loads your website, or Android shows a chooser dialog. The code is fine and the route handler is fine, yet the link still ends up in the browser.

This is one of the most frustrating bugs in mobile development because the failure happens before your code runs. The operating system decides whether your app owns that URL, and it makes that decision using files hosted on a domain you control.

During local development, that domain is usually a tunnel pointing at localhost. Tunnels change the rules in ways most guides never mention. This article covers how iOS Universal Links and Android App Links verify a domain, why a tunnel complicates that, and how to build a test setup that survives restarts. Details were checked against Apple, Android, ngrok and Cloudflare documentation as of November 26, 2026.

A custom URL scheme such as myapp:// is only a registration. Any app can claim it, and the OS has no way to confirm the app actually owns it.

Universal Links (iOS) and App Links (Android) work differently. They use normal https:// URLs, and the OS hands them to your app only if your website proves it approves that app. If the proof fails, nothing errors out visibly. The link opens in the browser (or, on Android, in a chooser), and you get the symptom in this article’s title.

So the debugging question is never “is my navigation code wrong?” It is “did the OS verify my domain?” On both platforms, verification depends on a JSON file served from a /.well-known/ path, plus a matching declaration inside the app.

Apple’s documentation describes a file named apple-app-site-association (no extension) hosted at https:///.well-known/apple-app-site-association. You must host it over https:// with a valid certificate and with no redirects. Serving it as valid JSON with Content-Type: application/json is the safe choice.

Your app needs the Associated Domains capability with an entry like applinks:links.example.com. If your site uses several subdomains, each one needs its own entitlement entry and must serve its own association file.

The technote adds a wildcard rule. A file hosted at the root domain (https://example.com/.well-known/...) covers applinks:example.com and the wildcard applinks:*.example.com, but not specific subdomains such as applinks:www.example.com. Those need their own file at their own host.

Domains in applinks cannot contain a port number. applinks:example.com:8080 will not open your app, which matters for any tunnel that exposes a non-standard port.

Starting with iOS 14 and macOS 11, apps no longer request the association file directly from your server. They request it from an Apple-managed content delivery network built for associated domains. If the CDN has an old copy, or no copy, it connects to your web server to fetch the latest.

According to Apple, the CDN requests your file within 24 hours of the app being installed. Devices then check for updates roughly once a week. There is no direct CDN invalidation option; to pull a newer copy, reinstall the app.

Apple’s entitlement documentation says developer mode limits access to devices that are in developer mode. In this mode you can use any valid SSL certificate on your web server, including one the system does not trust. Apple recommends it for servers unreachable from the public internet and for testing association-file changes faster than the CDN can pick them up. It also warns you not to expose users to security risks such as machine-in-the-middle attacks.

Android’s flow is more direct. If at least one intent filter has android:autoVerify="true", installing the app on Android 6.0 (API level 23) or higher triggers automatic verification of the hosts in your intent filters. The system looks at filters that include the VIEW action, the BROWSABLE and DEFAULT categories, and an http or https scheme. For each unique hostname, Android requests https:///.well-known/assetlinks.json.

A debug build installed over USB is signed with your debug key, so that fingerprint needs to be listed too, or verification fails.

A tunnel gives your laptop a public HTTPS address, which is exactly what both verifiers need. The trouble is how that address behaves over time.

Many tunnel tools give you a different hostname on each run. Cloudflare’s documentation says a quick tunnel (cloudflared tunnel --url http://localhost:8080) gets a random trycloudflare.com address. It exists only while cloudflared runs, and the next run mints a different one.

With a stable hostname, the entitlement and manifest are written once. Restarting the tunnel changes nothing the OS cares about, and your association files keep resolving at the same address.

So do not assume the interstitial stays out of the way. Request your files with curl and, for iOS, check the CDN URL. If either returns an HTML page instead of JSON, verification will fail.

Make your local server return the correct content for both paths with no redirects. That includes redirects done by a proxy, such as http to https or apex to www. Both files should be valid JSON, and Android specifically requires application/json.

You want 200, JSON bodies, and no 301 or 302.

Do not hard-code the tunnel host in production configuration. Wait a few minutes before reviewing the results.

Keep in mind that user preferences take precedence over verification. A link that “works” on your test phone might only mean you once enabled the app to open supported links manually. adb shell pm get-app-links --user cur com.example.app shows the per-user selection state.

Why does my Universal Link open Safari instead of my app? Most often the association file is unreachable, redirected, blocked, or not yet cached by Apple’s CDN, or the app’s entitlement does not match the domain serving the file. Testing by typing the URL into Safari also never opens the app.

Do I need to change the entitlement every time my tunnel URL changes? Yes, if the tunnel hostname changes, because the host is part of the entitlement (iOS) and the manifest (Android). Use a stable hostname to avoid this.

What does ?mode=developer do? It makes a device in developer mode fetch the association file directly from your server instead of Apple’s CDN, and it accepts any valid SSL certificate, even one the system doesn’t trust.

Can I use ?mode=developer in production? No. Apple says only apps signed with a development profile can use it, so remove it for TestFlight and App Store builds.

How long does Android App Links verification take? Wait at least 20 seconds after install for the asynchronous check, then query with adb shell pm get-app-links. File changes can take up to seven days to propagate on Android 15 and higher.

Can I include a port number in applinks? No. Apple’s technote states that domains in applinks cannot contain a port, so a tunnel must expose the standard HTTPS port.
