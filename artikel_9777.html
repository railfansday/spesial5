A third-party script can drain your users: SRI and CSP in Laravel and Nginx

Tanggal: 2026-11-07

Posted on Nov 7 • Originally published at armeldev.xyz

You add a small script to measure how fast your pages load. One line in the layout, a link to the vendor's CDN, done. Months later, someone replaces that file on the vendor's server. Your code hasn't changed, but your site is now running someone else's.

That is exactly what happened to Polymarket in late October. The script of a performance monitoring tool, DebugBear, was replaced on October 29. The result: 726 wallets drained and about 2.7 million dollars stolen (The Hacker News).

When a page loads an external script, the browser makes no difference between your code and its code. It can read forms, change buttons, send requests on the user's behalf.

Yet we treat it as a detail: an analytics tool, a chat widget, a font, a library on a CDN. Each one is a door into the most sensitive pages, like payment, login or signing.

Every third-party script is code you run without having read it.

The integrity attribute (Subresource Integrity) gives the browser the expected fingerprint of the file. If the content changes, even by one character, the script is blocked.
