Run an AI model in Blazor with no server and no API key

Tanggal: 2026-11-26

Posted on Nov 26 • Originally published at spawndev.com

Adding AI to an app often means an account, an API key, a bill for every request, and sending your users' data to someone else's server.

For many jobs you need none of that. A small model can run on the visitor's own device, in the browser, from C#.

We will build a page that names what is in a photo. The photo is never uploaded. You need the .NET 10 SDK and a browser.

A model is a file. This one is MobileNetV2, a 14 MB image recognition network from the ONNX Model Zoo (Apache-2.0). It knows 1,000 kinds of things, from dog breeds to kitchen tools.

SpawnDev.ILGPU.ML reads the file and runs it on the GPU. It uses WebGPU when the browser has it, then WebGL, then WebAssembly.

Download mobilenetv2-7.onnx into wwwroot. For the sample buttons, also save red-panda.jpg and labrador.jpg there.

The model is loaded when the first photo arrives, so visitors who only look at the page do not download it.

ModelHub has the browser download the model into its own storage. The session reads the weights from there and sends them to the GPU, without making the model a .NET array. The next visit uses the stored copy.

This matters. We first wrote this page with HttpClient, which brings the whole model into .NET:

If you change the model, give the file a new name. A stored copy is found by its address and is not checked again.

ClassificationPipeline does the rest of the work around the model: it resizes the photo, prepares the colors, and turns the numbers that come out into names.

The browser already knows how to read JPEG, PNG and WebP files, so we let it. The pixels stay in the browser's memory on their way to the GPU.

ClassifyAsync takes the pixels and returns the best guesses, each with a label and a confidence.

"Lesser panda" is another name for the red panda.

The first photo includes loading the model and preparing it for your GPU, so the page says so while you wait. Your times will differ.

Browsers without WebGPU use WebGL or WebAssembly instead. On the same PC with WebGL, the model took about 1.5 to 1.7 seconds for the first photo and about 0.3 seconds for each one after it.
