Bitcoin launches Testnet5 and gives miners a real trial of four proposed fixes

Tanggal: 2026-11-19

Bitcoin’s new Testnet5 lets miners test four proposed consensus rule changes as Bitcoin Core and Sparrow Wallet prepare support.

Bitcoin miners have a new network, Testnet5, where they can test their software against four proposed changes to Bitcoin’s rules, with support in Bitcoin Core and Sparrow Wallet at the patch stage.

The Bitcoin Improvement Proposals repository added the record of Testnet5’s first block to the network specification on Nov. 17, three days after the block was mined.

The four changes are collectively known as BIP54, or Consensus Cleanup. Bitcoin Inquisition’s signet already enforces them, but producing blocks there also requires miners to satisfy a signing challenge in addition to proof of work.

On Testnet5, independent miners and pools can use their own software to build blocks and see whether other nodes accept them without that extra requirement.

Two of the four rules limit how much work certain blocks can impose on nodes and how miners can use timestamps to influence difficulty. One caps certain signature operations in ordinary transactions to limit how long a block can take to verify.

The other restricts timestamps at the start and end of each difficulty period to prevent miners from artificially driving the difficulty down.

A third rule rejects transactions that measure exactly 64 bytes after removing witness data, closing an ambiguity in proofs of transaction inclusion. The fourth makes each new mining reward transaction unique by requiring its locktime to equal the block height minus one and requiring that locktime to take effect.

Pool operators can use Testnet5 to check that their software, which usually builds the reward transaction, applies the new rule.

Testnet4 let miners drop to minimum difficulty if a block’s timestamp was more than 20 minutes after the previous one, except at the start of a difficulty period. BIP95 says competing blocks mined under the exception caused frequent short reorganizations, where one set of recent blocks replaced another.

Testnet5 removes the 20-minute rule altogether and raises the minimum difficulty from 1 to about 1 million. The specification’s authors chose the higher floor to slow early block production before difficulty adjusts, while keeping it low enough for a single specialized mining machine to keep the test chain running.

Early testers can build the Bitcoin Core patch and sync by manually connecting to a peer, its author reported. The proposal targets Core’s 32.x branch and still needs to be merged and shipped in a public release.

Bitcoin Core 32.1, the latest release as of Nov. 18, predates the Testnet5 integration build.

Sparrow’s wallet integration proposal opened late on Nov. 17, and would let users select Testnet5 in the wallet and add two public Electrum servers to connect to the chain.

A Sparrow collaborator reported on Nov. 18 that the wallet’s Silent Payments feature worked in tests against both servers. The proposal, which depends on an update to Sparrow’s Drongo library, remained open.
